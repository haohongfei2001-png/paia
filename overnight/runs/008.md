## Implementation summary

The ON-02 candidate implements the missing explicit AI-update comparison path without creating a new content truth store:

1. Every update of an existing AI-organized Topic keeps the current presentation readable and writes a separate bounded candidate instead of replacing the current draft.
2. Candidate validity is tied to the exact current presentation revision and a body-free Topic material-version snapshot. Human edits or material changes make the candidate stale and block save.
3. The UI stages `adopt` / `keep` decisions locally for every changed AI field. Nothing is written by an individual section choice. `保存这些选择` sends all choices once; the domain applies them in one CAS-guarded transaction and one presentation revision.
4. Explicitly adopted and explicitly kept changed sections become human-protected. Unselected/incomplete decision sets are rejected.
5. Candidate evidence receives a deletion fence. Source purge drops an affected candidate and leaves the still-valid current draft intact; purge of current presentation evidence retains existing stronger invalidation behavior.
6. Candidate state remains inside the existing `aiPresentation:<topic>` organization-state row. Backup validates candidate evidence and strips an unsafe candidate rather than creating another body store.
7. `OUTCOME_UNKNOWN` no longer exposes an automatic retry action; status reads remain local and paid retries require another explicit user action.
8. Added domain and real-browser coverage for candidate isolation, atomic save, concurrent stale state, purge, Backup round-trip, zero-request no-delta/status reads and current-draft preservation.
