## 1. Fixed semantic rules 与最小数据契约

### 1.1 全局不可破坏项

| ID | 固定语义 |
|---|---|
| SEM-01 | Source 保存当时发生的事实，不被普通编辑、AI 重算、导入或 UI 迁移覆盖。未知发送时间不以捕获/导入时间补写。 |
| SEM-02 | Input 是档案工作正文；Thought 是既有思想内容与组织；AI 整理是派生呈现。不得创建 Reader、Search、Revisit、Context 的重复 truth store。 |
| SEM-03 | 人工修改、排除、移除、主题归属、恢复优先于自动过程。来源事实的补全不覆盖用户工作。 |
| SEM-04 | Smart Filter、主题移出、档案移除、永久删除、不主动回顾、禁止用于 AI 是独立动作，不可互相暗含。 |
| SEM-05 | 记录“用户发送过”不等于认定“用户相信”。引用、JD、角色扮演、操作指令及未知作者材料不得被写成用户立场。 |
| SEM-06 | 显式选择固定保存真实对象、版本与范围。搜索和模型只补充；不得替换、静默压缩、静默截断已选内容。 |
| SEM-07 | 捕获、云端 AI 处理、同步、外部连接分离授权。历史 Prompt 是材料，不是当前权限或可执行指令。 |
| SEM-08 | 本机准备不等于发送。复制/导出之后不能承诺收回外部副本。手动用户输出与受控外部工具访问分别验证。 |
| SEM-09 | 删除 fence/tombstone 优先于缓存、索引、历史恢复、备份及重导入。不得从旧预览或旧版本复活已永久删除内容。 |
| SEM-10 | 保存失败保留用户缓冲；版本冲突不能最后写入覆盖；Undo/Redo 与恢复都形成可追溯工作历史。 |
| SEM-11 | 普通阅读、编辑、本地搜索、手动组合与复制不得暗中发起 Provider 请求；无授权的自动付费重试为发布阻断问题。 |
| SEM-12 | 工程检查通过不等于留存或市场价值成立。可选本地统计保持观察者地位，不决定授权或内容选择。 |

来源：设计核 §2–3、§9–11；与本轮密切相关的编辑边界见设计核 §3.4。[S1]

### 1.2 Thought 中编辑完整 Input 引用：最终裁决

**用户心智只有两句话：在档案里改，修改档案；在思想库里改，默认只修改这条思想。**

不引入“思想库用稿库”、独立 overlay、补丁树或分支工作区。使用现有 `thoughts` 条目的正文、人工保护、来源关系和版本历史。一个 Thought 可由多个 Topic placement 引用；这些位置展示同一个 Thought，不各保存一份正文。

| 情形 | 最终行为 |
|---|---|
| 完整引用尚未在思想库改写 | 显示并跟随对应 Input 的当前工作正文；不生成另一份人为需要维护的正文。实现可保留当前已有镜像字段，但它不是独立权威。 |
| 默认关闭反向修改时第一次实际改字 | 在一次域事务中解除这条 Thought 的工作正文跟随，保存到**既有 Thought 正文字段**，标记人工编辑；不修改 Input 或 Source。点击/聚焦不触发解除。 |
| 同一个 Thought 出现在两个主题 | 该 Thought 的编辑在两处一致显示；从一个主题移出只移除该 placement。 |
| 思想库已改写，之后 Input 改了 | 保留 Thought，不自动合并。显示“档案有更新 · 查看”；侧面只读比较。用户可“保留我的修改”或“恢复为档案当前文字”。 |
| “恢复为档案当前文字” | 显示将被替换的当前 Thought 与档案正文，确认后新建 Thought 工作版本，并重新建立明确的完整引用。人工旧版受现有历史保留策略保护，永久删除仍优先。 |
| 独立 Thought、局部摘录、多来源综合、AI 整理稿 | 始终只在自身编辑范围内写入，不猜测反向映射。 |
| 高级开关开启 | 仅对仍跟随、完整、一对一、版本有效的 Input 引用允许一次原子双向工作正文修改；Source 仍不变。写入前在焦点区域显示“同时修改档案”。 |
| 已经只属于 Thought 的改写，再打开高级开关 | 不回放历史改动，不自动重新建立跟随；必须先执行明确的“恢复为档案当前文字”。 |

**实际文案：**首次思想库独立编辑提示“已修改这条思想，档案未变。”；常驻轻量标记“已在思想库编辑”；更多菜单“查看当时记录”“查看档案当前文字”“版本历史”。普通界面不显示 binding、fork、overlay、projection 或“分叉”。

**最低实现契约，字段名允许按仓库惯例映射：**在现有 Thought 上增加/复用一个 `bodyBinding` 状态（`input` / `thought`），而不是新增正文表。`input` 仅在来源和完整范围可被证明时成立；`thought` 的正文权威是现有 `thoughtText`。`workingInputId` 只能表示仍有效的跟随，不能在独立改写后被读取器重新推断为共享。原 provenance / dependency 继续保留，用于追溯、删除与限制传播；它们不是反写权限。

首次解除跟随须同时检查 Thought revision、Input revision 与原选择范围；期间来源变化则拒绝这次写入、保留缓冲并提示“档案刚有更新，请核对后再保存”。已经是 `thought` 状态的人工编辑，不因为来源有新版本就自动覆盖。

**历史表达：**主题页可保留来源日期，但已改写内容同时标明“已编辑”；“以前的我”使用当时 Source，不能将今天 Thought 的改写投回过去。Thought `createdAt` 不被当作来源发送时间，编辑时间单独记录。

**重复处理：**新“加入主题”优先复用同一来源、相同范围、相同当前内容的现有 Thought。若已有 Thought 已被改成不同内容，不得以它替换用户刚选中的 Input；可复用另一条仍跟随的精确引用，确实没有时建立一条普通 Thought。不得自动合并历史上不同的人工 Thought，仅因它们源自同一个 Input。

**撤销：**解除跟随是一次完整编辑事务，可撤销。双向修改的 Undo 必须原子检查双方版本；若期间高级开关被关闭，先确认“这次撤销也会修改档案”，不能偷偷只撤一处或绕开当前限制。确认只授权这次撤销，不重开全局开关。

正文解除跟随不影响主题归属；用户没有真正修改文本时不保存空版本或解除关系。

理由：独立人工改写本来就是 Thought 的职责；不需要为它另建第四套正文模型。[S1][S9][S10]

### 1.3 显式材料与授权的最终语义

| 类型 | 可做什么 | 禁止什么 |
|---|---|---|
| 普通复制 | 用户直接复制眼前当前文本；可复制未保存缓冲作为保底。 | 不暗附其他记录、不调用 AI、不假报已发送。 |
| 本次明确选择 | 用户从 Input / Thought / 已有 AI 整理选具体材料，形成仅本次的 manual selection；未进入思想库不构成阻断。 | 不以该动作开启全库、主题或未来连接权限。 |
| 尚未授权的内容 | 对手动、明确、范围固定的选择，可在本次预览确认后输出；自动补充仍须获准范围。 | 不把默认未授权误写成用户已经明确禁止。 |
| 明确禁止用于 AI / 永不提供 / 持久排除 | 在材料盘中保留受阻项，不能进入有效输出；显示原因。 | 不能悄悄移除用户选项，不能因显式选择绕过禁止。 |
| 解决禁止 | “修改此项限制”进入来源规则；确认仅改变被指定的规则；继承禁令不能被单项普通允许覆盖。 | 不提供含糊的“一键忽略全部限制”。 |
| 外部连接 / Grant-bound 输出 | 保留 existing Profile / Passport 主路径与更强检查，重新验证消费者、用途、期限及撤销状态。 | 不复用 manual selection 作为外部工具绕过授权的快捷方式。 |
| Local-only | 禁止 PAIA 主动云端处理、远程同步及连接访问；普通复制、用户手动文件导出、本地准备可用。 | 不因此开放原先禁止用于 AI 的材料，不自动重启网络服务。 |

实现必须在 trusted service 层区分 `manual_selection` 与 `grant_bound` 意图；不能仅在 UI 删除限制或绕过 `ContextPackageService`。浏览器原生选词/系统剪贴板是用户自己的能力；本规范不承诺阻止屏幕内容被手动复制，但PAIA不得给受阻Context新增“绕过检查复制”按钮。程序化输出必须经过对应可信路径。

老 `externalAccess=false` 的迁移保持**外部连接仍关闭**，但不再把“用户手动复制自己的输出”误作对外连接开启。此差异是本文明确授权的 UX 语义修正，需独立回归。[S1][S11]

### 1.4 Context Preview 精确输出契约

预览是本次、短期、可检查的输出快照。材料项必须保留 kind、稳定 ID、revision、全文/选段范围及作者角色；Context 的标题、内容和状态不可仅来自搜索 snippet。

用户在预览中直接改字，编辑的是**本次输出**。视觉是一篇连续文档，内部按来源材料段保持映射；不得将整篇变成无法追溯的一个任意字符串。可独立写“本次说明”，但不能把它标成过去原话。

预览构建流程另有 `building`；构建后的输出状态为 `ready / dirty / stale / blocked / expired / error`。输出点击时，trusted path 校验材料生命周期、权限、revision 与本次编辑版本，再输出用户刚检查的完整文本；不能临时重新检索并替换正文。禁止把旧版 `MemoryService.share()` 的重新拼接结果当作无条件等同于当前编辑预览。

**隐私删改：**本次移除记录留在本次排除集合；改写某材料后保留其本次 override；明确“遮去所选文字”建立本次遮挡规则。后续建议不得自动采用，且必须排除已删材料并套用遮挡规则。所有人工改写发生后，重建默认保留这些改写；无法保持时阻止重建并显示差异，不恢复原始未遮挡内容。不能声称可自动发现所有同义改写或间接身份线索；输出仍要求用户检查。

源文编辑使相应快照 stale；源文移除、永久删除或禁止使相关材料 blocked，并立即从可输出正文中剔除/遮挡；用户必须解决后重建。混合来源且不能安全拆分的派生段落整段停止输出；不得等待再次调用 AI 才生效。

输出提供“复制这份内容”“导出 Markdown”。没有真实模型限制数据时不展示万能 token 上限；字数与条数来自实际输出。过长不可静默截断；提供完整文件、按完整材料分批（超长单条再按段落分批并明示）或用户手动减少材料。

### 1.5 阅读、回访与历史的时间契约

真实继续阅读采用稳定锚点：文档/主题 ID、条目 ID、段落/字符位置、已保存 revision、排序、展开状态。持久化只放必要位置元数据，不复制正文。候选匹配可用不可逆摘要和偏移，不在阅读位置表另存私人引文。

自动锚点仅在可见页面的有效阅读停留后更新；v1 默认滚动结束后 3 秒，或直接“记住这里”。搜索预览的瞬时打开不更新首页最近阅读顺序；用户在 Reader 有效停留后才转为正式阅读。删除原段落后选邻近仍有效位置，显示“原位置已移除，从附近继续”。不得复活删除内容。

回访的 visit boundary 与阅读完成是两个概念。移除旧用户 baseline 仪式，新边界只表达“上次打开后新增”，不表示“已读”。首次安装、升级或全量历史导入不形成未读债务；每次进入先固定本次展示窗口，再于离开/下次进入时更新边界，不能一加载就把眼前新内容清空。

旧内容主动重现默认关闭；单条/会话/主题的“不主动回顾”也约束其派生摘要与重复引用。禁止项不仅从渲染结果隐藏，还必须在预览生成、候选摘要与无结果推荐中排除。[S1][S3]

### 1.6 删除和依赖范围

| 动作 | 固定效果 |
|---|---|
| 从主题移出 | 仅取消当前 placement；保留 Input、Source、Thought 在其他主题的引用。 |
| 从档案移除 | 保留防复活信息，从正常档案、相关有效投影和未发出 Context 中移除；可撤销/恢复。 |
| 永久删除来源 | 清理 PAIA 可控制的来源正文与依赖缓存、引用、可恢复的相关历史；保留 body-free tombstone。 |
| 删除独立 Thought | 使用现有 Thought 删除/恢复语义，不删除被它回应的 Input。 |
| 删除包含人工内容的派生记录 | 不把明确独立的人工 note/新 Thought 误删；但仅改写了引用正文，不自动使整段变成与来源无关的独立材料。无法隔离来源片段时清除依赖正文，保留可证明独立的字段。 |

迁移不得把来源关联清空，借此逃避删除或“永不提供”。恢复普通移除也不能解除其他既有禁止规则。外部导出、离线设备和用户自持旧备份不被承诺即时远程抹除。

| ID | 授权变更 | 所属轮次 |

## 2. App-wide 交互、导航与状态保存

### 2.1 逻辑路由与可信入口

下表是逻辑目标，**不是新文件路径或 URL 承诺**。继续使用 `ui/archive.html`；内部导航携带 view state。浏览器 Back/Forward 使用 history state 时保持经过验证的原 URL，不擅自附加 hash/query。任何 URL 方案调整必须同时通过 sender 验证回归，不扩大成“整个 extension origin 都可信”。

| Route ID | 目标 | 默认返回 |
|---|---|---|
| `archive.home` | 首页 + 档案浏览 | 无上级 |
| `archive.document` | Input Reader | 发起方，缺失时 archive.home |
| `search.results` | 全局搜索 | 发起方 |
| `search.history` | 以前的我 | 原搜索结果 |
| `revisit` | 回来看看 | archive.home |
| `thought.home` | 思想库 | 无上级 |
| `thought.topic` | Topic Reader | 发起方，缺失时 thought.home |
| `thought.standalone` | 未加入主题的独立 Thought | 发起方，缺失时 thought.home |
| `reuse.tray` / `reuse.preview` | 本次材料 / 输出预览 | 发起方，缺失时 reuse.tray |
| `settings.group` | 设置分组 | 原页面 |
| overlays | 加入主题、接着写、来源、版本、AI 更新比较、导入/恢复 | 关闭返回触发控件及原位置 |

扩展新建全页标签进入 archive.home；若只是激活已经打开的 PAIA 标签，保留现场。明确内容目标高于默认首页。浏览器返回先处理最上层 modal，再处理逻辑路由；不得为回访/搜索单独建立第二套导航系统。

### 2.2 State preservation 表

| 状态 | 寿命与保存位置要求 | 退出/失败处理 |
|---|---|---|
| 正文与用户编辑 | 既有 domain stores + revision 事务 | 成功后才显示已保存；失败保留内存缓冲。 |
| 阅读锚点 | 现有 meta/偏好空间的版本化、设备本地元数据 | 重启可恢复；删除相关内容清理锚点；默认不进数据备份。 |
| 搜索词、筛选、分页、结果滚动 | 当前 PAIA 标签会话内存 | Reader 返回完整恢复；关闭标签即清理，不写分析日志。 |
| 多选材料 refs、排除、排序 | 当前标签会话内存，由可信 UI 持有 | 抽屉关闭和页面切换保留；刷新/关闭前有未导出人工编辑时提示。 |
| 输出快照、遮挡与本次编辑 | ephemeral trusted state，非 IndexedDB 正文库 | reload / worker 生命周期导致快照失效时停止输出；可保留 UI 缓冲并重新验证，不宣称永久保存。 |
| AI 已生成结果与候选 | 复用现有 AI presentation / revision / suggestion 结构 | 结果可以重开；用户编辑与候选不能因切页丢失。 |
| 来源/版本面板展开、当前选段 | 当前标签内存 | 关闭回到原滚动和焦点；不能改变内容版本。 |
| 设置、回访排除、反写开关 | 现有偏好/策略存储；版本化 | 立即生效；失败回滚开关视觉并解释。 |
| 未提交“接着写”草稿 | 当前标签内存 | 切页/关闭弹窗确认“保留在此继续写 / 放弃”；不把临时草稿伪装成已保存 Thought。 |

自动保存完成前，跨页复用/加入主题等动作先 flush；普通“复制”可复制缓冲，不受 flush 成败阻碍。不得声称浏览器强制终止、系统崩溃后未保存缓冲必然可恢复。

### 2.3 通用控件状态（所有页面继承；§3 给出页面差异）

| 状态 | 必须表现 |
|---|---|
| Hover | 轻底色或页边操作出现；不改变布局、不挤压正文。触屏有常驻更多入口。 |
| Focus | 可见焦点环；键盘顺序与视觉顺序一致。工具条不能遮挡当前焦点或光标。 |
| Selected | `aria-selected` / `aria-pressed` 等与真实状态一致；勾选/边线配合底色，不只变色。 |
| Editing | 明确当前写入范围；不回收正在编辑的节点；composition 期间不提交半截输入。 |
| Loading | 只占位未知区域，已有内容保留；无假百分比、无整页反复闪白。 |
| Processing | 显示真实阶段、可停止的后续处理；同一用户动作不能重复发出多个付费请求。 |
| Error | 对象附近说明失败范围、已保留内容和恢复动作；不只给“出错了”。 |
| Empty | 区分无数据、筛选无结果、范围无权限、索引未全、来源失效；一个自然起点。 |
| Disabled | 给出原因和下一步；以 aria-disabled 保持需要解释的控件可聚焦，不允许实际执行。 |

模态必须有标题、Esc、焦点限制与关闭后焦点恢复；非模态材料抽屉不把主页面设为 inert，仍可继续选择。危险确认默认焦点在“取消”；加载提示使用 polite live region，失败才使用 alert，避免每次键入读出“正在保存”。

### 2.4 主要控件标识与状态词汇

| 用户动作 | 固定中文 | 不再使用 |
|---|---|---|
| 原记录持续阅读 | 继续阅读 | 用最近收录冒充继续 |
| 新想法 | 接着写 / 补充今天的想法 | 含糊的“继续” |
| 给下一次 AI 使用 | 用于 AI | Context Compiler、Package Builder |
| 原输入页面 | 档案 | 一级 Source / Input / Projection 并列 |
| 主题总览 | 思想库 | 第二套聊天列表 |
| 二级回访页 | 回来看看 | 未读任务、清零、打卡 |
| 本机输出成功 | 已复制，尚未发送。 | 已分享 / 已授权给 AI |
| 原事实核对 | 查看当时记录 | 在每条正文旁常驻 Source Record |
| AI 稿更新 | 更新 AI 整理 | 用“同步”指代 AI 重算 |

简体中文为本规范文案基准；English 等现有语言必须语义等价。`{N}` 等是由真实状态填入的占位符，不能硬编码演示数字。

## 5. Design System v1

### 5.1 Fixed rules 与 visual defaults 的边界

**固定语义：**所见输出等于实际输出；状态真实；选中不被算法替换；错误不丢工作；文档可长期阅读；键盘/触屏有等价操作；不单靠颜色表达；减少动态设置生效。§1 的历史、删除、编辑与授权规则不属于可调主题。

**可调默认：**本节字体、尺寸、断点、颜色、圆角、阴影和动画数值。允许实现 Agent 在同一轮视觉验收中微调，但必须记录 token diff、理由和受影响截图，并通过对比度/布局/交互测试。不得用“微调 token”改变动作语义、默认授权、内容排序规则或导航方向。

| 场景 | v1 默认 | 固定行为 |
|---|---|---|
| 输入自动保存 | 500ms 无新输入后提交；blur/导航时 flush | composition 中不提交；状态由实际结果驱动。 |

### 5.7 Motion tokens 与 AI 转场

| Token | v1 默认 |
|---|---|
| `motion.fast` / `standard` / `panel` | 120 / 180 / 220ms |
| `motion.ai.cached` / `ai.firstReady` | 220 / 550ms |
| `motion.ai.maxTranslate` / `maxBlur` | 4 / 4px |
| `motion.ai.maxFragments` | 可见区域最多12块 |
| `motion.easing` | `cubic-bezier(0.22, 0.61, 0.36, 1)` |
| `motion.reduced` | 0ms；必要时不超过80ms淡入 |

AI 转场按四个阶段实现：准备新结构完成 → 当前可见段落轻微松开 → 规则矩形片段短暂错位/模糊 → 新层级对齐并恢复清晰。主题标题、侧栏、当前用户焦点锚点稳定。该转场不需要真实物理粒子，不出现玻璃爆炸、水波、霓虹、旋转装饰或持续 shimmer。

只为当前视口创建有限视觉快照/块，完成即销毁；不为十年长文制作巨大 DOM 副本。模型等待时间使用正常 processing 状态，不能无限循环结构转场；缓存切换不重新调用 Provider。浏览器不支持所用转场能力时，使用等价短淡入，保留任务与状态。减少动态时关闭碎片和模糊，用户仍能理解 Original/Organized 的切换。

### 5.8 Accessibility requirements

以 WCAG 2.2 AA 为规范基线；正文及关键元信息对比度至少4.5:1，必要非文本控件/状态边界至少3:1。24×24 CSS px 是 WCAG 相关目标尺寸条款的最低要求并有例外；本项目采用更宽松的40/44px默认命中区，不将其误称标准原文。[S14]

必须支持全键盘、可见且不被固定条遮挡的焦点、跳到正文、准确 landmark/label、200%文字放大和320px宽重排；代码/必要二维材料可局部横滚。模态有标题、焦点管理、Esc与返回焦点；非模态抽屉不误设 modal。[S15]

用户原文保留语言与 Unicode；中文 IME、emoji、组合字符、多行粘贴都测试。排序、拖动、选段与采纳候选有非拖拽替代。状态不能只靠颜色、动画、tooltip或鼠标hover；错误文字可朗读，频繁自动保存不刷屏播报。系统 reduced motion 生效；明暗两套都验收，不以浅色通过代表深色通过。

## 6. State migration / compatibility

### 6.1 允许的最小持久状态

本节授权在**现有 store 和既有实体**中增加必要元数据/策略字段及版本标记；不授权新正文实体家族。实现字段名可适配实际代码，但其含义、归属、默认值与迁移不得改变。

| ID / 所属轮次 | 状态与归属 | 迁移 / 恢复规则 |
|---|---|---|
| MIG-01 / UX-R1 | UI 偏好版本、语言、明暗、布局值；既有 preferences/meta | 只补缺失值；旧用户的主动语言、暂停、过滤等不重置。缺失值不等于 false，加载失败不写默认覆盖。 |
| MIG-02 / UX-R2 | 稳定阅读锚点、最近正式阅读对象；设备本地 meta | 不从“最近收录”推造历史阅读。第一次无锚点时显示最近收录；默认不入 Backup。按对象清理，容量有界，仅保留最近200个锚点，淘汰位置不删内容。 |
| MIG-03 / UX-R2 | visit boundary / 本次回访窗口；设备本地 meta | 新语义不覆盖旧已读字段的历史含义。升级时以当前安全序列建立起点，旧标记只读兼容；第一次不把全库算新增。Backup恢复后重新建立，不还原已读结论。 |
| MIG-04 / UX-R2 | 回顾 opt-in、单条/会话/主题排除、精确会话收录排除；既有 policy/meta | 默认不主动旧内容重现；已有用户显式排除保留。永久删除清理目标引用；保留安全限制所需body-free信息。回顾排除可随内容Backup带走；恢复后旧内容回顾总开关仍关闭。 |
| MIG-05 / UX-R3 | 既有 Thought 上的 `bodyBinding` 或等价元数据、可证明的 live `workingInputId` | 按§6.2迁移；不改正文、不重写 Source、不按字符串相似度合并。新旧DTO、revision、导出、Backup校验同步更新。 |
| MIG-06 / UX-R3 | 高级反向写入开关；现有 preferences/meta | 首次引入默认关闭。恢复后关闭；仅未来符合条件的操作生效。不得撤销历史上已经发生的 Input 编辑。 |
| MIG-07 / UX-R4 | 手动选择 refs、intent、输出generation、编辑/遮挡；可信短期状态 | 不创建持久 Context 正文表。旧 Preview 按旧契约失效/重建，不能迁移为已授权新包。现有Grant及deny语义不扩大；手动意图不能从任意内容脚本声明获得。 |
| MIG-08 / UX-R4 | Local-only、独立连接访问开关及旧 `externalAccess` 的语义映射 | 旧false保持连接禁止；手动输出按新manual路径，但明确deny/never继续检查。旧true不自动建立新的消费者或Grant。关闭总限制不重放旧任务。 |
| MIG-09 / UX-R5 | 主题级会话视图偏好；已有有效整理稿、人工稿与候选generation | 旧全局偏好只读兼容，最多用于当前已打开主题；新视图选择按Topic在本标签保存，不继续写全局开关。普通新打开默认原话，明确阅读锚点/AI搜索目标优先。已生成稿、人工修订和候选保留，不重算代替。 |
| MIG-10 / 每个所属轮次 | Backup/export白名单、DTO与对象兼容映射 | 当轮新增受保护字段当轮完成round-trip测试，不能拖到UX-R6。Unknown newer format拒绝恢复，不降级吞字段。用户数据和策略完整，凭证/密钥/临时包/Passport Grants/阅读游标不因新增字段进入Backup。 |

上述数量限制为实现保护默认，不是正文/数据容量上限。位置元数据淘汰必须与用户档案保留完全分离。

### 6.2 Thought binding 的迁移判定

迁移以现有来源、依赖、revision、完整span、`workingInputId` 和实际正文的证据判定，不能单独依据“文字相同”或一个 human flag。

| 旧状态 | 新状态 | 必须保留 |
|---|---|---|
| 已有明确有效的live workingInputId，单一完整来源、当前正文与Input一致 | `input`，保持一对一跟随；默认反写仍关闭 | 旧Input/Thought原有修改、历史、provenance、限制。 |
| 无显式link，但原有严格完整引用推断可证明：单一来源、完整span、版本匹配、没有Thought独立改写 | `input` | 既有内容，不新写一份“初始原文”。 |
| 人工Thought正文与当前Input不同，或明示独立Thought/摘录/多源综合 | `thought`，清除live workingInputId | 既有thoughtText及人工保护、原时间和依赖；不能把它覆盖成Input当前值。 |
| 证据不完整、历史标记歧义、link与正文矛盾 | `thought`并保护现有正文；高级诊断记数量/错误码 | 不猜测修复，不把不确定映射当反写授权；用户可以后显式“恢复为档案当前文字”。 |
| Source已purged或目标已删除 | 先执行现有删除/失效规则，再迁移剩余合法元数据 | 不从旧mirror、revision、缓存恢复已删原文。 |

当前 `propagateInputWorkingChange()` 也可能标记human；因此不能将“出现human标记”一律解释为用户在思想库独立改写，或一律解释为可共享。必须结合正文、link、来源和历史角色。迁移报告只记录数量、规则与异常，不能泄漏私人文本。[S9][S10]

**写入顺序：**逐批读取并分类 → 校验当前revision → 同事务写最小元数据/必要link清理与迁移标记 → checkpoint → 下一批。中断可重入、重复执行结果相同。未完成条目的读/写路径用同一安全判定，不出现旧代码绕过默认关闭反写的窗口。

**禁止回滚策略：**不得通过回滚到旧程序重新开放不安全共享编辑。迁移后回退UI必须仍使用已修正domain；旧程序无法理解新binding时禁止写入，保留导出/诊断。不得以“向后兼容”为由再启用无条件反写。

### 6.3 引用、搜索和导出的共同新鲜度

`bodyBinding=thought`后，所有Reader、Search、AI evidence与Context必须读取同一既有Thought正文；不能Reader显示改写，Search仍读旧Input，Context又读第三版。来源证据可过期，但人工正文不因此被替换。当前工作内容与历史Source在DTO中保留角色，不以客户端样式区分真伪。

索引是可重建投影；新schema或binding生效时可以逐批失效重建，但搜索须显示真实覆盖，不能谎称全库无结果。添加主题保持provenance与删除关系；解除正文跟随不解除隐私限制。

### 6.4 每轮迁移验收

使用旧版合成fixture复制库，记录对象ID、Source文本哈希、Input/Thought正文与revision、人工标记、placement、未知时间、tombstones及拒绝策略。执行升级、重复升级、半途断电模拟、恢复旧Backup、重新捕获同一来源五条路径。

Source正文和历史事实必须不变；正常工作正文不因UI升级改变。默认关闭的反写只约束未来，不抹掉已发生的编辑。只允许本文批准的元数据与投影变化。迁移失败保留可导出数据，不自动清库。

## 8. 连续开发计划：UX-R1—UX-R6

### 8.1 执行边界

每轮是可合并、可运行、可测试的完整纵向切片，不是先拆旧页面再等几轮补齐功能。复用同一个`archive.html`与现有domain services，通过小范围组件/控制器替换交付；不进行全仓目录搬迁或框架迁移。

过渡期仅允许**已完成的新页面 + 完整可用的旧页面**共存；相同功能只有一个对用户生效的入口和写入路径。新按钮尚无闭环时不发布该按钮；旧入口在新旅程通过后才移除。调试开关可以用于测试，不作为用户需要理解的第二套产品模式。

## 9. 状态机与验收追踪补充

### 9.1 AI Organize 的执行状态与显示状态分离

显示状态是`Original / Organized`，运行状态是`idle / confirming / preparing / processing / validating / candidateReady / failed / outcomeUnknown / stopping`；材料另有`current / stale / unavailable`。这些是同一能力的不同维度，不得把“AI已开启”同时用作“正在联网”和“用户已授权”的代称。

| 事件 / 前提 | 显示与动作结果 |
|---|---|
| Original点击AI开关，无有效缓存 | 打开本主题确认。开关仍表示Original；取消保持原样。确认后显示processing但原话继续可读，不能先显示空Organized。 |
| 首生成完成、材料有效、当前仍在此主题等待、无未保存编辑 | 通过校验后短转场到Organized，开关状态更新。离开后完成仅记录可查看结果，不抢页面。 |
| 有有效缓存点击开关 | flush当前编辑成功后直接切换；不检查Key有效性来阻断缓存阅读，不调用Provider。 |
| 有旧稿且材料已变化 | 旧稿可读并标“材料有变化”；主动更新不隐藏旧稿。旧稿的来源若被删除，则相关内容先失效，不能以“旧稿”名义继续显示已purged文字。 |
| 更新完成、当前稿无人为改动 | 显示“新整理已准备好 · 查看”；点击才应用已校验新稿并保留可匹配锚点。不自动滚屏替换正在阅读内容。 |
| 更新完成、已有人工改稿或处理中有人编辑 | 打开候选比较；“采用这一段”只暂存选择，“保存这些选择”以一个事务形成新受保护版本。剩余段落保留当前，关闭不自动采用。 |
| 比较期间当前稿/材料又变化 | 提示“内容刚有更新，请重新核对”；保留选择意图，不提交旧基准。再次读取并比较后显式保存。 |
| 无材料变化点更新 | 提示“当前材料没有变化。”；不发请求。 |
| stop / timeout / 结果未知 | 停止后续请求，已发请求不承诺撤回。先读取现有job状态；未能确认结果不自动重试，也不生成假的失败完成数。 |
| 禁止云端处理或仅本机模式开启 | 取消可取消的尚未发出任务并阻止后续请求；缓存仍可读。开启操作发生前已发出的数据不承诺收回。 |
| 从Topic切到另一个Topic | 保留各自视图/锚点会话状态；新Topic默认Original，不触发模型。 |

新AI稿正文的结构由已授权整理得到，不固定成“最初→转折→现在”。不存在变化证据时保留并列问题/重复思考；读者可从每个生成段回到其支持原话。所有AI新增标题/过渡语与逐字引用在内部有角色区分；视觉不要求给每句话加徽标。

### 9.2 Material / Preview 状态与输出门

| 事件 | 状态与必须结果 |
|---|---|
| 选择全文/选段 | 创建固定ref与版本范围；同一ref重复提示已加入；不同版本不得自动替换。 |
| 请求整主题/全部结果 | 先枚举并显示准确范围；超出现有有界能力时明确停止/分批选择，已选项保留。不能仅加入已加载页却写“全部”。 |
| 未填本次问题 | 允许按明确选择直接生成预览，不强制query或自动推荐。 |
| 请求补充 | 按允许范围本地检索；建议未选中，与明确选择分区；未获云端查询授权不调用模型。 |
| 初次构建 | `building`；成功为`ready`，失败为`error`且材料清单仍在。 |
| 用户改字/调序/遮挡 | `dirty`；确认新的输出版本后`ready`。改变只属于本次输出，原内容不变。 |
| 来源/版本变化 | `stale`；原预览可对照但不可按旧generation输出，须核对并重新准备。 |
| 来源移除/purge或有效禁止规则改变 | `blocked`；受影响文本从可输出预览中立即去除/遮挡，受阻条目位置与原因仍显示。用户明确移除或解决后才能重建为ready。 |
| service-worker/包期限失效 | `expired`；UI缓冲不是授权。可按仍合法refs和用户改稿重新验证生成新包，不直接从旧DOM走程序化输出。 |
| 输出按钮 | 仅`ready`且最终可信校验通过；锁定该generation、格式与人工输出版本。同一次操作幂等，晚到版本变化拒绝输出。 |
| 剪贴板失败但可信校验已经通过 | 提供该次已校验文本的手动全选复制或文件导出；不改变内容、不自动调用模型。 |
| 任意输出成功 | 显示“已复制，尚未发送。”或“文件已生成”；不声称外部AI已接收。 |

多种异常并存时先展示安全原因：`blocked`优先，其次`expired`，再`stale`，最后编辑/普通错误；不能因为一个“仍在保存”的轻状态遮住禁止外发。受限材料本来就在用户自有档案中，不代表PAIA能控制系统级复制或历史外部副本。

1. **先读最高约束。**《PAIA设计核 v1.0》高于本文；本文高于旧UI。本轮不重新定义PAIA，也不把暂不实现的长期方向删除。

4. **先复用域服务。**UI负责呈现/交互，trusted service负责来源、编辑、删除、版本和授权。使用现有Source/Input/Thought/AI/Context路径，不新建重复truth store，不用全量换框架替代改进。

6. **安全与迁移当轮交付。**更新DTO、read path、write path、revision、Backup/export和测试；不只修改按钮或表面状态。Thought独立编辑仍留来源关系，不借detach逃避删除/禁止。
7. **像素可调，语义不可漂移。**允许调整§5tokens，记录diff和视觉证据；不把参数调整扩展为导航、编辑范围、授权或内容策略的另一次设计。
8. **每轮实跑检查。**unit、真实browser、privacy/adapter、package/development、完整suite与release checks按§7执行；不可用记BLOCKED。不得删除测试、降级guard、mock掉真实信任边界来取得绿色结果。
9. **冲突时停止相关实现并报告。**给出Spec ID、实际文件/函数/行号、冲突事实、风险、最小可行调整及需要的决策。不得自行创造多层正文模型、改变数据所有权或放宽权限。保留最后可用状态，不继续依赖冲突推进下一轮。
10. **交付可接续证据。**按§9.4报告；仅更新repo中的实际实现状态、规范链接和测试入口，不重写Product Constitution。声明工程验证范围，不宣称留存、真实Provider兼容或未运行的用户硬件验证已成立。
