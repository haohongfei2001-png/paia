# PAIA 设计核

版本：v1.0（基于《PAIA设计想法》v2.5 整理）  
性质：长期产品设计底本。保留已确认的核心设想，清理聊天残留、重复表述与逻辑冲突；不等同于当前实现清单、UI 定稿或开发路线图。

# 0\. 设计核摘要

PAIA 是一个面向 AI 时代的个人输入、思想与上下文系统。它首先从用户在 AI 中已经自然产生的表达开始，通过自动沉淀、可读回看、长期理解和再次利用，把原本散落在不同聊天窗口中的个人内容变成用户自己长期拥有、可编辑、可追溯、可迁移的数据资产。

PAIA 不要求用户像经营笔记库一样持续整理。即使用户几乎不做人工加工，Input Archive 也应当已经比原始聊天历史更适合长期阅读和查找；Thought Library 在此基础上帮助用户跨会话形成长期主题和思想脉络；AI 整理进一步重组表达，使复杂内容更清晰，但不能替用户发明立场；AI Context 则把用户明确允许的相关材料重新用于新的 AI 交互。长期来看，PAIA 可以逐步成为用户侧的 Personal Context / Memory 基础，并扩展到更多个人信息来源，但不以“接入一切”本身作为目标。

# 1\. 产品定位、核心用户与长期愿景

1.1 核心产品定义

PAIA 的核心对象不是聊天记录本身，也不只是 Prompt，而是用户在 AI 时代持续产生的个人表达、信息、判断、偏好、决定、问题、假设与思考轨迹，以及理解这些表达所必要的最小语境。

AI 对话是 PAIA 的第一个主要采集入口，而不是永久唯一来源。未来可以接入备忘录、创作平台、语音记录、待办事项等信息源，但每一个新来源都必须能够显著改善“留下—回看—理解—复用”的核心价值链，而不是为了成为万能数据中心而扩张。

1.2 首批核心用户

首批核心用户是长期、高频借助 AI 思考持续性问题，并已经积累大量个人输入，却难以跨会话回看、理解和复用的人。典型场景包括长期项目、求职与职业决策、研究学习、创作、个人计划和反复推敲的长期问题。

PAIA 的价值不依赖用户同时使用多个 AI。即使只使用一个 AI 产品，跨会话的断裂、历史难以阅读和上下文难以复用也已经构成问题；多平台只会进一步放大这一需求。

1.3 核心价值链

PAIA 的核心循环是：Capture → Revisit → Understand → Reuse。

Capture 负责降低保存成本；Revisit 包括继续阅读、主动查找和重新遇见旧内容；Understand 是用户通过阅读、主题组织与可选 AI 整理获得的理解；Reuse 是把相关内容复制、导出或重新提供给 AI。Organize 是加速理解的能力，不应成为使用其他能力的前置条件。

任何新功能都应首先回答：它是否显著提升了长期保留、回看、理解或复用的效率与可信度。如果只是增加设置、装饰或整理负担，不应进入核心产品。

1.4 长期愿景

PAIA 首先必须成为一个用户愿意长期保存和阅读私人内容的产品。在这一基础上，它可以逐步成为用户侧的个人 Context / Memory 基础：由用户掌握自己的长期表达与信息，再按具体任务把最小必要内容提供给不同 AI 或系统级 AI。

“为人可读”和“为 AI 可用”不是互斥方向。前者是信任和长期价值的基础，后者是 PAIA 在 AI 时代可能形成的重要战略价值。当前是否作为一级导航、是否已有外部连接器，不决定其长期重要性。

1.5 当前能力模型与信息架构假设

PAIA 当前可以用 Input Catch \+ Input Reader / Input Archive \+ Thought Record \+ Thought Organize \+ AI Context \+ Passport 描述主要能力。它们代表不同职责，但不要求永久对应六个页面或六套数据库。

当前的一级信息架构工作假设仍可保留 Input Archive、Thought Library、AI Context 三个主要入口：Input Archive 面向原始来源和长期阅读，Thought Library 面向主题化思想组织，AI Context 面向授权后的再次利用。但“长期战略重要”不等于“现在必须一级导航”，具体导航和首页任务组织应在 UX 设计阶段继续验证。

# 2\. 产品基本原则

2.1 自动沉淀优先，人工整理可选

PAIA 不依赖用户持续加工。自动捕获、历史导入、轻度过滤、连续阅读和搜索应让用户在不整理的情况下也能获得价值。人工编辑、主题组织和 AI 整理应当是容易使用的增强能力，而不是维护义务。

2.2 原话优先，但不把“用户发送”自动等同于“用户观点”

用户发给 AI 的文字可能是自己的观点，也可能是引用、岗位 JD、他人文本、角色扮演、待改写材料或纯操作指令。PAIA 可以保存“用户曾发送这段文字”的事实，但在 Thought Library、观点演化和 AI Context 中不能未经证据把所有 user message 自动解释为用户长期相信的观点。

2.3 保留必要语境

只保存孤立的用户句子可能导致“第二种”“就这样”“继续”等内容多年后无法理解。PAIA 不必因此默认保存所有 AI 回复，但需要保留足以重新理解表达的最小语境，例如引用关系、被回复对象、附件/引用存在信息、来源跳转、必要的上下文片段或其他可追溯关系。

2.4 历史事实与当前工作版本分离

Source Record 负责保留当时真正发生过什么；用户可编辑的工作版本负责当前阅读和整理。今天修改后的文字不能在历史比较或观点演化中冒充过去的原话。发送/创作时间、采集时间、导入时间和编辑时间应在数据语义上区分，不知道时明确未知。

2.5 用户编辑优先，AI 不静默覆盖人工工作

用户主动删除、修改、补充、排除、归类和编辑 AI 整理结果后，自动过滤、重新整理、同步和重算都不得无声覆盖这些人工决策。AI 生成内容和人工内容必须在数据层可区分。

2.6 组织和 AI 整理是可重建的呈现，不是新的个人真值

主题、搜索结果、Revisit、AI 整理和 Context 都是围绕可信数据生成的组织或投影。它们不能成为唯一、不可追溯的新正文来源，也不能因为重新计算而抹掉 Source、工作正文或独立人工内容。

2.7 Smart Filter、主题归属、删除和 AI 授权是四种不同语义

“默认不展示”“不进入某个主题”“从档案删除”“不能提供给 AI”不是同一件事。一个动作不能暗含另一个动作。尤其 Smart Filter 只改变默认阅读可见性，不物理删除 Source，也不等价于隐私授权。

2.8 显式选择优先于算法推断

当用户明确选择某条内容用于复制、加入主题或提供给 AI 时，这一选择应得到稳定保留。搜索、语义匹配和 AI 检索可以补充相关材料，但不能用算法结果替换掉用户明确选中的内容。

2.9 历史内容不是当前操作授权

档案中保存的 Prompt、命令句、角色设定或旧授权只是历史内容，不能自动成为 PAIA 或外部 AI 当前应执行的指令。当前授权必须来自用户现在的明确操作。

2.10 工程完成不等于产品价值成立

功能已经实现、测试通过、架构完整，只能证明工程完成。Reader、Search、Revisit、Thought Library、AI 整理和 AI Context 是否真正有长期价值，仍要通过真实使用中的回看、找回、重复访问和复用行为验证。

2.11 本地优先与分离授权

PAIA 的普通阅读、编辑、搜索和本地组织应尽可能在设备本地完成。保存/捕获、调用外部 AI 处理、设备同步、对外提供 Context 是四类不同授权；开启其中一项不能暗含其他项。

用户可以随时关闭 PAIA 主动发起的云端 AI 处理、远程同步或连接访问，同时继续在本地阅读、编辑、搜索、复制和导出。内容一旦被用户主动复制、导出或发送到外部系统，PAIA 只能停止后续提供，不能承诺收回外部副本。

# 3\. 数据分层、真值角色与编辑传播

3.1 Source Record

Source Record 保存外部来源事实：原始用户文本、来源身份、原始时间证据、会话/消息身份、导入或捕获事实，以及必要的防复活 tombstone。它不应被普通编辑覆盖。

Source 重要，但不应成为日常阅读界面的负担。来源、证据和原始记录默认弱化，在用户需要核对时通过低干扰入口查看；无需在每段正文旁重复展示来源。

3.2 Input Archive

Input Archive 是用户认可的可编辑阅读层。它承载用户在 PAIA 中日常看到、修改、复制和删除的工作正文，同时保留与 Source 的来源关系和版本历史。

Input Archive 的编辑应像 Word 一样低摩擦：直接编辑、自动保存、Undo/Redo、版本历史、复制和整条移除都应尽可能自然，不要求用户先进入复杂编辑模式。时间标签、来源和系统元数据在阅读时应弱化。

3.3 Thought Library

Thought Library 是围绕长期主题组织个人表达和思想的层。它与 Input Archive 回答不同问题：Archive 回答“我在什么时候、哪个来源/窗口说过什么”，Thought Library 回答“我长期围绕某件事想过什么、不同表达之间有什么关系、这些内容如何变化或延续”。

Thought Library 不是简单把聊天窗口重新分类，也不应要求用户维护复杂本体。Topic 是主要用户心智；Section、Entry 等结构只在确实有助于长内容阅读和组织时出现，不应成为用户必须理解的对象。

Thought 可以直接来自 Input，也可以由用户在 PAIA 中主动新写。用户新写的 Thought 应按实际创建时间进入系统，不伪装成过去的外部输入。

3.4 同一内容与反向修改

PAIA 应尽量避免让同一份完整内容在多个入口形成需要重复维护的正文副本。当 Thought Library 展示的是某条 Input 的明确原话/同一工作内容时，应尽可能共享同一可编辑对象或稳定引用。

对于用户希望“修改思想库同时影响档案”的场景，可提供设置中的高级开关，由用户选择是否允许 Thought Library 的修改反向影响 Input Archive，默认关闭。只有在系统能够明确识别同一条内容、并能安全映射的情况下才允许传播；独立 Thought、局部摘录、多条综合、AI 整理稿或语义不明确的内容不得被算法猜测后反向改写历史 Input。

Input Archive 的用户修改原则上应继续影响依赖它的 Thought 证据和后续 Context，但传播可以通过引用更新、失效标记或重算完成，不要求每次立即调用付费 AI。

3.5 AI Presentation / AI 整理结果

AI 整理属于基于 Thought Evidence 的派生呈现。它可以被用户编辑，但人工修改后的结果应得到保护；重新生成时形成新的候选结果，不覆盖用户已经修改过的整理稿。

3.6 AI Context 与 Passport

AI Context 是面向具体任务生成的最小必要上下文，是用户重新利用自己长期信息的能力，而不是第四份永久正文数据库。Context Package 可作为内部数据契约；正文默认短期存在，用户明确保存的输出草稿除外。

Passport 是未来外部 AI / 工具访问时的权限治理能力，用来表达“谁、为了什么、在什么范围和期限内可以使用哪些 Context”。在手动复制/导出场景下，不应制造 PAIA 能控制外部副本生命周期的假象；真正的消费者身份、期限和撤销，应在 PAIA 能实际控制外部访问链路时发挥作用。

# 4\. 数据采集、历史导入与长期保存

4.1 自动捕获与时间

在用户明确授权后，PAIA 应自动捕获符合条件的已发送用户内容，尽量记录每条消息真实发送时间，而不是把捕获时间冒充发送时间。打开旧对话时可以补录历史消息；来源时间不可靠时明确标记未知。

Temporary Chat 默认不自动抓取，因为它与临时、不留存的用户预期冲突。未来如支持，更适合显式单次保存。

4.2 历史导入

PAIA 应支持通过官方导出文件补全历史输入和原始时间。Import、Sync 和 AI Update 必须是三个不同概念：Import 负责把过去数据带入 PAIA；Sync 负责设备之间保持一致；AI Update / Refresh 只处理新增或变化的派生内容。

4.3 十年级别的长期存储

如果 PAIA 承诺长期保存，备份、恢复、版本迁移、去重、防复活、索引重建和开放导出都应视为基础能力。数据规模和存储上限不应成为用户无法理解的隐性断点；具体工程上限可以迭代，但产品语义必须为长期大库成立。

# 5\. Input Archive：组织、阅读与编辑

5.1 组织方式

Input Archive 仍保留来源会话/窗口作为重要的熟悉线索，但这不意味着用户每次进入 PAIA 都必须先管理窗口。首页可以围绕继续阅读、寻找旧表达、回访和最近内容等任务组织；具体一级导航和首页结构属于 UX 设计假设，不在设计核中永久冻结。

原平台的 Project 等结构可以作为来源侧分组信息帮助浏览，但不应直接成为 Thought Library 的主题体系，也不应自动影响授权。

5.2 连续阅读

打开一个来源/窗口后，内容按时间形成连续可编辑文档，优先提供接近 Word 的长期阅读体验。用户可以切换时间正序/倒序，时间和来源元信息保持弱化但可追溯。

窗口可生成极短摘要，帮助用户快速判断内容，但摘要不能替代正文，也不能成为新的事实来源。

5.3 长输入折叠

过长输入可以采用轻量折叠以改善扫描效率，但折叠只是展示策略，不影响正文、搜索、Thought、AI Context 或导出。具体阈值（例如三行）属于 UX 待验证参数，不在设计核中固定。

# 6\. Smart Filter 与阅读优化

6.1 定位

Smart Filter 是提高 Input Archive 阅读体验的重要能力，入口主要放在设置中，默认使用轻度档位而不是完全关闭。轻度模式只过滤高度确定的纯控制性、无长期阅读价值内容，并应尽量避免误伤事实、观点、偏好、决定、纠正、创作、附件相关表达等内容。

6.2 可逆与可恢复

Smart Filter 的核心语义是默认隐藏/降低可见性，不是物理删除。规则变化后内容可以恢复显示；用户手动恢复的内容不应再次被自动隐藏。Source 始终保留，除非用户执行永久删除。

6.3 强度与 Thought 的关系

更强的过滤可以作为用户可选能力，但不能把“通过强过滤”定义为一段内容是否有资格成为用户思想的唯一标准。Thought Library 的内容选择应综合用户明确行为、语义关系和上下文，而不是由一个过滤等级裁决。

# 7\. Thought Library：长期主题、原话与思想轨迹

7.1 核心形态

Thought Library 是长期主题层。它聚合来自不同来源、不同时间的相关表达，并允许用户在一个主题中继续阅读、补充和编辑。其价值来自跨会话积累，而不是一次性摘要。

主题页应保留时间脉络，包括早期表达、关键转折、最近表达和支撑这些变化的原话；没有足够证据时，不强制把并列、反复或矛盾表达编成一条顺滑的“成长故事”。

7.2 用户主动控制

用户应能把 Input Archive 中的内容加入 Thought Library，并指定主题；未来可以提供智能归类，但自动归类不能取代用户明确选择。产品整体仍应尽量减少整理负担，避免变成精细化笔记工具。

7.3 阅读布局

Thought Library 的外部组织形式应与聊天窗口列表明显不同，更适合跨主题浏览。可以使用思想块/主题卡片等形式，但具体卡片形状、密度和布局属于 UX 设计，不在设计核中固定。

# 8\. AI 整理 / AI 概览

8.1 原话优先与双视图

Thought Library 默认优先使用用户原话和接近原始表达的组织方式。AI 整理作为同一主题、同一批可追溯材料的另一种呈现，而不是第二套独立思想库。

用户打开 AI 整理后，系统可以改变结构、顺序、分组、标题和层级，帮助用户更快理解自己的复杂表达；但不能擅自改变用户立场、确定性、因果关系、情绪强度，也不能把 AI 推断写成用户观点。

8.2 更新方式与成本

AI 整理应尽可能围绕当前主题或用户明确选定的内容工作，并优先进行增量更新：先识别新增/变化内容，再判断其与已有结构的关系，避免每次处理整个思想库。增量策略服务于成本和速度，但不能因为节省 token 而忽略被新内容影响的旧关系。

8.3 AI 整理的体验

AI 整理是 PAIA 中少数可以明确使用动效表达“结构发生变化”的地方。切换过程应带来记忆重新展开、思维被梳理、内容焕然一新的感觉，可以使用克制的模糊、毛玻璃、碎片聚合或结构刷新感，但不使用持续发光、无意义渐变等装饰制造“AI 感”。

动效既可以承担产品表达，也可以自然覆盖模型处理时间。即使处理很快，也可以保留短而顺滑的状态变化，只要不拖慢使用。

# 9\. Search、Revisit 与长期回看

9.1 Search

搜索在视觉上可以弱化，但能力不能弱化。随着数据跨越数年，PAIA 需要能够按关键词、时间、来源、主题和自然语言意图找回旧表达，并直接定位到对应上下文。

“语义搜索”是能力目标，不是必须绑定某种技术实现。词面检索、语义模型、向量或混合检索应由真实找回效果和成本决定；在没有证据证明需要前，不因为技术潮流增加复杂度。

9.2 时间阅读与“以前的我”

PAIA 可以提供按时间查看同一问题相关表达的能力，帮助用户比较过去与现在。但时间排序本身不能被解释成观点已经发生变化，更不能把有限搜索结果宣传为完整思想史。历史比较应尽量使用当时版本和可靠时间证据。

9.3 Revisit / 回访

Revisit 是低负担的重新进入入口，用于继续阅读、新积累内容回看、发生变化的 Thought 和少量有明确理由的旧内容重现。它不应成为无限信息流、打卡任务或通知增长机制。

具体 baseline、已读游标、旧内容年龄阈值等属于实现策略，可以迭代；用户心智应尽量简单：PAIA 帮我重新遇见值得看的自己的内容，而不是制造“还有多少没处理”的债务。

# 10\. AI Context、外部 AI 与用户侧 Personal Context Layer

10.1 当前产品意义

AI Context 不只是授权设置，也承担“把过去的信息重新用于新的 AI 任务”的核心意义。用户可以从 Search、Reader、Thought Library 或明确选择的记录出发，为某次任务准备上下文；未进入 Thought Library 的内容也可以被直接使用，不应强制先完成组织。

10.2 最小必要 Context

Context 应围绕具体任务按最小必要原则生成。用户明确选择的内容必须优先保留，相关检索只能补充，不能替代显式选择。发送前应允许预览、删改，并清楚区分“在本机准备”与“已经对外提供”。

10.3 长期战略

长期来看，PAIA 可以成为用户侧的 Personal Context / Memory 基础，为 ChatGPT、其他 AI 产品、系统级 AI 或未来 Agent 提供由用户控制的个人上下文。它的差异不在于比系统级 AI 收集更多，而在于：数据首先为用户自己可读、可拥有、可编辑，外部 AI 只获得用户愿意提供的一部分。

这一长期方向保持开放，但当前是否使用一级导航、何时开发 Connector / API / MCP、是否需要多套 Profile，都应由真实复用需求决定，而不是提前扩张。

# 11\. 删除、版本、撤销与数据所有权

11.1 可见移除与永久删除

删除语义至少区分“从正常档案中移除”和“永久删除来源数据”。前者保留防复活标记，重新捕获同一 Source 时不会自动回到正常档案；后者应清理 PAIA 可控制范围内的 Source、工作版本和依赖内容，并保留不含正文的必要 tombstone。

用户在原 AI 产品中删除聊天，不自动删除 PAIA 已保存的数据；PAIA 中永久删除也不能承诺删除外部平台、已导出文件或第三方已经保存的副本。

11.2 版本与历史

用户编辑必须可以撤销，并保留必要版本历史。旧历史证据不被今天的工作版本覆盖；新写的 Thought 和新的观点修正按真实创建时间追加。

11.3 用户拥有数据

长期私人档案必须支持完整导出和安全离开。PAIA 不应通过封闭格式、云端绑定或权限结构锁定用户。

# 12\. 跨平台、信息源与 App 扩展

12.1 信息源扩展

除其他 AI 外，未来可以连接备忘录、待办事项、小红书/微博等用户创作内容、语音碎片等来源。不同来源有不同时间语义和可编辑性，不能假设所有来源都像聊天消息一样不可变。

接入后必须区分内容角色：用户本人写的、AI/他人回复给用户的、用户引用/收藏的。只有 user-authored 内容默认进入“我的表达/思想”路径；其他内容可以作为语境、证据或收藏存在，但不能自动被当作用户观点。

12.2 平台职责

Extension 重点负责无感捕获和快速复用；Web / Desktop 更适合完整阅读、整理、搜索和管理；Mobile 更适合随时查看、快速记录、语音输入和从其他 App 选择性分享进入。

不同终端不必复制同一套 UI。平台扩展应该在它能提供新的真实价值时发生，而不是为了“有 App”而套壳。

# 13\. 导出、私人边界与分享

PAIA 的核心是私人记录，不应通过内置社交机制反过来污染用户记录动机。更合适的路径是导出、生成思想记录或用户自主生成分享材料；是否分享以及分享到哪里由用户在 PAIA 外决定。

导出不仅服务分享，也承担数据迁移。至少应能导出 Source、Input Archive、Thought Library 及必要元数据到开放格式，让用户停止使用 PAIA 后仍能完整带走可理解的数据。

# 14\. 设置、语言与个性化

设置承载低频控制，不应把高频主流程藏起来。Smart Filter 强度、Thought→Input 反向传播开关、授权、同步、安全、语言和外部连接等适合放在设置；日常 Search、AI 整理、Revisit、复制和复用应直接存在于主界面。

设置修改应尽可能立即生效，不要求用户刷新或重新进入。语言应优先跟随用户系统/主要使用语言，并提供手动切换；IP 只可作为弱参考，不作为唯一判断依据。

换肤和阅读个性化可以存在，但不应在核心阅读体验、信息架构和数据可信性之前成为重点。

# 15\. UI、视觉与交互原则

15.1 阅读优先

PAIA 的界面首先服务长期阅读。长文本排版、层次、留白、稳定导航和低干扰编辑比卡片装饰、炫技动画和“AI 风格”更重要。

15.2 控制项少而稳定

低频来源、时间、证据和权限信息应弱化但可达；用户不需要理解数据库结构才能完成阅读、查找、整理和复用。

15.3 编辑自然但不误改

可编辑性应接近文档工具，而不是到处出现“编辑/保存”按钮；同时通过自动保存、撤销、版本历史和清晰状态保证用户不因低摩擦编辑失去历史真实性。

15.4 动效只表达状态和结构变化

动效重点用于进入、返回、AI 整理、结构重组、加载和状态变化，不以持续发光、无意义渐变或装饰性毛玻璃制造 AI 感。AI 整理可以拥有更独特的“记忆重组”动效语言。

15.5 低层级视觉偏好

删除等高风险动作应使用含义稳定、符合用户习惯的视觉语义；例如删除优先使用传统垃圾桶图标，而不是容易与关闭/取消混淆的叉号。此类细节属于设计系统偏好，可随实际可用性测试调整，但不应牺牲直觉。

# 16\. 商业化与 AI 成本控制

PAIA 的基础归档、阅读和基本搜索应尽可能保持低门槛。长期收费应围绕用户持续获得的价值，例如云同步/容量、多来源连接、深度 AI 整理、高级检索、长期趋势与更强 Context 能力，而不是让用户感知 token、调用次数或复杂充值等级。

AI 成本优先通过增量处理、范围约束、缓存和只处理变化内容控制。具体处理链路不在设计核中硬编码为固定“过滤→分类→整理”流水线，以免未来模型成本、检索和本地能力变化后反而限制产品。

# 17\. 产品验证原则

PAIA 的真实价值要通过用户在长期数据上的自发行为验证，而不是通过功能数量、导入规模或演示效果证明。重点观察的不是“用户创建了多少 Topic”，而是用户是否会主动回来阅读旧内容、能否更快找回过去表达、是否重复进入长期主题、是否愿意把历史材料再次用于新的思考或 AI 任务。

产品验证可以使用本地、低侵入、默认关闭或明确授权的聚合信号，但不得保存私人正文、搜索词或借分析机制影响授权和内容选择。验证机制服务于产品判断，不成为新的用户负担。

# 18\. 当前开放方向与待验证问题

以下内容保留为开放方向，不应因为当前没有实现或没有验证就从长期愿景中删除：

\- PAIA 的最终品牌名；当前工作名为 PAIA。  
\- 长输入折叠的最佳规则和视觉形式。  
\- ChatGPT Project 等来源侧分组如何映射到 Input Archive 浏览。  
\- Thought Library 的最佳主题粒度，以及 Topic / Section / Entry 对用户应暴露到什么程度。  
\- AI 整理的删改强度、默认档位和最佳动态体验。  
\- Thought Library 修改反向影响 Input Archive 的高级设置，在真实使用中是否有足够价值以及哪些内容允许安全传播。  
\- AI Context 是否需要成为一级导航，或更多作为 Search/Reader/Thought 的“用于 AI”动作存在。  
\- External AI Context Connector、GPT 插件、API / MCP / Agent 接入的长期形态。  
\- Notes、创作平台、语音等多来源接入的优先级。  
\- Web / Desktop / Mobile 的最佳进入时机和各自独特价值。  
\- 更强语义检索、长期观点变化分析和个性化 Revisit 的必要程度。

# 19\. 当前明确边界

PAIA 当前不以替代通用笔记软件、聊天软件、任务管理、团队知识库、社交内容社区或人格诊断系统为目标；也不以知识图谱、全量生活监控或自动向所有 Agent 开放个人数据为目标。

这些边界不等于永久禁止未来接入新的信息源或 AI 能力，而是要求所有扩展继续服务同一核心：让用户自己的长期表达和信息更容易留下、更值得阅读、更容易理解，并在需要时由用户自己重新使用。

## 设计核主句：

**PAIA 的目标不是替用户重新写一个更漂亮的自己，而是让用户在 AI 时代持续产生的表达、思想和信息不再被困在一次性对话里；它们可以被用户自己长期拥有、阅读、理解，并在未来重新成为新的思考和 AI 交互的上下文。**
