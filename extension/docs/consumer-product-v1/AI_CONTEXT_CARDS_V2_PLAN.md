## 1. 不再讨论的产品合同

### 1.1 四张卡

| 对象 | 职责 | 内容与状态归属 |
|---|---|---|
| 我的信息 | 相对长期稳定的本人事实 | 独立、可编辑的 Context Items |
| 我的规则 | AI 怎样与用户工作，含偏好与长期自然语言规则 | 独立、可编辑的 Context Items；不另加偏好卡 |
| 我的现在 | 当前阶段、重点、目标与正在解决的问题 | 独立 Context Items；不是项目管理、待办或进度条 |
| 我的输入 | 开放的 Thought Library Topics | 只保存稳定 Topic ID 和访问状态，不复制 Topic 正文 |

前三卡的新增、修改、删除不反写 Source、Working Input、Thought 正文、主题组织或原始时间。依据仅用于追溯与必要的安全判断，不是双向正文绑定。

普通 Topic 开关仅控制深入读取，不连带关闭已独立保存的前三卡内容。例如关闭某个主题不会自动删除独立的个人信息；停止提供个人信息应编辑／删除该项或关闭该 Card。不能在外部请求期间从关闭主题临时提取新信息绕过限制。永久删除、既有强制禁止及未解决的 B-02 衍生清理边界仍保留，不把普通关闭与永久禁止混为一谈。

### 1.2 获批界面

首页固定为 2×2，顺序为信息／规则、现在／输入。窄屏单列。前三卡展示类别概览与实际条目数，不展示姓名、学校、地点等详细正文；输入卡仅展示少量开放主题名和剩余数量。

页眉为小型 `AI 访问 · 开／关`；Card 胶囊为 `AI 可读／仅自己`；全局暂停时开放的 Card 显示弱化的 `已开放`。卡片进入与胶囊切换是独立动作，不嵌套按钮，不相互触发。连接管理仅为卡片后的轻入口。

前三卡进入正常二级页，正文可直接编辑，支持添加、删除、撤销、键盘、IME、保存失败保留及离开保护。常态只留一句维护说明；来源在 `… → 查看依据` 中按需出现。不引入 Edit → Form → Save 工作流。

我的输入使用紧凑胶囊：名称和状态足够；20、50、144 个主题使用同一自然滚动页面。没有搜索、筛选 tabs、批量、checkbox、Done、锁矩阵、权限 modal 或管理表格。开关不重排主题；顺序由 Thought Library 提供，不在本任务重设计其根页、分类或阅读器。

继续使用当前 PAIA 的 shell、导航文案、品牌、标题字型、正文角色、内容轴、颜色、焦点、暗色和断点。获批图稿中的 Context 特有布局优先于旧 Context journey；其他空间的主体视觉不变。

### 1.3 默认权限和连接

新用户默认：全局关、四卡关、所有新 Topic 关、无连接。已有本地内容不自动变成外部许可。关闭全局保留 Card／Topic／连接设置；关闭输入卡保留 Topic 设置；打开下级不暗开上级。新 Topic 不因输入卡已开而自动开放。

所有已连接且允许读取的 AI 共用一份 PAIA 级范围，不增加多 AI × 多 Topic 权限矩阵。连接、暂停、撤销、重连分别表达；连接成功不暗中重开全局访问。只展示真实可用连接，不将示例品牌当作已接通能力。

读取关系：

```
浅层 = 全局开 ∧ 连接有效且可读 ∧ 对应 Card 开 ∧ Item 合格
深入 = 全局开 ∧ 连接有效且可读 ∧ 输入 Card 开 ∧ Topic 开 ∧ 内容合格
```

权限须由可信服务执行，而不是仅隐藏界面。Rules 是用户数据／工作偏好，不是修改授权、执行写入或读取其他账户的命令。外部读取永不隐含写权限。

### 1.4 真正的使用完成条件

外部 AI 能先读开放的浅层 Context，需要时发现／搜索开放的 Thought Topics，再读取相关完整用户 Inputs。无足够信息就返回不足，不回退到 Input Archive，不开放 Conversation／Project／任意 Archive Input 接口。

整个开放 Topic 的合格内容必须可遍历到真实末尾；搜索摘要不替代完整读取。可以分页、去重和按需查询，不能把截断说成完整，也不能每次把全库塞进 prompt。

用户日常问 AI 时不需要打开 PAIA、不需要选材料、不需要 Review／Ready／Export。真实外部完成这条路径，才是连接能力完成；本地 worker 测试或模拟 AI 不等于它。

### CTX4-01 — 第一个真实闭环

**目标：在实际扩展中打开四卡首页，进入我的信息，写一条信息；真实保存、刷新后保留、修改、删除和撤销均成立，历史数据不变。**

工作：

1. 从最新 main 定位 AppShell／RouteSession、可信 worker 调用、持久化事务、编辑保存／撤销／草稿 owner；登记实际路径和受影响测试。这里是实现批次的短前置，不另开长期架构研究。
2. 为独立 Context Item、四个 Group 状态和 Global Access 建立最小数据契约。使用稳定 ID、正文 revision、写入确认、并发前置条件；禁止为方便 UI 把正文存进无保护临时页面状态。
3. 审核现有存储是否足够；新增 entity 的产品必要性已经明确，但 schema／object store 方案仍需最小化、兼容检查和受保护迁移。不得在本轮规划阶段自动执行破坏性迁移。
4. 在真实现有 shell 加入获批四卡首页与我的信息详情；所有概览和数量来自实际 owner。其他未完成行为诚实保留不可用状态，不植入固定个人信息或假连接。
5. 完成添加、直接编辑、删除抑制、撤销、持久保存及失败保留；当前无外部连接时不会外发数据。
6. 加入受影响单元、worker／事务及原生浏览器测试，校对首页／信息／编辑／空态／失败图。

退出标准：重载与受支持 worker 生命周期后已保存内容仍在；已保存／保存失败文案准确；改写不改变 Source／Input／Thought 快照；删除后不会由已在途更新复活；Global／Group 状态持久化且不暗开。界面来自实际源码，不来自设计 gallery。

不包含：付费调用、外部连接开通、整库自动提取、Topic reader 重设计、公开发布。

### CTX4-02 — 本地四卡产品完成

将 01 的真实 owner 扩展到 Rules／Now，完成三卡自然分组、依据按需展开、真实条目数与类别概览。人工项目与自动项目的写入来源和保护状态在数据层区分，正常 UI 不暴露工程字段。

完整处理 inline edit、Enter／快捷提交、撤销、删除／恢复、IME 不提交、并发保存、路由／返回锚点、页面离开、失败与重试。复用现有草稿机制的实际边界，不能无证据承诺标签页关闭或浏览器崩溃后全部恢复。

实现 Global／Card 三态呈现：本身关闭、上层暂停但设置保留、实际可读范围已开启。无连接不伪称已被 AI 读取。连接页在接通前显示真实空态／不可用态，不提供假成功。

退出标准：三个详情页均由真实持久内容驱动；改变一个类别不影响别的类别；人工改写不被自动写入接口覆盖；320 至 1440px、深浅色、文字放大、键盘和现有阅读偏好无被删除或明显回归。

### CTX4-03 — Topic 授权及边界对接

只向 Thought owner 读取稳定 ID、显示名、稳定顺序、生命周期与合格内容能力。实现 Topic access 状态，不创建第二份 Topic 正文或另外一套分类。

20／50／144 项用同一可到尾页面；开关不重排；方向键、Home／End、Space／Enter、Tab 出入与焦点保留可用。新 Topic 默认关闭；纯改名保留；新身份、拆分、合并不能自动扩大授权。

区分新 UI 的普通 allow/off 与遗留 deny/never、条目排除、Source purge。普通 off 不联动独立前三卡；强制禁止与同源限制不能被新 allow 覆盖。遗留状态无法无损映射时保留原限制并拒绝相关读取，不默默清空，也不把多 Profile 的允许范围并集当新许可。

退出标准：输入卡关闭阻断深读而保留子选择；关闭 Topic 后目录／查询／正文／续读／缓存均不提供受阻内容；无效 ID 和删除／重建身份均无旧权限复活。仅有摘录的接口缺口单列，不能按完整读取 PASS。

### CTX4-04 — 中立可信只读服务

在可信边界实现开放浅层读取、开放主题目录、主题查询、主题内查询、原文读取与续读。实际 API 名称在接口契约中确定；用户 UI 不呈现这些技术操作。

每次数据出站前校验 Global、Group、Topic、连接身份、当前授权 generation、来源／内容资格和版本。搜索索引、命中摘要、响应缓存、分页 cursor 同样受控；撤销使未完成／旧 generation 的后续响应失效。

整个 Topic 可有界地分页到真实末尾，不静默截断；按 stable Input 身份去重；事实／规则／阶段状态、用户原话／引用／AI 文本保留角色区别。无任何 Archive 搜索、Conversation 授权或任意 Input ID 越权接口。

离线／超时／授权状态未确认时拒绝读取或明确不可用，不提供未知权限的陈旧数据。Rules 或 Topic 内部文字不能触发授权变更、工具写入或越权调用。

退出标准：可信主路径的正反测试通过，包括跨连接／账户、伪造 caller、失效 cursor、并发编辑、撤销、purge 和长文到尾；对被禁止字段与正文返回零泄露。该阶段只证明内部服务，不证明真实外部 AI 能用。

### CTX4-05 — 自动维护

从用户合格 Inputs 增量整理 Info／Rules／Now；内部提取范围与处理权限单独定义，不能混同外部读取开关，也不把外部“禁止查询 Archive”解释成 PAIA 自己永远不能从长期输入提取信息。

区分本人陈述、转述、假设、引用、AI 回复和否定条件。信息不足留空；不凭新近、次数或无新消息推断身份／当前状态。自动内容可按可靠新证据更新；人工新增／改写不自动过期或覆盖。

更新针对稳定 Item 身份及去重／关联关系，维护 user-edited／removed／protected 等内部状态。测试同义改写重复、新来源重复、在途旧候选提交、人工修改之后更新和删除之后更新。不能声称仅比较字符串就能完全阻止任意语义重复。

只有已经获准的处理服务可执行真实提取。当前 BYO／直接 Provider 通路已经退役，禁止恢复它以绕过真实服务依赖；无服务时手动三卡仍可使用，自动维护显示准确的可用状态，不能常态声称已自动补充。

退出标准分开记录：结构／身份／幂等与人工保护测试；真实、获准数据上的信息忠实度评估；实际请求内容／处理范围／费用记录。合成测试不能代替真实效果；付费测试前明确使用现有额度或取得上限许可，无自动付费重试。

### CTX4-06 — 一个真实连接先跑通

优先接通一个具备真实访问条件的 AI 客户端，不在没有通路证据时认定某品牌已经支持。开工验证客户端能力、身份绑定、回调／传输可达性、设备离线语义、权限传播与必要地区条件。

复用 04 的服务和统一范围。第一次真实连接只做必要登录与一次许可；以后正常查询无需逐次审阅。单个连接暂停不等于断开；撤销停用凭证；重连重新授权，不改变 Global／Card／Topic 原设置。

## 4. 迁移与失败处理合同

- 首先清点旧数据，不将历史 Context preview、临时材料盘或旧 grant 文本自动转换成独立长期事实。
- 旧多 Profile 的规则不能未经语义确认自动加入“我的规则”；历史数据保留，可在有明确映射和安全依据后迁移，不因 UI 退役直接删除。
- 新 Item 的正文、保护标记、删除抑制和 revision 必须在同一事务／一致写入边界内，避免保存文字成功而保护状态丢失。
- 迁移必须可重复、可检测部分失败并可恢复；不跨越未解决的 B-02 来决定人工作品是否永久删除。受影响派生内容不能绕过既有禁止继续外发。
- 读取撤销以实际服务提交确认作为成功边界；失败保留已知限制、清楚呈现未确认，不静默重开。
- 结构／存储失败先保持本地数据，不启用依赖功能；模型忠实度失败不覆盖人工内容，收窄自动更新并报告；真实连接失败只阻塞真实连接，不改回 Builder。
