## Preserved invariants

The VS-01 implementation must preserve the current safety laws rather than trading them for apparent convenience:

- Source/archive material is not silently rewritten.
- Permanent deletion/tombstone constraints remain authoritative through backup/restore.
- Backup does not include provider credentials.
- Restore remains fail-closed on malformed, incomplete, unsupported or conflicting input.
- Storage failure is not reported as success.
- Provider outcome-unknown paths are not automatically retried in a way that could duplicate cost/effects.
- No business/archive data is moved into `localStorage` as a lifecycle shortcut.

## Failure map / next-round contracts

### CPV1-01.1 — Durable save acknowledgement and recovery boundary

Primary task: preserve the already-correct transactional write/operation-receipt
foundation, then close the pre-acknowledgement interruption gap. Verify
pagehide/tab close/worker termination and add only the bounded recovery-draft
mechanism real failure evidence requires. Recovery material is not Source truth.

### CPV1-01.2 — Extension/page version handshake and reconnect

Primary failure to remove: an already-open ChatGPT page can retain an invalid
pre-update content-script context after extension reload. Implement explicit
runtime/content-script version detection and a safe reconnect path, or one clear
consumer refresh action where reinjection cannot be proven safe.

### CPV1-01.3 — Consumer update flow

Primary failure to remove: the normal update path is developer-operated and
requires GitHub Desktop plus `chrome://extensions`. Preserve existing identity,
code-backup and rollback safeguards where useful, but move normal users onto a
validated product-level update path.

### CPV1-01.4 — Recovery/degraded UX

Unify capture disconnected, AI unavailable, index unavailable, save failure,
storage pressure, stale page and update failure into bounded consumer actions.
Existing local archive use should remain available when the failed subsystem does
not require blocking it.

### CPV1-01.5 — Backup protection for update/migration

Certify the actual recoverable support range and create/validate a current-version
pre-change recovery point. Do not represent the existing 64 MiB / 100,000-item,
empty-target restore boundary as large-library recovery.

### CPV1-01.6 — Real lifecycle certification

Execute the declared existing-archive/update/restart/worker/reconnect/edit
interruption/failure matrix in current browser conditions. VS-01 closes only
after applicable CI, real-browser evidence and user-level flow no longer require
developer tools.
