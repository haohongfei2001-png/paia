## Preserved invariants

The VS-01 implementation must preserve the current safety laws rather than trading them for apparent convenience:

- Source/archive material is not silently rewritten.
- Permanent deletion/tombstone constraints remain authoritative through backup/restore.
- Backup does not include provider credentials.
- Restore remains fail-closed on malformed, incomplete, unsupported or conflicting input.
- Storage failure is not reported as success.
- Provider outcome-unknown paths are not automatically retried in a way that could duplicate cost/effects.
- No business/archive data is moved into `localStorage` as a lifecycle shortcut.

## Failure map / next-round contracts

### CPV1-01.1 — Automatic update flow

Primary failure to remove: the normal update path is developer-operated and ends in manual extension reload. Preserve verified runtime-path safety and rollback behavior where still useful, but the consumer contract cannot require repository synchronization or `chrome://extensions` interaction.

### CPV1-01.2 — Backup / Restore Support

Primary task: certify and, where necessary, repair the already-real portable backup/restore substrate. Verify representative full-state round trip, deletion fences, settings, source structure, large-library bounds, interrupted/invalid restore, and ordinary-user discovery. Do not invent a second backup format without evidence that the existing one is insufficient.

### CPV1-01.3 — Save acknowledgement semantics

Primary task: establish a single truthful product contract for durable writes and visible acknowledgement across editable surfaces. Explicitly test close/reload immediately after an acknowledged save and storage-failure behavior.

### CPV1-01.4 — Restart / Relaunch State Integrity

Primary task: certify real extension worker restart, extension reload, Chrome relaunch and update/migration paths against authoritative Source, Working Input, Thought, relationships, settings and deletion state.

### CPV1-01.5 — Lifecycle UX Review and Repair

Review all successful and failed lifecycle paths as user journeys. Engineering-only recovery steps cannot be accepted as normal consumer UX.
