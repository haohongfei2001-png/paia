## User result and present limit

The extension now exposes its installed and waiting version, an explicit check for an available update, and one save/reopen/refresh path that does not force reload while the user may have dirty edits. A normal archive status read underlies any healthy archive claim. Package preflight rejects changed extension identity, nonincreasing versions, expanded permissions, host/CSP/content-script changes, a higher minimum Chrome version, and changes to core runtime/storage files. Recovery preflight permits only a previously audited known-good package reissued at a higher version with identical code apart from the manifest version. The development updater remains a fallback.

Previously, normal updating depended on GitHub Desktop, a script and `chrome://extensions`; users had no clear in-product version or waiting-update state. The new engineering path does **not** yet prove a normal signed-channel update. It cannot claim that the same installed identity and local archive survive real distribution or that a browser rollback was performed.
