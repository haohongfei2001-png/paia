# Minimal extraction for the existing Prompt owner

## Keep

Keep the existing private frame, composer-relative layout/nonce/caller owner, typed current-expression service, Family/history/search, permissions, single insertion arbiter, native host adapter, IME/draft/revision/UNKNOWN/undo guards and manual work. R1's component.js/css, demo.js/css and six card SVGs are byte-preserved here to make that visual inheritance auditable. They remain demo code, not a replacement production backend.

## Extract the geometry, not the harness

1. Draw **one** circle-to-stadium skin behind the current capsule text and fixed toggle. Ordinary height48, radius24, width48→272. Remove the old neck and duplicate circle border in recommendation state. Retain separate text and toggle hit targets; the right48px target never moves.
2. Keep the board as a336×312 rounded body. Align its right edge with the anchor and place its bottom8px above the circle top. Root-relative bottom offset is56px, not R1's34px. The full envelope is336×368. Compute available height from the actual composer/viewport, retaining existing safe-space recovery rather than shifting the anchor during mode changes.
3. Reveal the shared skin and its text mask together (120ms opening,80ms closing). Never scale/translate the anchor or foreground glyph. The board only fades; no completion timer gates a click. Preserve reduced motion and interactive semantics.
4. Put the delayed close tooltip beside the circle while the board is open, not over the last row. Retain original focus, management, error and dirty-work controls.

`geometry.js` subclasses the local R1 fixture solely to isolate visual changes. In production these formulas belong in the existing layout owner, not a second scheduler or class hierarchy copied verbatim. `demo.css`, demonstration controls/content/ranking and textarea writes must not ship into the real host.

## New trust/geometry edge to verify on integration

The empty8px gap and unpainted region below the board must not steal host clicks. A transparent pixel in a cross-origin iframe is **not** by itself click-through. Use the existing frame/host projection and approved target/shape owner to preserve interaction regions; do not add a new privileged frame, forward arbitrary events, expose expression text to the host or paint a large invisible catch-all rectangle. The offline pointer test does not establish this production boundary.

Retest affected target bounds, mode/resize acknowledgement, focus, selection, undo and private-frame Source/release parity at the current coherent batch. The unchanged functional bodies are KEEP, not a reason to restart S0–S4. Do not merge this independent design PR as installed/native fidelity acceptance. It does not change main, PR295, PR297 or the current canonical plan.
