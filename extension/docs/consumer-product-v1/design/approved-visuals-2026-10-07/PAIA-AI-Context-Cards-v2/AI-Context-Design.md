## 1. 确定的产品模型

**我的信息、我的规则、我的现在、我的输入。**

首页回答：有哪些 Context、哪些类别开放、AI 访问是否开启。点入才阅读和修改内容。外部 AI 正常使用无需用户进入 PAIA。

- 我的信息：相对长期稳定的本人事实。
- 我的规则：AI 应如何与我工作；包括偏好与长期自然语言 instructions，不另设偏好卡。
- 我的现在：阶段性状态；不是项目管理、待办或进度跟踪。
- 我的输入：Thought Topic 的访问入口与许可状态，不是 Input Archive，不复制 Topic 正文。

浅层三卡拥有独立 Context Item；第四卡只拥有访问状态。这次不是对旧纵向三段页面的调整。

## 3. 首页布局

### 3.1 固定为 2×2

第一行：我的信息 / 我的规则。第二行：我的现在 / 我的输入。四卡同宽，间距 16px，桌面最小高度 220px，内边距 24px。允许内容与文字放大撑高，不裁切文本。

页眉只有标题和 `AI 访问 · 开/关`。四卡之后只有低频入口 `已连接的 AI  2  ›`。不展示访问日志、不增加解释区或引导任务。

正常 1440×900 视口内，标题、四卡和连接入口全部可见。内容少时保留自然余白，不加入广告式说明填充画面，也不把内容拉成四个巨大纵向 section。

### 3.2 卡片内容

我的信息：基本信息 · 背景 · 经历 / 语言 · 长期习惯。  
我的规则：回答方式 · 语言 · 表达偏好 / 工作方式。  
我的现在：当前项目 · 当前目标 / 最近关注。  
我的输入：少量开放主题名 + 剩余数量，例如 PAIA · HCL · AI 产品设计 · 写作 · 学习 +8。

前三卡底部只显示实际项目数；第四卡显示开放主题数。示例数据为 8 / 7 / 4 项与 13 个开放主题，不是对真实用户的数据统计。数字是内容提示，不做大号 KPI。

首页不展示姓名、学校、地点或私人正文。主题名是用户明确要求的概览，不附加主题正文。无开放主题时显示“还没有开放的主题”。

卡片正文区域打开详情；右上胶囊只改变访问状态。二者为独立的可聚焦操作，不嵌套按钮，点击胶囊不跳转页面。

## 4. 状态胶囊

选定主文案：**AI 可读 / 仅自己**。

开启：既有浅蓝选中底、蓝色文字与实心小点。关闭：轻底、次文字与空心小点。文字和形状共同表达状态，不只依赖颜色。没有大 toggle、checkbox 或 lock 图标。

胶囊本身就是状态和操作：点击立即提交改变，不再追加保存、Done 或确认页。正式实现只有得到真实提交确认后才显示已生效；等待/失败在原位置短暂反馈，不能提前假报成功。样机用内存状态演示这个交互，不实现分布式提交。

### 4.1 全局关闭

Header 变为 `AI 访问 · 关`，出现一行例外说明：“AI 访问已暂停，开放设置已保留。”各卡底层选择不变；此前开启的卡显示弱化的 `已开放`，而不是仍显示“AI 可读”。关闭卡保持“仅自己”。

重新开启后按原有选择恢复。全局关闭不删除内容、不逐个撤销连接、不重置 Topic 状态。

### 4.2 类别关闭

关闭“我的规则”不影响其他三卡。关闭“我的输入”暂时遮住所有深入读取，但不逐个重置 Topic。

在“我的输入”详情内，上层关闭时显示“此类内容仅自己可见，主题选择已保留。”原本开放的胶囊保留实心点但变弱，仍可调整未来恢复后的选择；修改 Topic 不会自动重开类别或全局。

## 5. 二级详情与直接编辑

进入正常页面，使用 `‹ AI 上下文` 返回。保持当前一级导航选中和内容轴，不开 modal，不增加中间导航栏或第四栏。

页面组成：返回、标题及类别胶囊、一句自动维护说明、按内容自然形成的短分组、可直接编辑的 Context Item、底部添加入口。

**“PAIA 会根据你的输入自动补充，人工修改始终优先。”**是正常状态唯一的维护说明。

分组由实际内容决定，图中的“背景与经历”“语言与习惯”等是示例，不是必填表单。规则和当前状态首先是自然语言。

### 5.1 编辑操作

点击正文即可输入。非编辑时像阅读文档，不长期显示输入框或 Edit 按钮。聚焦时才出现既有焦点样式；Enter 换行，⌘/Ctrl+Enter 可立即提交。

设计样机用 650ms 停顿演示自动保存。正式实现不应每次键入弹通知。“已保存”只表示正文提交被确认；未提交的文字不提供给外部 AI。

IME 组合期间不提交、不移动输入位置、不重新挂载编辑器；compositionend 后再保存。正式接入继续复用当前编辑器的光标、选择、撤销和失败保护能力。

### 5.2 添加、删除、依据

“＋ 添加信息 / 添加规则 / 添加当前状态”直接创建一条空白编辑位置，不弹表单，不要求先有历史提取结果。

每条的 `…` 在 hover、focus-within 或触摸设备上可达，只放低频动作。删除后可撤销；删除同时形成“不再自动加入”的内部记录，不能几分钟后换个说法重新添加。

“查看依据”在该条下方按需展开，不常驻来源、时间、置信度或提供方列表。由用户独立新增的项说明由用户添加，不伪造历史来源。

### 5.3 失败与冲突

保存失败保留原处文字，显示“未保存，文字已保留。重试”。不要恢复旧正文、宣布保存或直接离开丢稿。

跨页面离开需要保护未保存内容；组合输入尚未结束时不破坏它。生产级标签页关闭恢复取决于实际 draft owner，不能因这张设计图而承诺跨重启恢复。

自动更新或并发保存不得覆盖人工正文。不能把源版本失效设计成旧 Context Package 的全页 stale/review 流程。

## 6. 我的输入：20 / 50 / 144 个主题共用同一个页面

采用紧凑、自然换行的小胶囊。每个胶囊仅含名称与状态。桌面实际可点击高度 44px，间距 12px；窄屏保持 44px，间距 10px。长名称可自然换行，不以截断隐藏唯一识别信息。

不使用搜索、筛选 tabs、全选、批量、checkbox、Done、表格、锁矩阵或选取 modal。不要在页眉加“全部 144”或“6/144”。图名和评审控件可说明测试数量，产品画面不显示这类管理统计。

20 个主题自然排列几行；50 个继续排列；144 个在同一页纵向滚动，真实到尾就结束。不另加“下一页”或未读任务，也不把更多主题强塞进首页。

不为授权页创建另一套 Topic 分类。排列沿用思想库提供的稳定顺序；开启和关闭不重排。思想库若变更顺序，接入时复用原顺序和锚点，不另设计 Thought Root。

键盘可进入胶囊区域后用方向键移动，Home/End 到头尾，Space/Enter 切换。Tab 离开该区域，不强迫经过 144 次按键。普通滚动与浏览器页面查找不需要新增产品搜索框。

### 6.1 新主题默认

**新 Topic 默认仅自己可见。**不继承“我的输入 = 开”成为自动开放。总开关是访问门，不是对以后新增内容的全库同意。

新主题随思想库的正常组织出现在本页。最多用一个随首次浏览消退的“新”字作局部提示；不推送、不显示待处理数量、不要求确认。用户不来这里操作，它就保持关闭。

同一稳定 Topic 的纯改名保留状态；新的身份、拆分或合并后的新对象不借旧状态扩大授权。保留现有明确禁止、来源失效和永久删除保护；不在本轮创造新的删除语义。

## 7. 独立 Context 数据：这次必须改正的边界

Info / Rules / Now 是独立 Context 数据，不是 Input reference 或 Thought reference。

用户修改“主要使用中文”，只改这个 Context Item。删除“正在读大学”，只删除此 Context 项并阻止自动复活。两者都不改 Source、Input Archive、Thought 正文、主题归属或历史时间。

自动维护可保留内部依据以支持核验，但依据不等于双向正文绑定，更不赋予外部 AI 遍历 Archive 的权力。

### 7.1 与 Topic 开关的关系

**普通 Topic 开关只控制深入读取，不连带切换三张独立 Context Card。**

例如关闭“工作”主题后，已独立保存在“我的信息”中的职业描述仍按“我的信息”的许可提供。需要不再提供该描述时，修改/删除该项或关闭“我的信息”；需要全部停止时使用全局开关。

上一版将每条浅层简介持续绑定 Topic 许可、关闭 Topic 就逐项连带停用浅层内容的规则，不再作为本轮主模型。否则四卡独立开关会成为表面简化、实际隐藏联动的假模型。

这不是允许系统绕过关闭范围：外部读取请求不能从关闭 Topic 临时提取新描述以补齐响应；自动提取本身有独立的处理授权与生命周期。内部 PAIA 提取与外部 AI 读取是两种行为，不能混为一项许可。

来源永久删除、既有强制禁止以及用户改写衍生内容的清理，仍遵守当前数据安全契约；独立 Context 不是免除永久删除责任的理由。本轮不擅自解决旧 B-02 衍生清理权限问题。

### 7.2 自动维护原则

自动生成只整理有足够支持的用户表达；不能把引用、假设、AI 回复或他人说法变成本人事实。没有依据就留空，不制造需要用户日常审批的队列。

人工新增和人工改写优先。后续提取不能覆盖、删除或通过相近措辞再建一条来绕过保护。只有明确的人类动作解除保护，不能因“更新了来源”自动失效。

“我的现在”可随明确的新阶段更新自动项；不能把旧任务完成或长期无变化自动解释成当前事实。人工保护项不自动过期。过时而无法确定的自动项可停止对外提供并保留内部历史，不创造待办流程。

自动维护不是这次新 UI 授予的外发许可。它必须使用已经获准的 PAIA 处理能力；没有处理权限时不偷偷调用外部模型，用户依然可以手动写 Context。

## 8. 访问关系

概念公式，仅写入规范，不出现在用户页面：

```
浅层读取 = 全局开 ∧ 连接有效且允许读取 ∧ 对应 Card 开 ∧ 项目当前有效

深入读取 = 全局开 ∧ 连接有效且允许读取 ∧ 我的输入开 ∧ Topic 开 ∧ 内容合格
```

只有“我的输入”多一层 Topic 选择。所有 AI 共享同一份 PAIA 级类别与 Topic 范围，不做 AI × Topic 矩阵。

新用户：全局访问关、四卡关、无连接、新 Topic 关。已有本地提取不自动变成外部授权。用户可先打开想提供的类别，再连接；也可先建立连接，保持访问关闭。没有任何可读内容时如实显示，不虚构“已认识你”。

打开含内容的 Card 是一次类别级明确许可；后续同类合格项目按该许可提供，不逐项 Review。已有/新增内容的持续许可在首次开启的轻量帮助中讲明，不长期占据首页。

“我的规则”中的自然语言不能修改权限、扩展 scope 或执行删除。被读取的内容是数据，不是授权服务的命令。只读始终不包含写入。

## 9. 连接降级为正常二级页

首页一个文字入口。连接页只呈现连接名称、是否连接、是否允许读取、断开或重连；没有 OAuth scope、Purpose、Grant、有效期下拉或访问日志大区。

连接与暂停区分：暂停保留连接，断开撤销凭证，重连重新授权。全局暂停不会断开所有 AI。

默认连接许可引用共享的 PAIA 级范围，不为一个 AI 建立新 Profile。连接流程只有选择真实可用连接与一次许可；第三方必要登录仍需真实完成，不能伪装成两步就必然成功。

**连接不暗中重开全局访问。**全局关闭时，允许连接后继续暂停，只有用户明确改变全局状态才恢复。

图中的 ChatGPT / Claude 是示例连接名称，不是当前仓库支持这些连接的证明。正式产品只列实际接入成功的服务。

撤销阻止后续读取与尚未出站的可取消返回；已经到达外部 AI 的副本不能召回。离线或服务未确认时，不显示全网已停止的假成功。底层审计可保留，不把审计工作流搬进首页。

## 10. 外部 AI 的读取方式

正常调用：开放的浅层 Context → 需要更多信息时查看开放 Topic → 搜索相关 Topic → 读取必要的完整用户 Inputs → 回答。

“我的信息”“我的规则”“我的现在”的语义标签对 AI 可见：事实、工作指示和阶段状态不应混为一个无类型的字符串。

关闭的类别不发送；没有开放 Topic 时不回退到 Archive。读取接口不暴露 Conversation/Project/手动 Archive Input 选择。

权限覆盖整个开放 Topic 中合格的用户 Inputs；实际一次任务只读需要的部分。响应可以分页与续读，但必须可读到真实末尾，不能把截断片段称为完整 Topic。搜索摘要是定位入口，不替代原文能力。

同源 Input 去重、检索预算、权限版本与失效校验留在后台。没有足够材料时回答不足，不要求用户回 PAIA 打包材料。

Thought Library 的接口应提供 Topic identity、title、可检索内容和完整合格 Input。如果当前仅有摘录，记为完整读取接口缺口；不默默借 Archive 打开额外权限。本轮不重设计 Thought Library 来填这个缺口。

窄屏四卡改为单列并自然滚动，不要求把全部内容硬塞进手机首屏。桌面一屏目标不被错误推广为任何视口都不允许滚动。正常字体下页面仍需支持文字放大和更长真实内容。

## 12. 极简产品数据模型

```
AI Context
  Global Access: on / off

  Context Group
    Info / Rules / Now / Inputs
    access: on / off

  Context Item                 # 只属于 Info / Rules / Now
    id, group, body
    auto-generated / user-created
    user override protected
    active / removed
    optional internal evidence

  Input Access                # 只属于 Inputs
    Topic ID
    allowed / blocked
    不复制 Topic 正文

  Connection
    connected AI identity
    connected / revoked
    read enabled / paused
```

上下文项目拥有自己的可编辑正文。Topic Access 只引用稳定身份。版本、原子提交、备份、凭证、存储位置由之后实现复用现有可靠 owner；这个产品实体清单不是数据库迁移批准。

## 13. Supersession：停止继续开发什么

### 13.1 上一版设计整体退出

上一版 `AI-Context-Prototype.html` / `AI-Context-Redesign.md` 中独立的设计语言、纵向三大说明区、搜索/过滤/批量的 Topic 管理面板、权限 modal、大连接区域不再沿用。

本轮也覆盖上一版“浅层 Context 只是持续绑定 Topic 的引用投影”的相关语义。Info/Rules/Now 改为独立 Context Item；不可只换卡片外壳、保持旧内部模型。

### 13.2 当前旧流程退出正常 AI Context

| 停止继续开发的产品/UI | 新归宿 |
|---|---|
| Context Task / Purpose | 删除任务入口；任务由外部 AI 当前对话决定。 |
| material selection / manual Input selection / Conversation selection | 从 AI Context 正常路径删除；不对外开放 Archive。 |
| Context Builder / Build / Supplements | 按需查询与读取，内部检索不变成用户工序。 |
| Review / Edit-Redact / Ready | 删除输出审批工作台；前三卡直接编辑独立 Context，不是改某次输出。 |
| Context Package / Copy-Export 主路径 | 不再是使用上下文的前置步骤；其他产品空间已有人工导出能力不因此删除。 |
| budget / coverage UI | 后台预算与完整性说明；不占首页或正常详情。 |
| stale Context UI | 退回引用与读取安全；不用全页重审 package。 |
| Passport grant / Consumer / Purpose | 真实连接许可代替工程表单。 |
| once / 7d / 30d / Profile 授权 UI | 共享类别/Topic 范围 + 连接 + 全局暂停。 |
| D6.2 / D7 的 AI Context journey 与对应阶段图 | 由本轮四卡、详情、授权与连接状态取代。 |

当前可见证据路径：`ui/archive.html` 的 memory 页面保留准备上下文、Profile、搜索和批量授权；`ui/desktop-appearance-preview.css` 将 Context 指向现有 journey presentation。旧流程完整符号还包括 `ui/memory.js`、`ui/context-workspace.js`、`ui/material-tray.js`、`ui/passport-controls.js`。退役应按真实调用和数据依赖执行，不因视觉设计就立刻删存储。

需要最终对齐的权威文档：`AI_CONTEXT.md`、consumer-product-v1 的 `PRODUCT_INTENT_CONTRACT.md` 与 `UX_CONTRACT.md`、desktop-vnext 的 F-07、D6/D7 Context 状态和验收映射。当前未写回这些文档。

### 13.3 保留底层，不保留复杂工作流

保留 authorization enforcement、revocation、read/write separation、access validation、Source eligibility、audit、retrieval、stale reference protection、local/cloud safety boundaries。

旧 Grant 不自动成为长期连接；旧 Profile 不自动合并成更大范围；备份恢复不恢复有效凭证。迁移不能丢弃已有用户作品和明确禁止记录。当前 D6.2 的 shell、品牌、通用组件和其他产品空间不随 Context 结构退役。

## 14. 验证与交付边界

最终样机检查 78/78，通过项包括：完整四卡、首页不含私人正文、卡片点击与访问切换分离、全局/类别关闭保留下层选择、Topic 切换不重排、144 项键盘末尾可达、浅层数据独立、添加、人工编辑标记、删除抑制与撤销、失败保留、显式重试、模拟组合输入期间不提交、320/390/768/1024/1280/1440px 无横向溢出、较大阅读文字、无外部请求。

首轮有一项组合输入事件检查失败；修正为标准事件监听后重跑通过。记录保留在 Check-History.md，不把首轮失败改写成一次通过。

这些是**设计样机**的检查，不是生产安全证明、真实连接验证、物理 IME、屏幕阅读器、触屏可用性、120Hz 性能或同步一致性认证。原型使用当前打开页面的内存状态，刷新会重置。保存反馈演示局部交互，不把设计图当成正式持久化能力。

正式接入的验收必须在实际扩展里重复：真实数据编辑与撤销、独立项迁移、处理授权、外部只读访问、准确关闭反馈、跨页失效、完整 Topic 读取，以及与 shell 同视口的视觉对照。

本轮完成产品、交互、高保真状态与设计样机；没有修改仓库、创建 PR、连接外部 AI，或更改真实授权。
