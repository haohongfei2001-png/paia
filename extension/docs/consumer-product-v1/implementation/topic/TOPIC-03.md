## Trusted input and decision boundary

`TopicFormationService` has no installed production instance. It requires both a
constructor-only current processing resolver and a constructor-only trusted
semantic assessment mechanism with a version, plus explicit versioned policy
parameters. Capture permission and Context read grants cannot supply either.
Request data may select bounded Input scope, an operation ID and optional
Input-backed Entry/candidate references; it cannot supply an authorization flag,
semantic confidence, permission update, arbitrary Source lookup or prepared plan.

Preparation obtains complete signed Topic02 identity/constraint coverage,
including active, dormant, prior-name, redirect and removed identities. Every
canonical identity requires an explicit same/distinct/internal-aspect/ambiguous
comparison. A missing comparison is not proof of absence. Exact target
processing checks cover raw and canonical IDs in bounded batches. Unavailable
coverage and unsafe derived metadata fail closed before assessment.

The assessment receives immutable selected Input fields, current authorized
Entry descriptors, identity/Section descriptors and constraints. Source-derived
Section labels use the existing safe-organization owner plus current backing
Input/filter checks. Protected human titles survive. A refreshed B-backed Entry
may be processed under B without releasing excluded historical A Input/Source
identifiers; canonical append-only history remains in the private CAS snapshot.

Claims have finite reason codes and exact eligible Input-span citations.
Substantive content is required before new Thought content: an empty/incidental
claim combined with Entry proposals is inconsistent and rejected. Meaningful
content with uncertain identity can still be stored as exact unassigned Entries.
Unknown output fields and attempted authority fields refuse.

These checks prove reference/schema/commit mechanics, not the truth of a
semantic judgment. A future real mechanism requires separate service admission,
current processing/budget authority and actual semantic/downstream evaluation;
a provider's self-reported booleans or confidence must not be treated as that
trusted assessment. This implementation does not choose such an adapter.

## Evidence independence and six-part policy

The policy separates the explicit-object path from recurrent subjects. A first
sufficient explicit continuing object can qualify immediately. A recurrent
subject requires repeated independent contributions; its configurable count
cannot be below two. The larger example counts and context diversity are
versioned strategy parameters, not immutable three/two product constants.
Section strategy parameters remain separate: richer evidence for a stable
internal aspect is not equated with subject recurrence across Sources.

Actual Source/Input owners provide lineage. Stable sourceKey, identical canonical
Source content and known revision links are deduplicated. Nonadjacent revisions
A and C remain one contribution even when intermediate B is outside scope.
Official reimports, repeated spans, edited summaries and generated Entry count do
not manufacture recurrence. A merged A+B Input does not count as a third Source.
Exact attributable A/B spans can count their two underlying contributions;
ambiguous edited merged spans contribute zero rather than every backing Source.
No Source is invented for an independent user-authored Thought.

Context diversity uses known Source conversations or reliable Source sent dates,
not capture/import timestamps. Unknown/conflicting dates remain unknown. Copied
content across contexts cannot manufacture multiple contributions or diversity.
The work is bounded to the existing 100-Input evidence contract, 100 Entries,
1,000 Source records and 100 citations per claim; existing request/content byte
budgets also apply. These work bounds are not semantic thresholds.

A new Topic requires six internally explainable checks: independent boundary,
direct return value, no existing identity, not an ordinary internal aspect,
qualified eligible provenance and human-intent compatibility. The first five
are evaluated before preparation; current source, identity and per-edge human
constraints are decisive in the final transaction. Ambiguity is not resolved by
picking the first or closest name. Equal names can represent distinct identities.
Removed names/aliases and same-object removal remain suppression fences even
under a newly proposed label. No established identities are automatically merged.

Insufficient substantive evidence can accumulate as opaque, hidden Topic02 work;
unknown identity can remain unassigned. No catch-all Topic, candidate inbox,
visible candidate count, seeded catalog or 144-Topic directory is created.
Candidate expiration and existing cleanup ownership remain unchanged.

## Sections, Entries and Placement

Admission allocates stable Topic and default Section IDs only in the guarded
creation transaction. Naming follows admission. User names, including broad,
unusual or equal names, are never renamed by this service.

The default Section remains complete and stable. A generated named Section needs
supported recurring-internal-aspect and return-value claims, plus explicit
comparisons against existing named Sections. Transient or unjustified labels
stay in the default Section; they are not renamed to another vague heading.
Existing manual Section names, order and empty Sections survive. No empty
automatic Section is created when every proposed Entry already has a Placement.
AI reading headings, Section promotion and established-Topic structural changes
are outside this slice; promotion remains TOPIC-04 and requires confirmation.

Existing LibraryCommit exact-excerpt creation/provenance and body binding are
reused. One idea can have several metadata-only Placements without copying its
Entry body. Separate spans representing different ideas can create distinct
Entries with shared Input provenance. Extra memberships need independent
reading/thinking/decision/reuse value with a citation belonging to that Entry's
own evidence; lexical/category-only extras are dropped.

An existing Entry's declared span must belong to actual direct dependency fields
and current provenance. Known exact-excerpt bounds cannot be replaced by a
nearby sentence about another object, nor by equal text from an unrelated
Source. Legitimate derived Thoughts need not equal Source text. Existing
human Placement/Section/order is a no-op, never permission to move it. New edges
still honor exclusions and fixed sets. Human rename does not freeze unrelated
lawful new membership. Same-ID dormancy reactivation respects restored lifecycle
protection and does not clone or change access.

## Commit, cancellation, restart and negative intent

Prepared handles are process-private WeakMap capabilities, bound to their
service/store instance; copies, arbitrary objects and cross-instance/store use
refuse. They are not serializable authority. Restart requires a fresh current
assessment or an already committed receipt, never resuming stale inference.

The final existing transaction rechecks complete identity/constraint generation,
Input/Entry/provenance snapshots, current permission epochs and exact Topic
scope, key/restore epoch, source eligibility, human edge/set intent, removal
suppression and layout/revision state. Cryptographic work remains outside the
IndexedDB write transaction. A concurrent first-admission result becomes stale
rather than creating another identity. Newly allocated target scope is also
reauthorized; no grant is written.

Operation receipts bind the exact request, assessment version and policy.
Successful retries return the receipt without reassessment or another write.
Failed transaction retries can reuse the same still-current preparation.
Cancellation before/during commit refuses atomically. No automatic paid retry,
lease runner or persistent inference dispatch is added.

Hidden candidate creation and unassigned Entry creation share one transaction.
Admission consumes a selected candidate only when its current entire evidence
bundle and opaque boundary are accounted for. Partial evidence leaves pending
work intact; unrelated candidates survive. Candidate revision, key/restore,
source/permission and boundary changes refuse. Failed receipt/Entry writes roll
back Topic, Section, Entry, Placement, candidate record/consumption and journals
together. Body-free receipts contain no copied evidence text or secret.
