## Implemented behavior

A configured original maintenance service can set `service.topic.reconcileAuthoredEntries: true`. A source-free Entry created by the original human owner, with its complete current authored-field journal and exactly one current manual Topic membership, can now receive an independent Topic semantic assessment. The current Topic must itself have a user-created, source-free identity. The request carries typed `human_entry_same_topic` evidence with the exact selected Entry fields and current Topic name. It never creates a synthetic Input or Source.

The bounded response must establish the same existing identity and cite the complete selected authored fields. Cleared fields remain explicit. The original TopicFormationService publishes the body-free reconciliation receipt; the original Maintenance transaction commits its exact Topic ACK. A sibling Context facet still uses its separate original owner and grant. One actual provider response serves both facets. No human Entry body, Topic name, membership, Section, dependency or provenance is rewritten.

The original classifier, independent selected-field qualification, explicit Topic-name field grant, independent Topic-processing issuer, original final read plan, publication capability and exact ACK are retained. The new owner retains exact metadata/member facts and its exact operation receipt through the terminal fence. Genuine Topic authority uses its original closed processing final fence; legacy direct owner callers retain their explicit legacy mode, and modes cannot be mixed during preparation/commit. No legacy DTO is represented as strict authority.

The baseline Input formation method still requires genuine, nonempty Input evidence. New typed fields occur only in the new transient provider contract. The existing ordinary response schema/instruction bytes, Input citations, Entry/Input persistence, Backup/Sync schema and human journal format are unchanged. Receipt uses the existing `thought-library`, schema 1 `saveReceipt` format and body-free result; `personal-topic-authored-reconciliation` is only its request-digest discriminator. Backup receipt projection already carries generic `digest/result`; no migration or remote Sync write was introduced.
