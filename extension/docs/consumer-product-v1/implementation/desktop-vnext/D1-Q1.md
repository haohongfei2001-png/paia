A05 Save & Recovery / A-05: a successful canonical transaction followed by response loss is reconciled through that operation's actual IndexedDB receipt. A04 direct-edit and S02 recovery are affected regression surfaces, with A-04/A-09 recovery, IME and conflict regressions still required. This batch implements Q1 for Working Input only; it does not complete D1, Q2–Q4, shared-shell migration, D2, D3 or D4.

Classification: I (edit/autosave/unknown coordination, readable recheck action); D (bounded operation-outcome interface and namespaced durable receipt metadata). P is limited to composing the existing save feedback/retry text, with no new visual design. Reuses DocumentEditor, RevisionSession operation identity, AutosaveSession, CAS revisions, canonical IndexedDB transaction, operationReceipts, RecoveryDraftSession, restore epoch, purge floors, editor composition guards and existing conflict UX.

`PAIA_ARCHIVE_OPERATION_OUTCOME` accepts only `{type,query}`. Query v1 binds `namespace=working-input`, document owner, operation ID, the existing SHA-256 digest of the exact edit request, and the existing recovery restore epoch. Extension-page and consent admission are unchanged. Read is serialized after canonical writes, uses fresh durable receipts, returns `{state:committed,result:{ok:true}}`, `not_committed`, or `unknown`, without body/receipt enumeration. Unknown/mismatched/legacy receipt, expired negative knowledge, worker restart or epoch mismatch cannot prove non-commit. Known negative knowledge is bounded to 128 body-free attempts in the current worker lifetime; it never grants durable success. The canonical transaction completion hook propagates through SmartFilterStore so a post-commit publish failure cannot manufacture negative knowledge.

The editor retains its already constructed outbound edit while acknowledgement is unresolved. New typing remains the existing local draft and recovery path; it cannot replace that operation ID/digest or auto-start a second operation. Explicit recheck reads the same operation; only known non-commit allows retry of the identical request. A committed acknowledgement updates the acknowledged baseline, preserving newer typing for a subsequent CAS operation. Pending edit members remain pinned during editor compaction. Recovery replay keeps its existing idempotent original operation and uses the same receipt readback on response loss. No new body store, canonical entity, permission, provider, connector or cloud authority is introduced.

New Working Input receipts add only already-portable `namespace/schemaVersion/ownerId/createdAt` fields to the existing receipt store; digest, operation ID, `{ok:true}` result and old replay semantics remain unchanged. No schema bump, destructive data migration or legacy receipt rewrite. Legacy receipt reads conservatively return unknown. Rollback UI/service use preserves receipts/revisions/tombstones/recovery protections; no database rollback or reopening of an owner-gated action.
