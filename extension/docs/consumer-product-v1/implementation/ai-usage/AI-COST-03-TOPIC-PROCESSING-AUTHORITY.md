# Independent Topic identity processing authority

## Source-only capability and current boundary

`TopicProcessingAuthority` consumes an independently configured original identity-processing issuer. It does not derive identity permission from Maintenance field qualification, capture, external Context access, local subscription state, or model response. The default issuer is absent and fails closed. A constructor callback and this local mechanism alone are not a deployed production permission service or paid Section Promotion bridge.

The issuer must resolve the exact `personal-topic-identity` request and return its original receipt: version, exact store and frozen caller, complete scope, epoch, processing decision, expiry and revocation signal. Scope binds the source operation metadata, restore epoch and exact ordered Input/Topic IDs, with the existing20 Input/8 Topic ceilings. The only local storage acquisition here is the original restore metadata row before and after issuance, charged to the same original branded request ledger. There is no new field grant, label/body retrieval or expanded Context/Filter evidence.

Each successful authorization mints an opaque use capability for the exact original live Repository transaction. A still-valid issuer lease may authorize a later transaction, but that transaction gets a new use capability. A previous readonly capability cannot authorize a new write, and copied/fake/foreign/completed/released capabilities fail. Same-epoch signal replacement or deadline extension is rejected. A narrowed deadline applies to all outstanding uses of that lease.

The source issuer receives its **original raw receipt object** for its synchronous currentness check, so a real WeakMap/identity-based issuer remains usable. The authority separately freezes validated scalar/scope fields and compares the raw object's own data fields on every check. Changed scope, epoch, expiry or accessors permanently invalidate that use, even if later restored. Exactly true is required; exceptions, promises and truthy objects fail. Clock rollback permanently refuses this authority instance; a monotonic first-deadline bound prevents a stalled wall clock extending a lease. Expired/revoked/closed capabilities are not refreshed by a read.

`readTopicProcessingAuthority(cap, store, transaction, request)` synchronously returns only `{epoch, scope}` after these checks. It cannot synchronously re-read IndexedDB restore state. The original owner's closed final read plan must compare `scope.restoreEpoch`, in addition to its original selected facts, after Repository finalizers. The two dedicated source tests retain both issuer-currentness and restore-drift rollback controls. Guard integration and production proposal lifecycle remain a separate subsequent slice; no caller-supplied `() => true` substitutes for this capability.
