## Owner boundaries

The original Filter writer and hidden reader remain the only decision owners. Preparation returns a resource lease, never an eligibility result. It cannot mint a decision, refresh historical proof/sequence/authority, modify Keep, authorize a new body scope, or turn a copied metadata object into a capability.

`filter-visibility-consumer-scope.js` accepts original private Context preflight or Thought page admissions only. It is one-use, tied to the same store/repository/database and original work ledger. The metadata transaction compares the captured root authority before and after exact `filterInputs` lookups. It collects the complete union of at most 200 Inputs and never takes a first-200 subset. The original Source-to-Input index must also be complete within its existing per-Source bound. Unsupported closure fails open without claiming complete qualification.

`SmartFilterStore.prepareAIFilterVisibilityScope` performs only metadata discovery inside its transaction, then invokes the existing readonly history owner outside that transaction. The caller repeats its original read authority and selection checks. Every returned pin remains owned by that original read and is released in `finally` after its last publication fence or failure. The original shared hub limits remain 8 pending qualifications, 8 pages, 200 pinned operations, and 48 MiB cache; these are shared-source-hub bounds, not a claim about arbitrary independently constructed hubs.

## Context

`captureContextEvidence` composes the original preflight results before the ordinary same-authority scope/lineage read. Original Context metadata discovery and subsequent reads spend the same work ledger. The preflight itself can validate authored canonical text under the existing qualification; the whole preflight is not described as zero-text metadata. Only the new private hint is body-free.

Shallow `ContextReadService` first runs its original caller, connection, cursor, Cards and external-read admission. Its private synchronous currentness veto is carried through the original read ledger and rechecked after awaits before subsequent text getters. Throwing, asynchronous or non-true currentness refuses. Late connection/generation/global-access/restore changes cannot be answered from the earlier preparation. Original result-publication fences remain separate.

Deep `topics`, `searchTopic` and `readTopic` preparation is still open. It needs an original Topic-only preflight capability after the existing exact selected-Topic policy admission. No raw Topic/Input DTO fallback is installed.

## Local Thought and Section readers

The original Thought entry page selects its exact Placement page and current Topic/Section structural metadata before preparation. Names and text are not matching keys. Original cursor identity, root authority, layout, Entry and Placement revisions are compared again afterward. Local canonical Entry work remains readable according to its original owner; the stricter Filter-dependent generated-label and Input projections do not delete human work.

Original Section order, query and expression routes issue a private token for their actual selected page. The query route first uses the existing local lexical owner, including its permitted canonical reads; this stage is not called zero-text. Preparation does not rerun the query or substitute newly discovered refs. The original refs, order, consumed cursor, reading generation and selected Section facts form one baseline. Expression indexing/empty pages prepare only the organization labels they actually return, without scanning all Topic prose. The same original page is then requalified and all pins are released after its original final fence.

The original 10,000-unit Thought read budget is shared by the new metadata preparation and that page's original bounded adapters. Wrapper origin is proven by private owner records and the actual live Repository scope, not prototype resemblance or a public transaction field. Copied, foreign, changed-method and completed wrappers are refused.

Remaining local entry points, including detached original previews, search qualification and metadata-only overviews, have not been claimed covered by the four entry/Section routes. Their original fail-open behavior remains until individually integrated and tested.
