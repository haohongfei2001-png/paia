## One paid child, two distinct permissions

Metadata selection remains bounded to eight complete identity Topics, twenty selected Inputs, sixteen Entries and one complete selected Section. Local qualification separately grants every required Input/Source, Entry/history and selected structural field. Selected parent summary is local-only preserving-CAS material.

A separate source-owned remote payload scope names the exact original job/child/proposal, root, Input fields/revisions, Entry body/revision, Section title/revision and complete identity Topic name/revision set. Its metadata includes the original membership, dependency and restriction closure. Constructing it reads no body or label. It retains the original 32 KiB receipt-scope ceiling; an oversized scope refuses rather than silently truncating. Parent summary, history and Source original text are absent from its sent-field grant and the provider DTO.

The original task retains the exact private plan and remote permission identities. Source registration must reject a local-only task. Permission checking uses the original raw issuer receipt; the client independently verifies it against its own issuer. A copied task, preview, receipt DTO or arbitrary callback cannot choose the extended provider contract. The real paid response and Foundation terminal handoff remain separate capabilities owned by the original Maintenance source/session. Each committed facet requires its exact joined ACK and publication. A real complete all-DEFER terminal may carry an empty publication suffix; it cannot invent an ACK. Missing the applicable original capability rejects. The task's original full-request digest hash is charged to its existing qualification ledger.

Before tokenization and physical dispatch, an asynchronous original-assessment check revalidates the same captured Entry fields, Section, selected summary, Source/Working and complete identity names. It neither reads a replacement page nor refreshes the sent DTO or baseline. A synchronous private task reader alone is insufficient for this content fence. Remote and parent revocation signals and the earliest original deadline eagerly clear waiting task state, alongside the original field grant. A detached offered proposal takes over its original remaining expiry timer; explicit confirmation then owns that same deadline. Empty task owners release their source-session slot, while an active confirmation/recovery remains counted. Fixed source routes retain the original private owner and original methods, so overriding a public method cannot manufacture an offer or confirmation. After all issuer callbacks, the original task performs a callback-free final sweep over the local fields, remote/parent receipts, original identity-use lease facts and shared ledger. A read-only lease-facts capability may survive the completed original read only to deny a stale send; it cannot authorize any body read, new transaction or replacement identity use. Physical dispatch consumes the same fixed task facts.

## Detached lifecycle

Only the original accepted assessment can detach. The bounded in-memory ticket keeps the sensitive derived name/preview/assessment and original immutable digests, identity, selection and deadline. It does not keep the old body page or renew its processing receipts. The original wall and monotonic deadlines cannot be refreshed by a new grant; clock rollback invalidates the ticket. A proposal is not a confirmed work item.

A source offer additionally needs the exact real paid-result identity and the original terminal handoff. Root advancement accepts only the original authenticated publication suffix. During finish, the original owner validates that chain and freezes only its exact final root projection. The offer drops the raw publication tokens, paid-result capability, old reader and material references; Context publication tokens can indirectly retain body facts and are not described as body-free. Full selected metadata and identity facts must still match. Changed semantic scope, unsupported Filter root changes, new identities or unrelated writes retire the proposal rather than refresh its assessment. No live reprepare is used as evidence of a prior successful write.

Explicit confirmation obtains fresh local fields and an independently granted identity capability. Both are bounded by the original proposal deadline. They reread the old immutable selection and compare the original view/snapshot/plan/name digests, without a new assessor or model. Cancellation ends the caller wait and releases the Store queue; late grants cannot recreate an expired or cancelled ticket. A raw issuer Promise that has not actually settled keeps its original acquisition slot. The confirmation owner admits at most eight such pending acquisitions, even after the corresponding caller has cancelled; only actual settlement releases a slot. No claim is made that cancelling a caller aborts an arbitrary external issuer Promise.

The original confirm and stage writers freeze their work intentions before put and register the same closed Repository terminal mechanism as activation. The terminal compares captured Source/Working/Entry/Section/identity/restriction facts, exact work rows and the expected root after all original finalizers. Every actual read and hash uses one cumulative original ledger. The final callback-free field, identity and budget facts sweep follows all issuer callbacks. Legacy direct callers keep their original limitations.

## Confirmed work and unknown outcomes

After a successful original confirmation, recovery uses only its existing signed work ID and original 24-hour lifetime. A bounded own-data envelope read verifies the original secret signature outside the IDB transaction, then rereads the same root, restore, authority and work before producing a private metadata capability. Unverified fields never become scope. Accessors refuse without execution; no Input, Entry or Topic text is acquired during this metadata step.

A recovery attempt then obtains fresh independent field and identity permission and revalidates the original signed snapshot. A new identity-processing epoch is allowed only in this explicit freshly qualified recovery path; it does not replace old proposal digests or extend the work deadline. Confirm rollback creates no work; a durable confirmation whose return is lost resumes that same work. Activation return loss resolves the actual existing receipt without another assessment or mutation. Receipt lookup has its own current field and identity grant and cannot mint a proposal or signed work.

## Existing Archive consumer

The existing Section action first checks for a unique already-produced offer. With no offer it retains the manual path. AI proposals use the same full Entry list and explicit confirmation, with fixed translated origin/reason text and the exact original proposed name. Merely opening the action does not generate or send a model request.

If the optional AI source is unavailable, only pure offer lookup returns no offer and retires unconfirmed stale AI preview tokens. The original explicit manual route remains independently authenticated. AI confirm, result and resume never fall back to a different operation.

An uncertain AI confirmation keeps only a bounded tab-local operation/Topic/Section checkpoint, never name, preview, body or permission. Reload recovery happens only through the same explicit Section action. The original eight-attempt bound also applies before checkpoint hydration. A real ninth-attempt RED is preserved and repaired. Original source/document checks, draft/IME protection, full move preview and history-based undo remain.
