Candidate base: `150f981a`; approved design checkpoint: `011ae7b8`. This is the explicitly approved first local lifecycle, **not** a live Qwen route, full incremental manifest, 200+5 refresh, financial service or complete AI-COST-05.

`LocalOrganizeSession` is an internal explicitly configured owner. It prepares actual Topic/Entry/Input evidence, binds the actual style/restore/policy/Section snapshot and trusted profile, uses the existing AIUsageFoundation job and metadata-only dispatch, assembles source text locally, validates a local/fixture result, and writes the original candidate and exact coverage in the Foundation's existing transaction. Existing adoption/history/status consume that candidate. No Foundation changes, worker wiring, new schema, second store/ledger, Settings entry or provider/network activation.

The session has bounded private handles/results (eight job slots; dispose releases them). Untrusted callers cannot recreate a capability by copying its visible job ID. Original saved schema 1 and candidate schema 2 stay unchanged, including the 100-ref limit and all eight-field limits. More than one requested child explicitly defers; canonical up-to-four-child support remains unfinished. A scope that cannot fit existing maxInputs/content/request/output bounds refuses rather than truncating. No missing legacy manifest is fabricated, and no saved row is upgraded to a qualified Qwen cache.

Actual semantic descriptors come from existing Input and human Entry owners. AI-derived Entry rows without their own human journal bind their actual Input dependencies; no new descriptor is minted to pass Foundation qualification. The private scope still binds every current Entry/version and real source qualification. Job semantic identity additionally binds current evidence version and internal profile, avoiding Input-only identity reuse after relevant structural changes. Current saved candidate and human presentation are rechecked before commit.

Response source spans are transient, exact field/list slot + Entry/revision + UTF-16 offsets. Boundaries must coincide with complete graphemes, and the slice must equal the returned text. Original style requires a span for every nonempty field/list item; balanced/concise may use evidence-backed generated text and are **not** certified semantically faithful by these local checks. No multi-span stitching contract or new prose renderer is claimed. Provider receives a clone; mutating its request cannot rewrite the private validation source. Request/output byte bounds remain existing policy limits.

Source/Working Input/Entry/Topic/Section canonical data is not mutated by generation/adoption. A candidate is not automatic adoption. Existing explicit adoption and protected-field/history rules remain in force. An invalid local result is conservatively recorded through the existing unknown-outcome attempt path; it never gains an ACK or automatic retry. A post-response transaction failure can retry the same private validated result without a new attempt. Disposal/restart cannot recreate lost private response or remint an unknown attempt.
