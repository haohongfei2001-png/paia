## Deliberately bounded relevance

The runnable conservative selector uses actual active Rules as behavioral Context. Automatic Info/Now additionally require an exact original Source `recordIndex.chatKey` matching the current canonical conversation. Selection uses stable IDs and original metadata, never matching names, arbitrary callback IDs or ungranted Item bodies/sections/time strings. Removed/invalidated Items are not selected. Protected and human-edited work is preserved. Automatic candidates must still pass their full original lineage; a missing, removed, purged, stale or otherwise unsupported lineage causes honest no-send.

Manual Info/Now and relevant automatic Info/Now from other conversations are not yet generally retrieved. This is an explicit remaining product gap, not a permanent conversation-only rule. A future bounded extension can use stable current-interaction Topic-ID metadata seeds for cross-conversation automatic Items; manual free-form sections require a separately authorized label-only stage before any local label match, followed by a separate exact Item-body/qualification grant. No section text may be treated as free metadata. That extension, relevance-quality evaluation and possible incomplete-coverage presentation are not implemented here.

## Opaque API and independent field grant

`assist-context-selector.js` exposes `selectAssistContext`, `assistContextScope`, `captureAssistContext`, `assertAssistContext`, `assistContextCurrent`, `assistContextValue` and `releaseAssistContext`. Handles and original snapshots live only in a WeakMap. Selection runs in the original bounded metadata transaction. It declares Item identity/revision/card/lifecycle/protection and field names, original Input/Entry/structural evidence descriptors and required Source IDs. It neither copies nor hashes the Context row's unselected text.

The exact source-owned request has purpose `assist-context-processing`, version 1, the original private Assist binding, `contextItems`, `inputs`, `entries`, `structuralTopics`, `structuralSections`, and `sourceRecordIds`. The independent resolver must return a same-store exact-scope receipt with version, opaque epoch, `processing: true`, finite future `expiresAt` and real revocation signal. Its synchronous `isCurrent` must return exactly true. The same epoch/expiry/signal/scope must remain current; repeated checks cannot refresh a grant or select a replacement baseline. External Card/Topic switches and latest-reply consent do not grant these fields.

The original qualification owners necessarily inspect Input body/note and Entry body/title/note, even when an old automatic Item's semantic provenance names only Input body. These local eligibility fields are now explicitly requested and individually granted before those owners run. Refusing any required field refuses the complete scope before text acquisition. These fields are not appended to the remote Assist payload and do not change the Item's historical semantic provenance. No sibling Input or independent derived Entry is added to make a whole-Topic reader succeed. A metadata-only complete graph guard rejects such unsupported closures before material acquisition. Closed Entry type/formation metadata and original memberships/dependencies/provenance are also frozen for final eligibility.

The provider receives only complete semantic Item strings containing card, body, section and actual stored temporal projection. Old associations, Source bodies/IDs, provenance, processing epoch, qualification fields and private snapshots remain local. Now without an explicit deadline remains unknown. An expired unprotected automatic Now is withheld; a protected human-maintained item remains explicit unknown-currentness rather than being silently deleted. Crossing a real explicit deadline invalidates a retained suggestion.

## Original owners, bounds and final fences

The helper reuses `context-topic-access`, `context-topic-scope`, `context-item-lineage`, authored/bound Entry readers, structural-context mapping, original Input projection and temporal projection. Every automatic Item passes original complete lineage qualification against its historical selected facts. Separate Topic proofs for the same Input remain distinct. Selected current Source/Working text must still match the old fact; fresh evidence is not silently substituted for a stale automatic Item.

Bounds are the existing page20 Items, lineage16 evidence identities, Topic8 union, Source128 union, canonical row512, 32 KiB metadata request, original 4096-byte complete Assist Context and 16384-byte full payload. Overbudget means no-send, never truncation or an invented complete profile. The retained local qualification material is capped at the original 8 MiB. Metadata, qualification and final reads share one branded original work budget: 131072 reads, 8192 hash fields and 8 MiB hash work. There is no per-Item reset.

The only new shared scope-owner seam is optional synchronous `isCurrent` on `createContextScopeWorkBudget`. It is held in a private WeakMap rather than a budget DTO. The reader checks it before and after awaited point/page/scan results, before returning rows to an owner, and around original scope hashing. False, thrown and Promise/truthy results refuse. Old callers with no predicate retain their original behavior and ceilings. Assist binds this predicate to its same private receipt, expiry, store, lease and abort controller. A timer provides idle expiry cleanup only; precise read safety does not rely on timer scheduling. Revocation, failure, cancellation and explicit disposal clear private Context/reply/result material and original lineage captures.

Initial capture requires the original metadata admission and exact graph. Subsequent qualification checks exact relevant Item, Source/Working, selected Entry/structure, restrictions, epoch and gate without adopting a live replacement baseline. Unrelated Context edits do not invalidate the retained result. The original signed transport retains its last physical-send fence, cancellation and billing records. An automatic Item without a genuine existing delta descriptor is not forged into a Foundation item; the original private reply obligation and exact transient dependency proof own its one-result acknowledgement.

Within `AIUsageFoundation.commitAssistResult` only, the same private Assist result capability supplies an optional `fenceAfterSettlement` closure bound to that exact original transaction. It runs after the joined result ACK, usage update and final job write; the original final synchronous `isCurrent` remains. There is no transaction crypto/network, caller DTO skip-list, expected-Item fabrication or second ACK owner. Other Foundation methods belong to their coordinated original owners.
