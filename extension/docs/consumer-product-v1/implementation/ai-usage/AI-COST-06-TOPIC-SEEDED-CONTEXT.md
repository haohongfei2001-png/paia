## Source-owned relevance rule

The source selector first examines only bounded canonical Item metadata and original evidence Source indexes. Active Rules remain behavioral Context. An automatic Item becomes a current-conversation anchor only if a concrete original evidence row names a retained, visible Source whose exact `recordIndex.chatKey` matches the current original Assist reply binding.

Only the complete original Topic binding from that concrete matching evidence row becomes a seed: stable Topic ID, creation identity, restore epoch, layout generation, removal marker and original organization operation identity. The implementation uses canonical field ordering, not a Topic display name. An Item with one current-conversation evidence row and another foreign evidence row seeds only the first row's Topic. A globally relevant Rules Item does not seed an unrelated foreign Topic merely because Rules are included.

An additional automatic Info/Now Item is eligible for selection when one of its original evidence rows has an exact seed binding. This rule applies to every bounded matching candidate; it is not limited to a single returned Item. Newly selected Items' other Topics enter their complete required qualification closure but never recursively discover more Items. There is no traversal of all Topics in the current conversation, historical reply lookup, body similarity scan, new persistent search index or model retrieval call. An optional caller callback only narrows candidates and cannot remove an anchor while keeping its foreign expansion authorized.

The complete seed set and selected metadata are captured privately and recalculated at every existing preparation, dispatch, result, original joined-transaction and insertion fence. Selected Source indexes and exact original graph/placements remain frozen too. Unchanged Item bodies alone do not prove unchanged relevance. A matching-name replacement, layout/restore ABA, changed Source association, removed membership or changed negative restriction cannot revive an old grant or baseline.

## Independent grants and bounded original qualification

Selection does not read or hash Item body, section or temporal fields. The existing exact `assist-context-processing` request independently grants every final Item field, Input body/note, Entry body/title/note and selected original structural field required by original eligibility owners. Permission and field requirements are unchanged. Missing any requested field prevents text acquisition, job creation and remote dispatch.

The final selected Items contribute their full old lineage to one shared bounded closure. A genuine cross-conversation positive has a current-conversation anchor Input and a foreign Input in the same original Topic, with separate original Context Items. Combining those two explicitly selected Item lineages lets the existing whole-Topic qualification owner inspect its required Inputs after exact grant. An unrelated sibling is still rejected before its body; the extension does not silently add it to make qualification succeed. Current facts must continue to match the old automatic Item provenance. No semantic evidence, association, original timestamp or protection is fabricated or rewritten.

The same limits apply: canonical row512, selected Items20, evidence16, Topics8, Sources128, 32 KiB exact request, 4096-byte complete provider Context, 16384-byte complete payload and the original single shared read/hash/retained-material budgets. Twenty-one real related Items fail before Item or source-body acquisition. No arbitrary replacement cap, silent truncation or complete-profile claim is introduced.

Automatic Now still uses actual stored temporal projection: unknown remains unknown, an expired unprotected Item is withheld, protected human work remains preserved, and crossing a deadline invalidates the result. Old associations, lineage, Source/Working/Entry qualification fields, seed bindings and grants stay local. The provider receives only the approved semantic Item strings. Receipt expiry/revocation and final Source/Working currentness continue through the predecessor's original branded budget and private original-owner settlement callback.
