## Original owners and explicit qualification

The current ContextCardsService row supplies stable automatic Item IDs, association IDs, revision, lifecycle, human protection and provenance. `readableContextItems` remains the current automatic-body eligibility owner. Existing Input grant scope does not authorize Context Item body, manual Items, unrelated Items or withdrawn human text.

`LocalMaintenanceSession.#processingReceipt` currently constructs `purpose: ai-maintenance-payload`, calls its existing constructor `processing.resolve(t, frozen(request))`, validates the exact outer receipt, and requires returned `scope` to equal the entire request. Its existing `contextItems` key is the separate human-correction contract and is unchanged. Source integration must add this helper's exact metadata as optional `existingContextItems` on that same request. There is no installed production processing resolver; the configured service remains default-null. The missing request/receipt wiring is local implementation work, not a new external trust-root requirement.

An existing Item scope is `{itemId, revision, card, lifecycle, protected, selectedFields, inputIds}`. The selected fields are body/section and, only when present, temporal. Removed, protected, invalidated, unsupported or incomplete Input closure requests no Item body fields. All descriptors and refs are bounded; excess work refuses instead of clipping. No source record or association is added to the provider projection.

## Private helper API

- `planMaintenanceExistingContext(store, t, {epoch, inputIds})`: call inside the original processing-request transaction. Returns a WeakMap-backed opaque plan. Searches only automatic Items whose registered provenance/invalidation overlaps the explicitly selected Inputs. It preserves the exact local row privately to catch same-revision drift.
- `maintenanceExistingContextScope(plan)`: returns the frozen body-free descriptors to include in the original processing request.
- `captureMaintenanceExistingContext(store, plan, {processingReceipt, assertProcessing, read, limits, signal})`: requires the original exact receipt to cover that scope. `assertProcessing(receipt, store)` must synchronously return true from the original owner's currentness check. `read` is the original foundation/owner read callback, and `limits.maxContentBytes` must be the existing bound. The helper does not mint or resolve another grant. It returns an opaque witness.
- `readMaintenanceExistingContext(witness)`: returns frozen provider-safe refs, revisions, cards, states and selected Input IDs. Only currently readable, fully scoped, unprotected automatic Items contain body/section and separately selected temporal text. Removed/corrected/restored protected Items and stale old automatic text are body-free.
- `resolveMaintenanceExistingContext(witness, ref)`: adapter-only lookup of original Item ID, associations, revision and lineage. It provides no write grant. IDs copied from model output must not replace this lookup.
- `assertMaintenanceExistingContext(store, t, witness)`: joins the caller's original transaction, rechecks exact selected Items and the complete original eligibility dependency reads: Input/Source rows, all reached Topic/Section/membership and identity metadata, Entry dependency/provenance, legacy restrictions, filters, original lineage authority and the original synchronous processing currentness. Nothing asynchronous follows its last currentness check.
- `releaseMaintenanceExistingContext(witnessOrPlan)`: drops the private handle and retained lineage capture. Releasing a witness also releases its plan.

Bounds: 32 relevant Items, 20 selected Inputs, 20 current Sources, 8 related Topics, 100 current memberships, 96 KiB provider content or the lower existing content limit, and the original 1 MiB local snapshot ceiling. Source unions are admitted from original metadata before record bodies are acquired. Membership counts and bounded key unions are admitted before membership values are acquired. Every retained row or query is charged incrementally in UTF-8 bytes before it is cloned; a crossing row stops later reads. Original Context scope reads retain their own request-wide counters. These are per-request admission bounds, not a reduction of durable Context capacity.

## Integration obligations still open

1. Source `LocalMaintenanceSession` must prepare the plan before its original resolver, retain the same exact selection across requalification, and release all plan/witness state on completion, revoke, cancellation and failure.
2. The source payload builder must include only the helper's projected records and charge them against the original combined content/request/token budget. The current component limit alone does not certify combined payload budget.
3. The source response adapter must map typed existing refs to original associations/revision/complete current evidence through the existing Context owner. It must never accept a model-authored Item ID, grant or replacement closure as authority. The conservative source fresh-Input guard is not disabled by this component.
4. `assertMaintenanceExistingContext` compares the pre-write snapshot and therefore belongs before the canonical Item mutation. Post-write/ACK settlement must validate only the original owner's exact intended transition. It must not accept a model-supplied replacement snapshot, broad ignore flag or unrelated writes. Original domain owner processing/revision/Source/human guards remain mandatory.
5. Body-free negative refs carry exact identity and protection but are not a semantic oracle. This component does not claim to determine whether any paraphrase is a new claim. Distinct same-Input registered claims remain separate; an unrelated Input is not globally banned. Explicit human restore remains protected and continues through the existing qualified correction/restore path.
6. Stale automatic body is withheld even after a fresh explicit Item grant. Its identity/association remains available privately for future qualified UPDATE; it is not relabelled current. Manual Item bodies are never included.
