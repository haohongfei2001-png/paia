## Original issuer and exact immutable comparison

The new source-private `maintenance-processing-receipt.js` keeps the original raw object for the original issuer's synchronous `isCurrent`. It independently captures the first exact top-level own data descriptors and a bounded, closed scope descriptor tree. Every currentness check validates the captured facts before and after the issuer callback. The source issuer still decides permission; a caller's scope DTO does not supply that permission.

The original store, repository/database, caller, epoch, processing value, first deadline, revocation signal, exact scope aliases, property descriptors and nested values remain fixed. Replacing a scope or nested node with an equal-looking new object cannot refresh the baseline. Accessors, sparse/extra-key arrays, unknown prototypes, cycles, excessive depth/keys/bytes and asynchronous currentness are rejected. Scope traversal retains the original 16-level, 4,096-key, 32-KiB safety ceiling; the session's earlier 1,024-key payload-scope validation remains unchanged. All strings and property names are length-checked before UTF-8 accounting. Frozen nodes need no repeated descriptor scan, but mutable descendants are still checked.

The session and local qualification owner keep the original receipt identity. Their cleanup closures retain the original signal directly, so later raw-property replacement cannot force a getter during cleanup. The source client consumes the same captured receipt and retains its original exact child, scope, reservation, consent, identity, policy and financial checks. It checks receipt facts immediately before raw-field access after other synchronous capability callbacks. Its final two-receipt check calls each original issuer with that issuer's raw object, then checks both captured descriptor trees once more without calling either issuer again. A later qualification callback therefore cannot invalidate the already-checked payload receipt and still return a current visibility grant. The body-processing and paid-response cleanup contracts are unchanged.

This helper is comparison/currentness bookkeeping, not a new permission issuer or a timer. It does not prolong expiry, grant additional fields or renew a completed operation. Actual session tests invalidate each of the three receipt kinds, let the original attempt retire, then restore the raw field: no old Filter ACK or paid replay becomes possible. Those three existing lifecycle controls passed without adding a global sticky ban. Previously disclosed idle storage-retry retention until the next access/host revoke remains unchanged.
