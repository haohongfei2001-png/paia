## Implemented boundary

The same aiPresentation owner prepares a bounded current scope, assembles only changed/new independently supported Entry blocks, validates versioned local fixture responses, commits candidate and coverage through the existing Foundation transaction, and uses existing explicit field adoption/history/status. Actual small batches grow to 200 Entries and then add five; a second fixture grows to 47 and adds three. Neither number is a production threshold. Retained accepted bytes live in the eight-field projection; manifest ranges address those saved bytes, never replacement text at an old Source offset. The provider payload excludes retained bodies.

V2 has a separate envelope/decoder and schema-3 candidate. Legacy schema-1 response/stored decoding and schema-1/2 candidate behavior remain. The frozen pre-change modules under tests/fixtures/ai-incremental-v1-reader are exact a5a3bab8 source bytes with SHA-256 and Git blob oracles; their actual decoders reject both new structures. Top-level refs are body-free, unique and exactly equal projection/manifest support. The new limit is 1000 distinct Entry refs, 1024 blocks and 256 KiB manifest, independently enforced; the initial proposed 1024-ref ceiling was reduced to retain existing recovery/purge bounds. Complete 1000/1001-ref synthetic decoder fixtures keep every other shape/byte bound legal. Actual owner growth uses real Entries and operations rather than inserted cache rows.

Every transmitted child retains the old maxInputs (20), 100 evidence-unit, request/output byte and eight-field text/list limits. More than one child explicitly returns DEFER. A large initial Topic that does not fit is not automatically partitioned. Legacy current presentations are not silently converted. Changes to protected dependent evidence, human-edited fields, style/profile/control/restore binding or unqualified Source/Input state refuse generation; accepted readable work is retained. These conservative cases need later design/work and are not counted as completed incremental regeneration.

First base-none adoption retains the prior false protection semantics. Subsequent explicitly selected changed fields remain protected. Adding independent blocks to an automatically protected field keeps every prior accepted byte and still requires the existing whole-field decision. A true human edit becomes one indivisible manual field representation, retaining its evidence support, including empty scalar or list-item text. This first slice refuses later incremental generation in the presence of such manual fields; it neither splits nor clears protection. Partial/kept decisions do not advance the whole-Topic checkpoint. V2 does not claim exact cache reuse or mint a new cacheBinding.

Source provenance/placement support and live controls are qualified again. Candidate digests cover the complete envelope: adoption computes the SHA outside IDB and compares the same exact proposal bytes inside the existing transaction after the original idempotent receipt lookup. Held restore/style changes, manifest tampering with unchanged public projection, permission removal and evidence mutation cannot borrow an old choice. Public history exposes only the existing eight fields; durable history retains its versioned accepted projection/manifest.

Existing recoveryDraftSourceIds, Source-purge admission and backup schema are not changed. Tests exercise real recovery, old backup restore, and old-backup anti-resurrection. Source-purge coverage explicitly retains current B-02 refusal and the existing historical survivor fixture; it does not claim new permission for mixed purge or full Source restoration. Protected recovery keeps user-owned bytes; generated bytes and stale authority are not resurrected. The test-only historical backup encoder does not revive production export.
