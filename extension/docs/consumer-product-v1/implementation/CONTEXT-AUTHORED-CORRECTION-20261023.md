# Original authored Entry lineage for protected Context corrections

Base: 76c9de3f. This finite package connects human editing and current restoration of an automatic Context Item whose complete original lineage is one source-free authored Entry. The original body-only and complete author body/title/note contracts are reused. Mixed authored/Input evidence, multiple authored Entries, bound/structural correction variants, and invalidated prior evidence remain pending.

## Ownership and qualification

The metadata stage checks the current Context human receipt, original typed lineage and remove/restore chain. It selects the exact original Entry/history references without acquiring author text. The original Maintenance qualification requests independent author/history fields; only its qualified reader calls `readAuthoredEntryContext`. That original owner proves genuine birth/current field history, complete meaningful or explicitly cleared fields, source freedom and current protected membership. No Context grant is borrowed as an author grant, and no authored Entry becomes an Input.

A child carries the exact single `authoredEntryIds` in its transient Context correction scope, an independently granted authored material envelope, empty `inputs`/`inputIds`, and sourceCount 0. Only a single Context unit accepts this shape. Ordinary Topic/Input material retains its original contract; no Topic facet is admitted by the new reference. The original source-owned response adapter reuses the original UPDATE path with exact Item metadata and original typed evidence. No persistent evidence, Input, Sync or Backup schema changes.

The selected automatic Item remains human-protected: the original owner checks the complete provenance and human receipt, returns NO_CHANGE, and atomically ACKs only its Context obligation. It does not rewrite the human Item, author fields, placement, Topic name or membership. Its Topic obligation remains pending. ACK failure retains the physical response for original replay.

## Closed settlement protection

The existing asynchronous lineage rechecks remain. Native final get/count requests also compare the selected Entry metadata/author fields, the original qualified author history, complete selected Entry placement/dependency/provenance collections, current Topic/member metadata, Context human/restore receipts, epoch/filter and original gate facts. A changed count, same-count replacement, raw author edit, historical mutation, added Source dependency or revocation cannot publish an ACK. The capture is charged to the existing qualification budget and 2 MiB retention ceiling; no new writer or broad query capability is added.

The production source-processing owner remains explicitly Input-only. This package uses the already-existing independently granted authored owner path; it does not broaden that source-only policy or authorize production, real data or paid requests. Original service semantic qualification/native integration remains separate.
