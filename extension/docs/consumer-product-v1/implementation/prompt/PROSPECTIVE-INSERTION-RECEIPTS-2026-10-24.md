## Action, transport and receipt protocol

1. A genuine original presentation captures the owner's transient receipt epoch before its original source/authorization reads. `issueAction` performs only reads and returns immutable `{version, actionId, operationId, receiptEpoch}`. The private action fixes lane, source/authorization/initiator digests, authenticated receiver, and the durable parent generation observed by that original owner. Merely showing a view does not initialize metadata. Old views/choices cannot remint the same original action with an edited epoch.
2. REGISTER authenticates extension runtime ID, top frame, browser document ID/lifecycle, tab/window and nonce. Frame-0 PROBE locates that authenticated binding, and exact document-ID PROBE checks it again. Manual private-iframe initiator identity is a separate digest, never the top receiver document ID. Same-document SPA URLs use the actual browser tab plus exact document probe; late ACK does not depend on the current URL or current source permission.
3. Intentional dispatch computes the request commitment outside the native transaction. One original bounded readwrite transaction CASes the captured parent generation and commits the new epoch together with PENDING. Concurrent sibling actions may use only that exact already-committed same-owner epoch. Another original owner's newer epoch invalidates old action admission, final send and native QUALIFY; an old action cannot promote itself to the new generation.
4. Only after commit and fresh original source/authorization/receiver checks does the captured transport send to the exact document ID. The final readonly transaction verifies the exact PENDING claim and current epoch. The invocation flag is set before the actual transport call. Existing producer UI timeout behavior remains outside this continuation.
5. The shared per-document composer owner verifies the canonical digest and exact receiver, deduplicates across manual/Assist/Next and independently evaluated scripts, then obtains authenticated original-worker QUALIFY immediately before its native guard. QUALIFY reruns the original captured source callback and checks current durable epoch/PENDING. Only privately branded actual native outcomes can produce an ACK. A public `{status, verified}` result is insufficient.
6. The body-free envelope contains version, claim/action/operation IDs, transient receipt epoch, numeric epoch, lane, receiver, source/authorization/initiator digests, domain digest and request digest. Domain digest commits to actual database ID and restore epoch. Request digest is SHA-256 of canonical JSON `{domain:"paia-prompt-insertion-v1", envelope:<without digest>, message:<original message>}`. Object keys sort lexically; array order and exact text are preserved. Unsupported values/accessors and oversized input refuse.
7. Exact authenticated ACK CAS changes only its own PENDING to INSERTED or NOT_INSERTED. UNKNOWN leaves PENDING unchanged. A separate NOT_DISPATCHED fact is available only when the private dispatch continuation proves that transport was never invoked. Any possibly invoked throw, lost connection, UI timeout or unverified response remains UNKNOWN. ACK settlement never replays insertion or adds a late reuse publication.

The original receiver can republish its exact cached native terminal ACK after re-registration. Its receipt-read path only returns original cached proof, never current DOM equality. Old unknown/native-unconfirmed entries are not upgraded. A stopped original worker may leave PENDING even when a new worker exists; only exact retained proof can settle it.

## Bounds, retirement and crash behavior

The absolute retained-evidence format is limited to 500 physical claims and 512 KiB. Prospective PENDING admission is stricter:128 KiB, with read-only healthy all-terminal pressure rollover at120 KiB. A larger valid historical/pending row is preserved but may refuse additional work under the unchanged cumulative limits; it is not truncated or called corrupt merely because prospective work cannot fit. Near-cap controls exercise actual dispatch rather than isolated transaction limits. Actions and authenticated receiver registrations are separately bounded. Capacity refusal does not delete pending or unknown evidence and does not reset epochs or coverage. No automatic insertion retry is introduced.

Explicit live rotation first invalidates old action admission and drains original registered insertion, physical send, settlement and publication continuations. Only then does it retire that insertion epoch; unknown claims remain. Transient count/byte-pressure rollover refuses while known original continuations remain. Once they settle, it synchronously invalidates every old action/context without writing metadata and captures a private one-use certificate for the exact original own epoch/nonce/parent. The next actual intentional insertion may retire that live-fenced predecessor in its same parent CAS, removing terminal claims only and preserving all pending/UNKNOWN claims plus late exact ACK identity. A foreign winner invalidates the CAS; cold owners cannot borrow this certificate. This is insertion-admission retirement, not native or global quiescence. Rollover also changes the transient owner token before any first durable epoch, so the receiver can bound attempted events to500 actions plus one initial event without a lifetime cap.

A fresh original worker can fence an older insertion generation at its first actual dispatch. It compacts only old epochs whose physical claims are all durably terminal. This is not evidence that every old source/publication task is quiet. Pending old epochs remain, while merged numeric retired intervals prevent an early unknown gap from creating an arbitrary lifetime limit. The monotonic contiguous floor and sparse intervals cover the entire admitted epoch range without unbounded tombstones. Synthetic checks cover more than 500 successful cold restarts, including one retained old unknown gap.

Retirement notifications carry exact original receiver, domain, epoch/token, cumulative durable floor and exact terminal claim IDs captured before compaction. They target receiver bindings from the terminal claims, not only whichever documents re-registered with the new worker. Receiver removal never relies on current DOM equality. Receiver native terminal proofs and unknown entries remain distinct.

For worker death after terminal compaction but before notification, registration returns authenticated owner, recovery-event and current-domain tokens. One genuinely new original action can authorize at most one batch of16 exact current-domain private native terminal ACKs in one original row transaction. An opaque internal context binds the earliest actual-insert probe to that action and ticket. Each PROBE carries its fixed recovery challenge, REGISTER echoes only that exact challenge, and concurrent A/B registrations cannot share a mutable per-tab current token. Dual probes and repeated phases reuse that same action-bound event and ticket; there is no self-scheduling drain or fresh-budget loop. The initial document event is separately bounded. Unprocessed and foreign-domain evidence remains retained, explicitly partial until a later genuine original event. An exact current-domain retirement summary may release only already-ACK-confirmed private terminal cache entries; an unacknowledged private terminal needs its exact individual batch result. The owner first reconciles any retained exact claim normally. Only an absent claim in a validated durable retired interval, with matching actual current database/restore domain and authenticated exact receiver, can receive `{settled:false, retired:true}`. This is an insertion-admission/cache-reclamation certificate, never a new durable terminal fact. Only the receiver's matching privately QUALIFY-admitted native terminal entry may consume it; unknown or unbranded outcomes cannot. A forged or missing claim cannot gain insertion/settlement authority from this response. Any later uncached old wire must pass live QUALIFY and is denied. Pending claims are never removed by this route. This joint original receiver proof and monotonic original-owner retirement invariant avoids permanent clean-session cache exhaustion without storing unbounded per-claim tombstones.

An exact late ACK may still settle its retained claim after another owner wins. Before any inserted UI result, the original saved source check is awaited inside the unchanged UI deadline, followed by the durable current-epoch fence as the last asynchronous boundary. Producer guards refuse a late check before starting a new source read. A stale continuation therefore cannot publish fresh inserted UI or new reuse state.

Each original insertion starts its immutable30s/4096-reference/2MiB restriction ticket at the earliest actual-insert probe, not while a user is merely viewing a presentation. `beginInsertion` is private-cap/exact-action bound and never resets that ticket. The original explicit `originalRestrictedRepositoryTransaction` seam installs it before native prelude reads and preserves all existing failure and selected-generation restrictions; it does not ambient-tag unrelated same-Store tasks. Same-ticket metadata scopes serialize, including reentrant QUALIFY, direct ACK and final UI fencing. Original producer qualification methods retain their original guards/budgets; this receipt ticket does not claim global accounting of unrelated source work. Source and probe continuations remain independently tracked after a deadline race. QUALIFY supplies only remaining time, conservatively captured before its RPC by the receiver, whose final private native guard refuses expired continuations. The unchanged original two-second UI deadline remains separate.

Cold retirement notices are grouped once by exact epoch/receiver and limited to16 per operation under its same deadline; unsent notices do not start automatic retries. Later genuine bounded reconciliation may recover retained proof. After a receiver's privately branded native terminal receives exact `settled:true` and all local active/publishing continuations settle, its cache may be forgotten with serial invalidation: every uncached old envelope must still pass live original QUALIFY, which denies terminal, absent, retired or foreign-domain claims. UNKNOWN and lost-ACK native proof are not discarded by this rule. This is conservative cache reclamation, not new ledger or global proof.

A live Store/database/restore identity change refuses old work. Corrupt, future-version, foreign-database and migration-not-active metadata is not repaired or replaced. A failed or unmeasured original native transaction poisons its restriction ticket. The owner cannot refresh its budget to perform readback or mint a no-dispatch fact; evidence remains UNKNOWN. A distinct test proves exact same-ticket readback only after an original transaction already successfully completed and an outer response was then lost. This is not general recovery of an uncertain failed native scope. A genuinely later authenticated native ACK remains a separate bounded source event.

A genuine existing-file restore retains nonportable metadata but changes the original restore epoch. A newly constructed genuine owner may admit prospective new-domain operations while preserving the immutable origin and every old unresolved claim. Old-domain ACK cannot settle a new-domain claim. This avoids turning prior history into a permanent blanket ban on all future intentional insertions without laundering restored evidence into current authority.
