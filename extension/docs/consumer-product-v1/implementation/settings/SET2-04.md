## Read-only update-event bridge candidate

An isolated successor introduces `PAIA_SETTINGS_UPDATE_STATUS`, an exact `{type}` read for the existing trusted Archive sender only. Popup, content scripts, other extensions, nested frames, incognito and malformed fragments are rejected before reading. It reads only the existing `paia-consumer-update:v1` key and actual manifest version. The read is exempt from filter scheduling and Archive mutation notifications; existing update-event writers and all other command gates are unchanged.

The projection accepts bounded numeric versions and valid timestamps. Available evidence must originate from the installed version and target a strictly newer version; installed evidence must name the actual installed version. Malformed, future, stale cross-version and absent evidence remain unknown. Storage failure remains a visible read error and never means latest or a fresh successful snapshot. About preserves its anchor nodes and focus; a later read supersedes older results. The existing key's change event triggers another trusted read only while About is visible.

This candidate performs no update check, reload, install, network call, preference write or permission change. A user can defer any available update simply by continuing to work; no unsafe action is offered to a dirty editor. Live distribution installation remains a separate unverified prerequisite. Unit evidence covers the actual worker's sender/no-mutation boundaries, version projection, failed reads and stale UI responses. Source/release dark 320px/200% available, installed, unknown and error evidence has been added to the existing whole-file browser gate but has not yet run for this successor.
