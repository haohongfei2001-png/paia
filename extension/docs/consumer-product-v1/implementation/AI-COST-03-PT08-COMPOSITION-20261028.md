# AI-COST-03 / PT-08 bounded comparison and Section promotion composition

## Implemented scope
This successor closes the protocol-composition gap recorded in the 0.55.26 current-Item comparison implementation. A qualified child can now carry both bounded current Context Item comparison and the original whole-Section promotion task in the same physical request. The original promotion payload is allocated first; comparison uses only the remaining original byte allowance. No action is silently discarded to fit.

Existing exact v1 and strict composed v2 profiles remain unchanged. A separately recognized exact v3 profile permits ordinary authorized Input comparison when there is genuinely no eligible whole-Section candidate. Its required all-empty NONE proposal is wire data only: it creates no Section task, proposal identity, permission, material or promotion ACK. The client derives the response contract from the exact selected profile and retains it privately. With a real task, original PROPOSE/DEFER binding and authenticated settlement remain mandatory; NONE is rejected.

The original session, independent comparison and Section grants, parent receipt, current snapshot, first deadline, cumulative work and byte budgets, and at most two physical requests per opportunity remain. Opening a card is not permission. A candidate denied by identity scope, evidence, permissions or budget cannot downgrade to NONE. A recoverable unsent storage failure clears the provisional null cache; same-job retry must obtain the genuine task and qualification again. No budget refill or extra request is added.

Manual/protected Items remain comparison-only. Automatic Item updates retain the preceding full new-evidence/CAS/protection/association contract. This patch does not change Context domain mutation, Foundation, database schema, UI, workflows, provider endpoints or configuration. All four service configurations remain null.
