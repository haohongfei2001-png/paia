# Bounded staging cancellation through the existing recovery session

Base 7e8259fd. The local recovery session already bounded discovery, but stage() awaited transport.get() directly. A held staging read kept busy=true indefinitely after pause/close; the old pause test released its host before observing settlement and therefore did not prove immediate cancellation.

Stage reads now reuse the same serial-fenced bounded wait, with a 30-second whole-stage read deadline (a smaller positive constructor value may be used, never larger). Pause or close settles the public operation before the injected host responds. Read results arriving after interruption cannot enter the original staging owner or disturb a newly resumed confirmed recovery. This cancels consumption, not a promise that an arbitrary injected transport physically stopped. No new activation engine, persisted body cache, retry loop or rollback of an already committed generation is added. The original activation transaction, confirmation/unknown outcome and replay semantics remain unchanged. The reader also checks the monotonic deadline after promise settlement so a delayed timer cannot admit a late result.

Tests use real original Source/Working bootstrap and grouped staged restore against synthetic fake IndexedDB. They prove pause/close settle while the host remains held, unchanged active tables, timeout after a durable stage has been created and original continuation from that stage, plus an old held response completing after a new successful recovery without changing its state/data. Existing post-commit pause/close, in-transaction rollback and lost-ACK tests remain intact.
