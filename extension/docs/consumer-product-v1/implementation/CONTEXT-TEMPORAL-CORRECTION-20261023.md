# Temporal Context human corrections and terminal protection

Base: 9896424a. This finite implementation completes original automatic Context `now` human text edits and current restoration when the original complete evidence is plain Input body lineage. It does not claim all CTX4 or product acceptance complete.

## Behavior and boundaries

The original ContextCards human owner remains the only producer of the change witness. Current exact revision, semantic digest, original human operation receipt, independent Context body/section and complete Input processing grants, current Source lineage and original no-change publication apply. Restoration additionally requires the original remove receipt and removed-state semantic digest. Existing temporal metadata is valid, frozen and excluded from new provider fields; human-protected temporal status remains unknown, with no automatic expiration or date rewrite. The remaining Topic facet stays pending.

The existing final async check preceded backup generation and could miss a later write. A closed original-repository get/count plan now compares only the selected Context Item, exact human receipts, restore epoch, smart filter, already-qualified original Input/Source facts, Topic metadata, active membership count and rows, and complete legacy restriction key/kind set with exact relevant restriction rows. A same-count removal/insertion cannot hide a new restriction. Other Context Item bodies are not retained. The same existing qualified budget fork accounts reads, references and retained bytes; original aggregate limits and processing revocation remain. No post-commit repair, schema migration, new grant, remote read or new ACK owner is added.
