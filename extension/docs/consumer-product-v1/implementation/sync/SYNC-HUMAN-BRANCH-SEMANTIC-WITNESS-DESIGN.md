# Unused read-only Human branch-semantic witness — proposed interface

**Design only.** This proposes the next finite prerequisite after `SYNC-HUMAN-CURRENT-ALLOCATION-AUDIT.md`, reviewed at `fd9712bb306e1cd889be7981019330f3b090b93b`. It does not authorize runtime implementation, branch retention, a Core transaction capability, ACK, resolution, checkpoint/codec changes or registration in a production caller. The earlier historical audit remains three limited matches/fifteen refusals or unknowns. The later current-allocation audit remains six pure semantic matches/twelve refusals; neither reconstructs historical permission or grants a write capability.

## Proposed surface and owner

Two internal functions in the existing `human-library-plan.js` owner are proposed:

- `captureHumanBranchSemanticWitness(store, core, completeGroup)` asynchronously returns only `Object.freeze({})`, branded in a private `WeakMap` after successful qualification and final reread.
- `revalidateHumanBranchSemanticWitness(store, core, witness)` opens its own original **readonly** transaction, rechecks the private binding and exact captured raw snapshot, and resolves with `undefined`. It returns no data or permission token.

Neither accepts a transaction, callback, generic get/put adapter, caller-provided parent state, current counters, permission flags, replacement allocator, historical DB or precomputed digest. There is no accessor for bodies, before/after, requests, computed rows, history, secret, mappings, receipt, mutable DTO or the private snapshot. JSON cloning, structured cloning, spread, forged empty objects and passing another owner's capability cannot preserve this brand. No prepare/execute/journal API is taught to accept the witness.

Private lifetime is bounded **per actual store**: at most8 live witnesses and at most8MiB **aggregate** retained canonical raw bytes, not8MiB per witness. A bounded FIFO holds only live handles and byte counts; before admitting another witness, evict oldest handles and delete their WeakMap brands and retained snapshots permanently. Evicted, failed and stale handles cannot be revived. An individual raw snapshot above8MiB is unqualified; no truncation or partial proof is allowed. The128-operation/4MiB union limit below is unchanged; this additional storage bound does not promise every otherwise-valid4MiB cut can be admitted. Candidate raw retention must be budgeted alongside live snapshots, evicting before exceeding the aggregate bound. There is at most **one capture or revalidation in flight per actual store**; a second call refuses busy, without queue growth, timer, automatic retry or parallel transient snapshots. Success and every failure release the in-flight slot. All eviction/bookkeeping is ephemeral and performs no database, local-control or Core write.

Keeping this initial implementation within the original plan owner would reuse its private `base` and bounded `editReadSet` directly; it does not require exporting those body-bearing reads or duplicating eligibility rules into a new reducer. A future reviewed implementation may append private helpers, imports and these two unused exports; all existing prepare/execute branches and their ordering must remain unchanged. A NEW owning test may be added. `core.js`, journal, codecs, allocation, search, store, worker, UI, settings, version and CI files are outside that implementation boundary. There is no production caller or registration. The only initial callers would be the NEW synthetic test; any later retention consumer needs a separate reviewed design and transactional fence.

## Exact private brand and admitted case

The brand holds the actual `store`, `store.repository`, actual already-open `IDBDatabase` object, actual `core`, original bound `store.humanLibraryJournal`, and the Core's dataset ID, device ID, prefix and fixed namespace. Exact object identity is required, not equal database names or equal cloned bytes. Capture requires all six actual readiness flags—`loaded`, `iaLoaded`, `filterLoaded`, `foundationLoaded`, `bindingsLoaded`, `documentsLoaded`—and no `foundationFailure` or applicable failure state, plus the already-open actual database. Those conditions are checked before every initialization-capable owner boundary, not only at method entry. Closing/reopening or replacing a database invalidates the witness.

A bare ready precheck followed by `store.run` is insufficient: an already queued `recoverMigration` can reset `loaded` before the inner callback, causing normal `run` to initialize or migrate first. The proposed helper must use a private **settled-tail/readiness barrier** that performs no `init`, `initialize`, `finishFoundation`, migration, recovery or `open` call. It captures the current queue tail and binding/readiness/control identities, waits only for that already-existing tail, and refuses if the tail, flags, failure state or identities changed. It must establish the same barrier immediately before each original queued guard/read can enter and detect intervening queue changes across that guard's own awaits. Its own known queue transition is distinguished from any newly queued external work; this is not permission to replace/reset the shared tail or cancel/reorder existing work.

If the original guard's asynchronous path cannot be entered without a proven no-init barrier using private glue, qualification returns unavailable. Do not edit the original owner, temporarily override `run`/`initialize`, add a fallback initialization path, or assume a ready callback proves the code before that callback stayed readonly. A separately queued explicit recovery may legitimately write; this helper must neither trigger initialization nor attribute those independent writes to its own readonly evidence.

Initial scope is one standalone active user-created Entry, `bodyBinding:thought`, body-only `entry-edit`, one accepted shared parent, and one current canonical sibling. Current and ancestor chains must consist entirely of permitted Entry creation/body-edit closures. No Source/Input dependencies, provenance, placements, Topics, lifecycle/structure/type/note edit, removed/purged ancestor, unresolved existing multihead, unproved derived data or generic historical installation is admitted. The original current prepare entry point must refuse through its normal **CAS conflict** result after its earlier request/actor/duplicate/current-eligibility checks. Invalid actor retains the original error; duplicate is unqualified; an actual current private plan is unqualified and is never executed. No CAS value is replaced to manufacture a plan.

Coalesced and NO_DELTA **parents** are admissible only when their complete accepted Entry/history semantic closure, immutable receipts and actual mappings are proved and the same original pure computation reproduces the incoming semantics. A missing historical revision-counter marker is not fabricated. The initial witness uses actual current counters for hypothetical local physical slots, reserves none and discards the computed local output.

Indexed data is not silently normalized. Recursively validate every accepted/incoming portable member with the original strict codec, including nested history phases; literal `indexedSearchVersion` in portable input remains invalid. Local indexed/queued/coalesced history is allowed only if an actual existing original-owner proof covers every relevant phase at the final fence. The current completed-search proof qualifies an original named plan's exact canonical phases; it must not be repurposed as arbitrary historical permission. If that proof cannot apply to this read-only witness, return unqualified. The initial implementation may conservatively reject all such local indexed cases. No deleting derived tags to force acceptance.

## Capture, compute and final fence

1. Acquire the one-in-flight slot, establish the settled-tail/readiness/no-failure/no-pending-control barrier and check exact bindings. Clone and validate the complete incoming group through original validators **outside IndexedDB**. Preserve exact member order, request key order/digest, domain event kinds/roles/ordinals and original operation bytes. Retain those bytes only privately; later caller mutation cannot change them.
2. Check the exact existing database immediately before entering the original repository transaction, require `t.tx.db` to be that same captured object inside its callback, and check it again after completion; `repository.transaction` itself awaits `open`, so the readiness/queue barrier must cover that await as well. In one original readonly transaction capture the current base, original bounded Entry read, incoming-operation receipt absence, current target head and canonical descriptor/member closure, actual parent closures/receipts, physical mappings and all relevant purged/redacted fences. Capture the namespace/generation, recovery-restore epoch, exact permission/consent settings, library/sealed state, secret identity, thought/revision counters, Entry/history/protection values and absence/index facts. Record lookup absence as well as presence. No crypto await occurs inside the transaction.
3. Traverse the **whole union** of incoming group, current canonical branch and all required accepted ancestor logical descriptors/members with the existing Core ancestry rules. Count each revision once globally. Hard limits are128 unique operations and4MiB canonical operation bytes for that union, not per branch. Preserve original parents/heads/history bounds; the entire private raw capture must also remain bounded. Missing/redacted/partial/swapped closure, receipt mismatch or any excess refuses before qualification. Do not truncate history, rely on an incomplete frontier, or use max/time as a winner or historical-counter estimate.
4. Outside IndexedDB, validate every captured closure/digest and restored request with original functions. Re-establish the no-init queue barrier before the original current prepare guard using the unchanged current input; only the conservative conflict path qualifies. Derive parent semantics from accepted parent payloads and actual mappings. Run the same original `computeHumanEntryEditState` with current local counter/physical values and the original replay allocator, then require exact original portable Entry/history semantics and complete event consumption. Preserve protection, authored timestamps, operation identity and historical branches. No source of parent semantic content is the caller, incoming `before`, current canonical body or test oracle.
5. Open a fresh original readonly transaction and reproduce the **same full raw capture**, including current base, receipt absence, closure membership and every read/index/absence/mapping fence. Compare exact original canonical bytes, not only hashes, revisions or a selected subset. Recheck all object identities before and after transaction completion, including the actual transaction database inside the callback. Changed state returns stale/unqualified and creates no witness. Crypto, callbacks and timers are not kept alive inside this transaction.
6. After the final awaited transaction has fully completed, synchronously check the exact store/repository/database/Core/journal bindings, all readiness/failure flags, expected settled-tail identity and the current local control identity (`pendingControl`/`controlCache`, database identity and captured permission/consent epoch). A pending control change or a changed control identity invalidates the candidate even if the last database snapshot was equal. No await may separate that last synchronous check from storing the brand/return. Mint only within the handle/aggregate-byte budget. Revalidation repeats the same no-init barrier, exact database/ready/raw checks and final synchronous pending-control/control-identity checks after its last await, then returns nothing. It may use the already-validated private immutable input/closure bytes; if any raw fact differs it refuses rather than repairing/rebasing the witness. No automatic retry is required.

A future writer cannot treat this readonly revalidation as a durable guarantee after its transaction ends. Any later write consumer must revalidate the same snapshot **inside its own original final transaction**, through a separately reviewed binding with no caller-supplied adapter. This proposal adds no such consumer. Even a valid witness therefore cannot advance Core heads, store incoming branches, reserve local counters, append domain history, produce an operation receipt or ACK.

## Implemented conservative resource refinement under independent review

The first implementation was blocked by independent current-semantic, transient-memory and in-place-control failures. Input and progressively collected records/groups are sized before encoded duplication.
