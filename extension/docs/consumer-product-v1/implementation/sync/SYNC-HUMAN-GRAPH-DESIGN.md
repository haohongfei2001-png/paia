## Proposed smallest useful slice

One optional, local-only family for independently authored `bodyBinding=thought`, `provenanceType=user_created`, human Entry graphs, including active/ordinary-removed state and all available qualified recovery history. No Input refs, Source refs, evidence/dependencies, AI generator/output, redirected/merged identities, layout jobs, legacy ambiguous identity, or permanently purged graph. Every reachable Topic/default/named Section, current and removed Placement, membership exclusion/fixed-set/order intent and relevant Topic identity fence must be included. Multiple Topics needed by a move form one closure. An unplaced independent Entry is legal; no invented Topic is added.

Deliver a real vertical path: existing create/edit/place/remove/restore owners atomically journal the family; existing publication and segment reader preserve it; explicit local receiver applies complete causal groups through private existing-domain transaction helpers; grouped checkpoint inventory includes the same family and can restore a bounded fully covered graph into an empty installation. Constructor option defaults null. No UI/worker registration, provider, new permission/schema or claim of full Library recovery.

Supporting create-only export while later actual edit/remove routes remain unguarded is not this slice. Where a mutation cannot yet produce a complete valid plan, a bound journal must reject that mutation before any canonical write. The unbound/default path stays unchanged. This fail-closed intermediate condition is not a deliverable substitute for the named supported journeys.

## Indivisible portable data and causal identity

Propose new required `humanLibraryMember` v1 and `humanLibraryCommit` v1 outer codecs, not hidden fields in an old codec. Each member binds dataset, producer, logical operation ID, original domain request operation ID/digest, typed entity ID, full before/after domain revisions and canonical payload. The descriptor binds exact ordered member refs `{type,entityId,revisionId,operationId}` plus history closure and original transaction identity. Every member alone is unknown to the frozen exact 033 reader; test maxOperations=1 and byte-boundary splits, descriptor first/last, and cross-commit swapping. Keep protocol envelope v1 and existing segment limits.

Stable outer entity identity is the real Entry/Topic/Section/Placement/history identity, not a fresh bundle UUID; parents bind prior acknowledged revisions. Complete group admission checks all current parents before materialization. Concurrent overlapping groups retain protocol siblings and refuse canonical materialization/ACK until explicit resolution; never select a winner by arrival, clock or largest revision. Separate independent graphs can progress. Independence inside the same graph is not inferred merely from different storage rows. Resolution must name every conflicting parent and recheck current domain state; no new UI is proposed.

Entry payload preserves title/body/note/type/formation, all human protection/authorship/field revisions and semantic organization/dependency revisions, lifecycle and creation/edit times. Topic payload preserves stable ID, personal identity revision, lifecycle/noRecreation, default Section, human name/summary/protections and organization revision. Sections preserve exact logical IDs, layout generation, default flag, title/rank/protection. Placements preserve both removed and active edges, Section/rank, membership authorship and protections. Negative/fixed membership intent retains operation/time/reason/revision, including both move sides. A direct body equality is never sufficient identity.

Wire history preserves immutable revision ID, before/after, field mask, actor/reason, original operation ID, base/after revisions, original timestamps/windowStartedAt and original remote sequence evidence. Receiver assigns only local sequence/listKey/documentList/derived display sequence according to the actual owner and records a namespace-qualified mapping. A history ID is a stable entity, not immutable content: the existing journal legitimately coalesces into that same ID. A legal coalesced update is a new protocol revision with the exact prior protocol parent and before-image/head/CAS; only an identical protocol revision/operation identity with different bytes is a collision. The local mapping retains the same mapped history row identity/sequence while advancing its qualified content. Coalesced replacement revisions must prove the prior revision and preserve its causal evidence; missing/pruned ancestry is explicit unsupported, never a fabricated baseline. A future retirement policy is not included.

## Topic identity and device-local suppression

Never transport `thought-suppression-key`, `exactSignature`, `identity.nameToken`, opaque alias token or an entire meta dump as portable authority. The receiver computes local keyed values from proven portable inputs using the current local secret; before committing, recheck that secret and restore epoch. Entry exact signature uses the existing keyedHash body/type contract. Topic current-name and alias tokens use the existing exact normalization in `prepareTopicName`/identity helpers. Same display name does not merge stable IDs or remove keepSeparate.

Aliases require exact historical plaintext names from the qualified existing Topic history and the corresponding human identity operation. If an opaque alias/noRecreation fence cannot be reconstructed from surviving approved history, reject the closure; do not guess, silently omit the fence or copy the sender's token. Removed Topic identity stays removed and registered in local name fences. `topicKeepSeparate` remains a portable pair of stable Topic IDs with human intent/revision; both endpoints must be in the closure or have a proven existing current graph. No redirect/merge support in this first slice. Existing Source/Input-derived suppressions and purged unknown-name fences remain unsupported and block checkpoint scope.

## Actual transaction seam: prerequisite, not an adapter promise

Current public domain methods allocate UUIDs/time and call mutable history inside a live transaction. They cannot simply be called after receiving wire state: that would generate new identities, timestamps, history and echo. Do not change global store.clock/uuid or write raw canonical rows from a new receiver.

Required refactor is an explicit private domain plan built by the existing writer: snapshot requested read-set and relevant retained histories; reserve IDs/time in a request-local plan; reuse/extract the current pure field/identity/rank/CAS validation and mutation computation. Precompute wire hashes and local keyed tokens outside IDB. The same owner consumes a private capability inside the existing final foundation transaction, rechecks exact read-set, namespace, permission, recovery epoch, library sealing and secret, and applies the planned domain/history/derived-index writes. The optional journal then commits the exact Core members, domain operation receipt and outbox in that same transaction. Bound pruning must use the same planned time and refuse unrepresented retirement. No second reducer that independently reimplements Entry editing is acceptable.

`LibraryDocumentsStore.operation` derived touches must participate in the plan/final comparison; hooking only `ThoughtStore` before `touchTopic` is incomplete. Public priorOperation remains request-digest idempotent. Local domain operation receipts are not imported as UI commands; portable domain operation identity is separately bound to Core receipt/proof. Unknown local ACK retries use the original request/operation ID and return the durable original result. Remote duplicates after later legal edits acknowledge only exact previously committed Core group identity without overwriting current content.

Before coding, choose one exact owner-plan API (suggested internal `prepareHumanGraphOperation` / `commitHumanGraphOperationInTransaction`) and demonstrate extraction for the real createEntry/createTopic/place/move/history paths. If this cannot be done without changing their existing semantics, return for interface review; do not add an unused generic callback adapter.

## Receiver and grouped restore

Complete group preparation validates member closure, parent graph, portable identity mapping and history chains before any canonical write. Current snapshot and all receipts/heads/source-free qualifications are rechecked in the final transaction. Missing pieces stage protocol only or refuse; no canonical receipt/frontier marked as successfully applied. Generic Core/applyPending/checkpoint paths must not independently materialize members. Keep the same restricted complete-family capability used by current Source/Working families; default receiver refuses the new codecs.

Extend group planner with actual causal dependencies and scope compiler with human graph inventory. Source/Working/manual owners retain their original checks. Exact inventory must reject unjournaled Topic/Entry edits, aliased name fences without portable proof, omitted removed edge/history, unsupported AI or dependency stores. Restore activation remains one transaction over the already approved fresh replay namespace, canonical writers, scope proof and active pointer/outcome. Temporary staging cannot bypass required codec refusal or materialize on duplicate protocol receipts. Allow only explicitly enumerated owner mappings (local keyed tokens and physical sequence/index values); never generic metadata deletion to make equality pass.

Retain 128 total unique operations including all ancestors and 4 MiB encoded operation budget; existing two-namespace storage accounting remains. Graph traversal/read-set/history budget must use these complete bounds before canonical mutation; no silently truncated history or split move. Large graphs return explicit unsupported/resource-limited and leave all stores unchanged. No promise that this admits 128 Entries (one Entry graph takes multiple operations).

## Review refinement: concrete single-owner plan boundaries

This is a proposed extraction API, **not a function already present**. Avoid a general `(transaction, callback)` shadow database or a second Sync reducer. Each public supported method dispatches to a named existing-domain plan; ordinary and journal-bound calls consume exactly the same plan/apply functions. The null-journal path does not serialize or create Sync operations.

`ThoughtStore.prepareHumanOperation(request, kind)` coordinates only an enumerated set of private domain planners. It obtains actual current rows and bounded history edges in a read transaction, allocates a request-local `{at, ids}` once, calls the relevant pure planner, computes keyed identities and immutable operation digests outside IDB, then returns a WeakMap-backed capability. `commitHumanOperationInTransaction(t, capability)` rechecks all exact rows/ranges, epoch/secret/sealed-library/permission and the request receipt; applies the prepared domain outputs through the extracted existing writer, including its actual Library index hook; the optional journal consumes that exact capability in the same transaction. Callers cannot construct a capability or substitute before/after rows. The planner's UUID/time are private arguments, never a mutable store-global override.
