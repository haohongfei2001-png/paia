# SYNC01 Source/default Input bootstrap — design only

Base 1700f9bf432cecd7597adcadb4a1a2b98e2678e6 (coordinated 0.30). No runtime, tests, CI, schema, worker, permissions or provider changes in this branch. This is a proposed explicitly injected local slice, not full canonical restore, account integration, checkpoint activation or implementation evidence.

## 1. Current seams and exact missing capability

BNS CONTRACT 03/04/05 requires immutable original payload, evidence-qualified Source facts, exact human history, same-transaction canonical/outbox and remote canonical/ACK, and no inferred grants. PLAN SYNC01 permits local synthetic proof before OAuth. The existing ten-field source codec is not the complete capture owner and must remain byte/behavior compatible.

Actual IndexedArchiveStore.sourceOperation validates capture, hashes message identity outside the write transaction, then creates records, calls applySourceTime against the times ledger, saveRecord, defaultBlock and refreshDoc in the write transaction. defaultBlock uses syncLibrary for logical document/Input formation and invokes IAStore.prepareInput. IAStore.initializeInput allocates local deltaSequence and journal(planInputRevision) allocates baseline UUID, at/windowStartedAt and revision sequence. Calling this path naively on the receiver would manufacture different baseline history. BackupService's separate file-restore confirmation and whole graph owner is not a BNS materializer.

InputWorkingCommitReceiver presently requires all of those canonical objects. It compares every existing history ID and exact before/after, with an explicit baseline fallback that permits local sequence/list tuple differences. This fallback is the intended bridge: it does NOT permit a freshly invented baseline ID/time. Its first successful Working closure writes real workingHistory and workingOwner mappings. No fabricated mapping to a nonexistent inputWorking revision is allowed.

## 2. Deliberately narrow admitted state

One initial ChatGPT source snapshot, one message, a previously absent conversation, and one default Input/document per logical commit. Source.previousVersionId=null, no parent source/version chain, no importProvider/profile/evidence or legacy ambiguous binding, no branch, no Source user modification/removal, no Input manual changes/placements/Thought references. Record note/editedText empty, hidden=false, deletedAt=null. Input libraryText=null, note empty, editedAt=null, excluded=false, revision=0 and active; one exact Source provenance, no merged sources. InputState contentRevision=0, removalState=active, filteringPolicyState=none. Baseline reason=baseline, important=true, before===after and exact sourceRecordIds. No Keep intent is invented.

The optional binding defaults null/off. With it bound, enrich is explicitly unsupported in this first slice. Batch messages length other than one, any existing conversation/source/record/default Input, changed metadata, multi-message/mixed requests, and missing/unknown fields fail BEFORE canonical mutation or protocol acknowledgement. capture(request) has no operationId in its actual public DTO. Therefore this slice does NOT offer cross-worker capture-call acknowledgement reconciliation. A new request object after a committed-but-lost capture ACK finds the existing Source/conversation and refuses UNSUPPORTED/ALREADY_PRESENT without a second bootstrap. The already committed outbox remains recoverable and is republished under its persisted operation IDs. WeakMap preparation is only an in-process transaction capability, not durable caller retry identity. Ordinary unbound capture/enrich behavior remains unchanged. This temporary optional scope is not suitable for enabling the normal scan scheduler; worker registration remains absent.

Remote exact duplicate is allowed only by the actual complete bootstrap receipt plus current deletion/restore/namespace qualification, never by body similarity. Different IDs with same sourceKey/dedupe identity are not silently merged in this slice. Source/snapshot tombstones, Input removal, capture exclusion and immutable collisions reject the entire closure, not partial materialization.

## 3. Exact versioned wire shape

New required outer types `sourceBootstrapMember` v1 and `sourceBootstrapCommit` v1; protocol stays 1. Old `source` codec is untouched. Every member independently requires the new codec even when publication maxOperations=1 or segment order is reversed.

Member.value exact keys: {id, entityType, entity, logicalCommitId, datasetId, deviceId}. id is a stable typed logical entity ID, not random per retransmission. Allowed entityType is exactly source, timeEvidence, inputDocument, input, inputState, baselineRevision. Outer operation identity/type/entity ID, inner dataset/device and logical commit identity must agree. All initial parents are empty; future unsupported revisions cannot masquerade as another initial bootstrap. Existing Core digest/operation receipts apply.

Commit.value exact keys: {id, version, datasetId, deviceId, sourceId, sourceKey, documentId, inputId, baselineId, members}. members is an exact set of all six typed member ID/revision-digest refs, no extras/duplicates; one of each entityType. The timeEvidence member is present even when no ledger exists: entity exact {id: sourceKey, value: null | verifiedLedger}; null is an explicit fact, not omitted closure. Digest includes all members and current identities. Existing codec string/body limits, CORE_LIMITS batch/aggregate bytes and SEGMENT_PROFILE encoded/decoded/count/chunk/expansion limits remain mandatory; six members alone is not a payload bound. Oversize or unsupported text rejects the complete closure without truncation. No arbitrary metadata/store names are accepted.

Canonical fields to encode/validate (physical index rows are excluded):

- Source required exact initial fields: id, platform, chatId, chatUrl, chatTitle, sourceMessageId, pageOrder, originalText, contentHash, sourceKey, dedupeKey, sourceSentAt, timeSource, timeConfidence, conversationOrder, capturedAt, previousVersionId, note, editedText, hidden, deletedAt, updatedAt. Require timeCandidates, which current applySourceTime emits even for unknown time: exact {dom:boolean,response:boolean,agreement:unknown|single|agree|conflict}. Reject other fields rather than drop them. Hashes are recomputed from exact original text/identity; no normalization.
- timeEvidence exact {id,value}. Preserve the actual current times row ledger: required blocked:boolean, createTime:null|finite number, candidates:object; optional domConflict:boolean only when present. candidates permits only chatgpt_dom and chatgpt_response_create_time; each exact {source,timestamp,identity:{chatId,sourceMessageId}}, with source matching its key, canonical ISO timestamp and qualified identities. officialExport and all unknown ledger fields reject in this initial ChatGPT-only slice. Absence/null is retained. The bound initial planner passes its captured operation time explicitly to the existing applySourceTime calculation; the receiver validates/recomputes the same initial arbitration at that captured time, never its own current clock. Recompute from the supplied qualified ledger with the existing SourceTimeResolver/applySourceTime logic and require exact Source time/timeCandidates equality; reject conflicting or inconsistent representations, never sanitize them into another value. Existing backup validation alone is insufficient (timeEvidence only has a broad top-level field list). Identity-mismatched or arbitration-inconsistent ledgers do not qualify. These checks establish only internal consistency of the verified portable operations. Under BNS provider trust (no provider signature or separate secret trust root), a malicious party able to rewrite the entire self-consistent ledger, Source and hashes is not distinguishable as fabricated provider evidence; this slice does not claim that authenticity guarantee. Unknown remains unknown. No receiving-clock rewrite.
- inputDocument exact {id,source,working}. Both retain the current logical fields: id/platform/sourceConversationId/originalConversationTitle/userTitle/summaryPlaceholder/futureAISummary/firstSourceSentAt/lastSourceSentAt/status/aiSuggestionStatus; source additionally has titleRevision=0. No sourceRecordIds or index/sequence fields are imported. All initial values must match the current shared pure formation logic, rather than arbitrarily accepting userTitle or AI output.
- Input exact existing initial projectBackupEntity inputs shape: id/documentId/sourceRecordId/originalTextReference/libraryText/note/editedAt/excluded/status/provenance/mergedSourceIds/aiSuggestionStatus/revision/provenanceSignature. Admit only keys actually produced by current initial owner; extra protection or future fields fail unsupported, never stripped.
- InputState exact {id,documentId,contentRevision,removalState,filteringPolicyState,sourceRecordIds,deltaSequence}; remote deltaSequence is evidence in the immutable operation, not the receiver's local counter.
- baselineRevision exact existing workingRevision codec keys: id/kind/entityId/documentId/before/after/reason/important/sourceRecordIds/entityKey/sequence/windowStartedAt/at/listKey/documentList. Validate baseline semantics and tuple consistency. The sender baseline ID, time and body snapshots survive unchanged; only local physical sequence/list tuples are allocated on materialization.

The enumerated initial Input field set is exact; userTitle/branchStatus/importOrigin/userEdited from the broader backup allowlist are not admitted here. Actual bound capture outputs must match these field sets in production-owner tests before codec admission. No catch-all arbitrary JSON field is allowed.

## 4. Producer plan and trusted transaction capability

Do not override store.clock/store.uuid globally, even temporarily. Do not call defaultBlock/initializeInput on the receiver and patch the resulting rows afterwards.

Extract the smallest existing initial-formation seam into a shared pure planner plus a private transaction writer. Use syncLibrary/unknownTime/applySourceTime unchanged to form Source/document/Input and exact time ledger; use planInputRevision(t,data,{now: explicitCaptureAt,uuid: ()=>plannedBaselineId}) in the sender planning read transaction to derive the one baseline, not an alternate history algorithm. Allocate sender record ID and baseline ID once for the captured operation. Preserve actual capture time separately from provider event time.

Suggested interface (names provisional):

1. `SourceBootstrapJournal.prepareCapture(store, validatedSingleCapture)` performs read-only bounded initial qualification and snapshots real control gate, namespace/restore fence, sequence counters, relevant source/tombstone/removal/exclusion absence and conversation absence. Allocate IDs/at and build the shared plan; prepare required operations/hashes outside a live write transaction. All actual current initial fields are verified. Return an opaque object held in a private WeakMap, not a caller-constructible DTO capability.
2. Inside the existing sourceOperation commit transaction, `journal.authorize(t, prepared)` rechecks all relevant snapshots/generations/control and reserves that exact plan for t. Existing canonical writer consumes this one plan; it cannot fetch a new clock/UUID, or silently fall back to ordinary defaultBlock. `journal.commit(t, prepared)` verifies written Source/time/document/Input/state/baseline against the planned values then commits the prepared outbox. Real transaction completion precedes the capture ACK. On rejection no partial content, baseline, outbox or protocol progress is retained.
3. Unbound sourceOperation continues its existing branch unchanged. Bound unsupported enrich/mixed/duplicate-source cases reject before writes. Only the already committed outbox publication/remote receive has durable exact operation replay. Reusing a live prepared capability is restricted to its captured snapshot; it is not a claim about new capture objects across process death. A repeated capture call against a committed Source refuses rather than infer an ACK from matching text. No store-wide saveRecord override or post-transaction journaling.

The writer is reusable for remote initial closure via a separate private receiver capability; its API accepts explicit verified canonical Source/document/Input and baseline, never arbitrary store names. It reuses recordIndex/blockIndex/sourceCount/refreshDoc and the same initialization data constructors. Local counters are passed/allocated per transaction; there is no global clock/UUID override. All stores remain existing ones.

## 5. Receiver and baseline bridge to Working

Explicit receiver accepts ONLY complete verified bootstrap members+descriptor. Use real publication→pack→readSegmentDescriptor; the generic Core receive/applyPending/reconcile/checkpoint paths refuse this family, not no-op acknowledgement. Constructor binding is same repository/core and opt-in; no provider/worker registration. Do not expand Working inbox's allowed families in this batch.

Before expensive retrieval/verification capture namespace/restore/control; final transaction rechecks them and all source/content/removal exclusions. Recompute exact Source identity/body digests, verify times identity and initial formation fields, closure and absence/duplicate fences. Within one repository transaction allocate local record/document/block sequence and local Input delta/revision sequence. Write supplied immutable Source, exact ledger, supplied verified initial document/Input values and freshly derived indexes. Write the verified baseline with its ORIGINAL id, at, windowStartedAt, before/after, reason and Source IDs; replace only sequence/listKey/documentList with allocated local ordering values. No temporary wrong baseline exists at any point. No human intent is reconstructed from cache.

Core keeps the original full sourceBootstrapMember baseline wire operation with sender sequence intact; optional bootstrap metadata proof binds baseline ID, original member revision digest, local sequence and actual canonical snapshot. This is not workingHistory under an inputWorking revision. Do not precreate inputWorking heads/workingOwner or fictitious inputWorking history mappings.

After bootstrap, an actual first InputWorkingSyncJournal edit publishes the same baseline ID/time/snapshots in its existing inputWorkingMember family. The existing receiver baseline branch permits only the allocated sequence/list tuple differences; it compares every existing baseline ID and exact content. Its successful first Working closure then records workingHistory against the REAL incoming inputWorkingMember revision and workingOwner as usual. Mandatory test both directions: A capture/bootstrap B; A edits→B receives; B edits→A receives. Also B edits immediately after bootstrap before A's first edit, demonstrating that the remapped baseline is not falsely treated as an old mapped Working revision. Concurrent edits remain conflict/unsupported, not silently resolved.

The actual enhanced store also owns SmartFilterStore.initialFilter(b,state): original capture adds optional presence/queue rows after its core transaction. The remote initial writer must explicitly rebuild a conservative local filterInputs row through that existing factory (untouched, unknown presence, no Keep/classification grant), never import sender classifier/evaluation state or mark absent evidence present. Keep this derived row inside the receiver transaction so normal queries and the next Working protection owner see consistent rows; factory absence is UNSUPPORTED, not a silent skipped index. Derived rebuild effects are not canonical wire fields. Existing sender optional presence behavior remains separate and is not claimed portable.

Canonical writes, protocol revisions/receipt/frontier and bootstrap proof commit atomically with origin remote and no echo outbox. Any index/receipt/final write failure rolls everything back. A prior identical receipt cannot bypass later permanent deletion, namespace or same-value restore fences. This is one bounded initial closure; no arbitrary checkpoint activation callback and no whole-library replacement.

## 7. First actual negatives and acceptance

1. Real capture on A → real publication maxOperations1/64KiB split → actual old-reader validation on EVERY member/descriptor refuses. Missing descriptor never admits old-compatible members.
2. Fresh B with no copied canonical stores applies complete initial closure; exact canonical Source/time/identity/body equality (physical local sequences separately checked). Feed actual A Working edit next, then B edit back; baseline ID/at/windowStartedAt and wire operation bytes preserved, local sequence differs intentionally from A.
3. Mixed/multi capture, enrich, existing conversation, parentSource, import/branch/manual fields, or existing Input: bound request refuses with full before/after stores and outbox equal. Default-null regression keeps original capture/enrich behavior.
4. Forge time ledger identity/timestamp candidate, unknown→guessed time, Source hash/body, document ID, baseline at/ID or refs; two legitimate bundles swap one member; duplicate/missing/extra members: zero canonical/receipt/frontier writes.
5. Source/snapshot tombstone, existing Input removal/exclusion, same ID different exact Source, same source identity different record ID, namespace switch, permission loss, same-value backup restore during preparation: no overwrite/resurrection/ACK.
6. Abort after each canonical and protocol write phase: original empty or old generation remains exact; worker restart republishes persisted outbox operations and retries remote apply under the same identity exactly once. It does not retry capture(request) as though that DTO carried an operation ID. New post-commit capture calls explicitly reject without duplicate canonical/outbox writes. No echo outbox, no automatic consent/grant/model/network call. Test a lost capture response followed by new worker/request object: exact stored data/outbox unchanged and explicit refusal (not success ACK).
7. Local/remote sequence counters intentionally differ and unrelated histories exist; no collision, UUID/time preserved, exact replays do not allocate another baseline. Future Working coalescing stays with current sole planner.
8. Long Unicode and unknown/evidence-qualified time fixtures pass real producer/decoder/receiver. Only claim the measured bounded slice; no 1k/50k/500k performance, physical device, cloud lost-device or full canonical restoration claim.
