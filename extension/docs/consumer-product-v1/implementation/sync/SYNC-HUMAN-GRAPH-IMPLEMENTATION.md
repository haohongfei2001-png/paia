## 2. Private allocation and named original-owner execution

The next internal checkpoint adds private request-local ordered allocation and named Topic creation, independent Entry creation, and unplaced independent Entry edit plans. `executeHumanPlan` brands a cloned request privately, revalidates its exact read-set inside the original `thought-store.operation` transaction, and calls the actual existing public domain method. There is no replacement repository, callback reducer, mutable global clock/UUID override or remote authority. Exact resulting domain rows/history/operation receipt and sequence counters are checked before that transaction can finish. Same-window edits retain the real coalesced history identity; no-op retains its existing behavior. This is **not yet** optional journal publication, a new wire codec or remote restore.

The normal path still consumes the original allocations. `thought-read-index` receives an optional deferred generation only from the private transaction allocation context; its existing active/index/key conditions alone decide whether to consume it. Actual missing-index, inactive-Topic and already-current-index cases consume none; repeated real Topic touches preserve separate times/counts/generations. Newly appearing Topic index metadata invalidates a prepared creation plan. The Topic touch computation is shared by the original writer and planner.

Root expressly authorized the two IAStore pruning seams and subsequent pure original prune predicate extraction. Working and Human active transaction owners cannot both supply a pruning time. Unbound pruning retains its original clock, cursor order, important count, 90-day cutoff, newest-20-important and invalid-date semantics. Bound plans reject unrepresented history retirement before writing; explicit bound pruning is unavailable. Tests compare the actual original cursor against the shared predicate and verify complete rollback. They do not claim a retirement protocol exists.
