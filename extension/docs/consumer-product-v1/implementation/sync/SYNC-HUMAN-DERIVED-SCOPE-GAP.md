# Human local derived metadata — actual gap and bounded interface for review

Private unpublished Human graph work. This is a proposed interface, not approval or implemented compatibility.

Actual original-owner gap: a real journal-bound `createTopic` followed by original `searchBatch` writes `indexedSearchVersion='0:active:0'`; the next explicit `editTopic` refuses `BNS_HUMAN_CODEC_INVALID`. `/tmp/human-search-derived-gap.log` records the actual owner value and failure. Current required codec's exact field list excludes this local derivative. Neither an arbitrary key deletion nor transmission of sender search truth is acceptable. Actual full grouped recovery currently admits only untouched original search queue locators, and rejects indexed/posting/Topic projection states rather than claim completion.

Original setters/sources:

- `library-search.js:queueSearch` derives `searchVersion=ownerVersion(kind,row)` and writes a body-free `libraryMigrationItems` task with exact `['search',kind,id]` ID, phase `delete`, offset zero, source IDs.
- `searchBatch` processes original `librarySearchTerms` postings, then sets `indexedSearchVersion=task.version` through original `putDerivedSearchRow`; tasks can lawfully be phase `delete` or `write` and partially processed. Its postings are hashes plus original owner/version/field locators, not a second body store. `indexedSearchVersion` records completion of a particular local search owner version, and may lag current `searchVersion`; it confers no human protection or canonical revision.
- `thought-read-index.js` creates complete root/Topic local metadata, body-free root rows and four ordered Topic/expression projection rows per actual descriptor. `organizer/topic-reading.js:descriptorReader` is the existing original descriptor source. Generation, cursor, counts, times and build progress are local, not incoming domain truth. Original build/invalidate transition is already shared; this proposal must not change query, sorting, asynchronous pipeline or copy sender generations.

Proposed finite qualification: **only** `indexedSearchVersion`, on actual Entry/Topic/Section local rows, can be omitted from the wire when an original search-owner read proof qualifies its real exact string/version, task/posting schema and current owner ID. No suffix matching, generic derived-field stripping or blanket ephemeral-store exemption. Before CAS still compares the complete captured local row, including this field. The original receiver owner preserves or invalidates its **own** local derivative according to its existing search writer; an absent receiver has no indexed-completion claim. Incoming indexedSearchVersion and arbitrary additional fields continue to be required-codec failures. Producer compares its exact original semantic fields to the actual parent wire plus explicit local derived proof, not to unchecked after guesses.

The scope proof must read and bind every actual task/posting/index metadata row before publication/activation and recheck in the same final original transaction. It must reject extra body fields, unknown task kind/owner/phase, wrong IDs, wrong source IDs, orphan owner/version or unproved stale generations. Complete ordered metadata/counters are preserved locally. Old index rows from retired generations are recognized only via original owner generation/cleanup qualification, not guessed from strings. No new shadow store/reducer is allowed.

Narrow proposed extraction: expose the existing original pure projection-row constructors/IDs and exact metadata validators for readonly qualification, and have their original writer reuse them. Do not rewrite search/query/sort/build loops. The original `descriptorReader` remains the actual source of descriptor values. A qualification cannot derive stale snapshot values from a later canonical row; original metadata/retained causal snapshot must prove them or the scope refuses. Cleanup uses existing original derivative owners after safe local invalidation; it cannot erase foreign or unproved rows to make scope pass.

Required actual matrix before any broader claim: Entry/Topic/default+named Section without search, queued delete, partial write, completed current index, completed older version followed by original edit, remove/restore, both move sides and repeated touches; source indexed→absent receiver, source absent→indexed receiver; root/Topic building/completed/retired cleanup generations; original task/postings/index output byte oracle; malformed/extra/orphan/stale/body-containing rows refuse before publication or canonical writes; same-txn canonical+mapping/Core/derived counter+pointer fault rollback; duplicate/lost ACK and cleanup preserve body/identity/history. Actual old-reader required-family refusal remains mandatory. Any state not proven by the original owner is excluded, never silently normalized.


## Split A: search completion field and original postings proof (proposed first)

Finite interfaces: `planSearchQueueLocator(kind,row)` extracts only the original queueSearch task constructor; original queueSearch must reuse it. `planSearchPostings(kind,row)` extracts the original searchBatch construction using existing tokens/field list, not a new tokenization rule. `qualifyHumanSearchCompletion(capture, retainedOwners)` is readonly and accepts only the exact field `indexedSearchVersion` plus actual owner/task/postings rows. Its candidate completion version must match an exact retained same-entity full original Human member before/after snapshot's original ownerVersion. Current-row equality alone cannot prove an older indexed snapshot; retained protocol ancestry is the proof source. The currently queued version must be the actual current owner's original searchVersion; any old postings must exactly match an admitted retained original snapshot and original constructor, with no body/extra/unknown columns. Full captured local rows/tasks/postings remain in final before CAS even when this one proven local field is omitted from portable wire. Missing retained older version, foreign family, unrepresented owner, malformed or extra postings/task fails. No root/Topic read projection exemption is part of Split A.

## Split B: root and Topic read projection rows (not Split A authorization)

Finite constructor extraction proposed for a separate review: `planThoughtRootProjection(topic,generation)` returns the existing original root row or deletion ID; `planThoughtTopicDescriptorRows(descriptor,generation)` returns exactly the current four order/expression rows using existing descriptorId/expressionDescriptorId and fields. The existing writeProjection/writeTopicDescriptor writers reuse these outputs byte for byte. These functions allocate nothing and perform no reads. Original descriptorReader and complete original index metadata remain the source of any current descriptor oracle.

Retired/stale row proof cannot use currentcanonical as an older snapshot. The qualifier must match each row to an exact original admitted generation and retained full Topic/Entry/placement snapshots whose revisions/layout and original timestamps produce that descriptor. A generation lacking original retained build/snapshot evidence is refused, including orphan/retired data until the existing original cleanup owner has qualified it. Index metadata sourceCursor/build counters, active/building/retired generation relationships, original completedAt and timeRevision require an explicit original metadata read proof; no sender index truth is exported. This second interface needs an actual nonempty descriptor/index-row gap audit and separate narrow approval before extraction/runtime. The earlier index invalidation extraction approval is not this approval.
