## Minimal proposed test-only bridge

1. Preserve exact copies of both complete files under a new fixture directory outside the Node unit-test discovery pattern, and record their hashes. Only after the complete native bridge is approved and registered may their old Node-positive registration locations be moved; the source content and every assertion stay intact. Until then, these two files are knowingly pending environment migration and must not be treated as current-positive Node evidence or suppressed via skipped tests. No runtime trust fallback is introduced to keep fake tests green.
2. Compile each frozen source separately into a temporary MV3 worker module. Allowed mechanical environment changes are only: replace `node:test` registration with a local ordered case collector; replace `node:assert/strict` import with an independently checked strict assertion shim; replace the Node local-storage/fake-IDB imports and the `device()` construction with the original `LibraryDocumentsStore` using actual global `indexedDB` and isolated `chrome.storage.local` prefixes; omit redundant global fake-IDBKeyRange assignment. Preserve all remaining imports to the actual runtime owners and all original functions/callbacks/assertions verbatim. Require exact, single-occurrence guarded substitutions; unexpected source changes fail compilation.
3. Preserve asynchronous lifecycle tests. The existing test-only `setImmediate` task yield needs a documented browser task-queue equivalent, separate from the explicit real `abort`/`complete` event waits. It is never evidence of transaction completion. Keep the actual event-wait assertions and owned deferred gates unchanged; no sleeps or extended timeouts substitute for completion.
4. Use the existing approved native storage harness with `closeArchivePage:true`, actual headless Chrome, fresh temporary extension/profile and network-deny evidence. Load the temporary test module after the existing native storage fixture, preserving production worker bytes and without adding permissions. No accounts or external service calls. Track every actual native database created, close it after its case and clean only the owned temporary profile.
5. Run all14 cases from the first file and all13 from the second, sequentially by complete case. Split the two full files for scheduling if needed; do not divide a case or drop a slow branch. Source is the first gate. A separately reviewed emitted-release pass must use byte-identical current runtime and exact same assertion fixture before claiming source/release equivalence. Do not repeat the already-frozen narrow probe unnecessarily.
6. The strict assertion shim must implement exactly the used methods: `equal`, `notEqual`, `deepEqual`, `notDeepEqual`, `ok`, `throws`, `rejects`. Match strict primitive equality, complete key presence (including undefined), array length/order, prototype-sensitive object comparison and expected rejection predicates/fields; reject unexpected success and wrong error code/name. A separate finite conformance-vector review/run against original Node assert is required before using it as evidence. Reuse an existing proven shim only if these contracts are actually demonstrated. Do not replace body/store assertions with booleans or summaries.
7. Record case names, result, executed assertion counts, native transaction identity, private event trust observations and full source/runtime/fixture hashes in a bounded body-free receipt. Per-case failures remain failures; abort the receipt's PASS status if any case is missing, duplicate, cancelled, skipped or mismatched. Body comparisons execute inside the worker; receipts contain no body text. Original expected error codes and rollback snapshots remain unchanged. No provider ACK or product delivery is inferred.

## Runtime and Node contract split

The original repository now captures the platform IDBTransaction constructor and its db/mode getters at module initialization. A candidate must pass those actual internal-slot getter calls. Native terminal observers require trusted events targeting the exact captured transaction and ignore false events without consuming either listener; only a true terminal event removes them. The private commit assertion requires trusted-native completed status plus original finalization success and unwind. No factory/name/tag whitelist, test environment switch, public DTO or trust-mint callback exists.

Node fake-IDB keeps ordinary store operations and cleanup. It cannot qualify native commit; retention refuses before graph writes through the immutable owner-computed native identity. `human-retention-nonnative-refusal.test.mjs` is the new honest negative contract. It does not replace any of the27 positive native cases. Original readonly semantic witness and generic Core tests remain valid Node checks for their unchanged scope.
