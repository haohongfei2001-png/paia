## Proposed opaque original read proof

`captureHumanCompletedSearch(store, core)` reads exact Entry/Topic/Section owners, full actual search tasks/postings, the search-rebuild fence and complete original revision rows (including every Topic history) in one original readonly transaction, after foundation is already ready. It accepts only a store/Core/repository binding used by the private Human journal. It returns an empty frozen capability held in a module-private WeakMap. Callers cannot supply owners/tasks/hashes/booleans, change a captured version or issue their own proof. No transaction proxy or shadow domain reducer is introduced.

Read bounds are checked before full rows are retrieved:128 rows per original owner family,128 search tasks,32768 total postings and128 Topic history rows, with a combined encoded4MiB cap. These are conservative finite-scope admission bounds, not a claim to support arbitrary datasets or an absolute transient RAM bound. All source IDs must be empty for this private Human family. Source/generated owners remain separately qualified families. A required row beyond any bound refuses, never truncates.

For each completed current owner, require the original `ownerVersion(kind, row)` to equal both its actual `searchVersion` and `indexedSearchVersion`; require no task for that exact owner; compare the complete sorted actual posting set to exactly `planSearchPostings` plus `planSearchPostingRow`, including original IDs, version, tokenizer and source locators. Exact equality rejects missing, extra, duplicate, orphan, foreign and body-containing postings. Inactive rows have the original empty posting set. Completion is local derivation only; no tag/posting is sent as canonical truth.

For untouched unindexed owners, admit only no postings and either no task or the complete exact original `planSearchQueueLocator` delete/offset0 row. Any write-phase/partial delete, stale tag, unmatched task or unsupported owner refuses. Rebuild is absent or exactly original `{id:'library-search-rebuild',phase:3,cursor:null,complete:true}`; incomplete/wrong/extra rebuild fields refuse. No Root/Topic read-index field is exempted by this search proof.

`requireHumanCompletedSearch(t, cap)` rechecks complete captured owners, every task/posting, rebuild and Topic histories in the same captured actual IDBDatabase lifetime and final original write transaction before any domain/Core/mapping/pointer write. A search writer changing only a local tag/posting/task after prepare must abort the whole original transaction. No hash/WebCrypto/tokenization is performed inside final IDB; expected projections are prepared outside.

## Narrow outgoing projection and original transition constraints

`projectHumanSearchRow(cap, namedPlan, type, row, phase)` may omit only the literal key `indexedSearchVersion` from a qualified current Entry/Topic/Section full row. It must bind both actual captured before and the existing opaque original named plan, not accept a DTO after snapshot. Before must match the full captured original owner. Planned after may retain that same tag while its canonical version advances; this is the exact existing typed owner transition, not a requirement that future tasks/postings already exist before commit. Every other semantic/local/unknown field remains subject to original required-codec refusal and complete before CAS.

Topic history leaves require explicit named `history.before` / `history.after` handling before identity portability. The original owner journals before queueSearch/touch; actual history.after differs from the final canonical Topic in negativeUpdatedSequence/searchVersion/updatedAt/countVersion. Those original differences remain intact. The projector accepts exactly CANONICAL_BEFORE and CANONICAL_AFTER for a complete original member row; a Topic history member then handles its explicit before and after leaf phases internally. These are the originally designed TOPIC_HISTORY_BEFORE and TOPIC_HISTORY_AFTER distinctions, not separate caller-selectable phases. A private accessor inside the existing plan module, `humanSearchPlanWitness(namedPlan, store, core)`, must verify the original opaque plan's store/Core binding and return exact original per-member rows plus its actual planned history leaves, without reconstructing or reducing a snapshot. The qualifier accepts a history leaf only if it equals that exact phase's original leaf, its corresponding Topic before equals the full captured completed owner, and the copied tag is exactly that captured owner tag. It never compares history.after to final p.topic or deletes the four phase fields to make them equal. Existing coalesced before-images that cannot meet this narrow witness remain refused. Receiver differences that alter original coalescing/member identity must likewise refuse before writes rather than edit the original journal rule. No recursive derived-field remover, suffix/prefix match or change to physical-field mapping is permitted. Existing retained history containing a tag without a matching full qualified snapshot/typed transition refuses. Thus this first cut may reject a later reindexed/history-heavy dataset; that limitation is retained, not called full search portability. A later admitted same-dataset ancestry `(kind,id,ownerVersion)` witness design must qualify older full snapshots and historical local tags separately.

Incoming top-level and deeply nested `indexedSearchVersion` always refuse under the required codec. A sender proof never qualifies receiver metadata. Receiver preparation uses its own capture/typed plan/projection, preserves or invalidates its own local completion through the original writer and exact final CAS. An empty receiver has no completion claim. No canonical body/history/ID/revision changes to satisfy portability.

Grouped scope remains refused for completed indexing until its actual compiler/scope owner is integrated with the same qualified proof. Existing `compileHumanScope` keeps only latest after rows; broader partial/older support must add bounded full before/after ancestry witnesses and bind every raw task/posting/rebuild to those exact snapshots. No generic exemption to make full recovery pass.
