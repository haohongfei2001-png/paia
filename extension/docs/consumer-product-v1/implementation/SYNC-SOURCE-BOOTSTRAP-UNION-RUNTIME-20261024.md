## Exact scope

This cloud-only synthetic slice binds the existing RESTORE / CONTINUE lifecycle to the original grouped owner for exactly two Source-bootstrap-only heads with one exact common direct parent and disjoint original identities, into an empty canonical target. It does not create a remote manifest during recovery or treat the typed local selection as an application-selection grant. Unsupported families, conflicts, nonempty targets, protected/native generation paths and follow-on local edits remain refused.

The existing initial lifecycle reservation, discovery, both original heads and ancestor, local selection CAS, parser/compiler, grouped staging/atomic activation and confirmation share one original 4096-reference / 2 MiB / 30-second invocation ticket. A shorter configured read interval only tightens the existing deadline. Cold CONTINUE retains the exact local selection and restore ID, reauthenticates the owner's durable receipt, and does not re-download a completed or validated union unnecessarily. Paused / uncertain local-storage outcomes are never treated as rollback or permission to repeat a write. Native activation already proven successful remains reported as restored even if its subsequent lifecycle confirmation fails.

Provider reads retain the original cancellation/deadline wrapper. Nested owner and local-receipt awaits use a private set of live cancellation callbacks, with no replacement timeout or new ticket. The UI/application-selection PREPARE / ACTIVATE / CONTINUE / RESTART route is unchanged.

## Genuine subsequent publication

Publication consumes two parents only after the original atomic union activation and exact cold provenance are proven under the discovery ticket. The original encoder then produces a real checkpoint with both authenticated original head IDs; original revision retention is checked against each parent. A missing sibling, empty replacement inventory, incompatible successor, or advanced remote cut whose operations are absent locally is refused before any upload. A genuine later sole successor is admissible only when its authenticated ancestry includes both original sibling heads. Late upload acknowledgements retain the same publication identity and use original readback rather than duplicate POST.
