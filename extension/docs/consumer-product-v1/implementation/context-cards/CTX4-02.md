## Compatibility and protection

`put.card` accepts only `info`, `rules`, or `now`. Omitted card still means Info;
request bytes are not normalized before hashing, so old operation IDs/digests
and recovery envelopes remain valid. A stable Item cannot move between cards.
Unknown pending writes cannot switch card, target, action, epoch or access intent.

All admitted Items remain explicitly manual, protected and user-edited. Automatic
or protection-override fields and automatic operations are rejected; future
maintenance still requires its separately authorized service and typed writer.
Delete/restore retain the same tombstone, revision and exact-deletion fence.
Receipts contain no second body. Source-free Rules/Now drafts follow the existing
purge admission and recovery contracts; they do not gain source linkage.

The additive row keeps schema/database version unchanged. Old Info rows need no
rewrite and their exact receipts replay. New Rules/Now rows require this reader;
a pre-expansion build rejects unsupported row contents rather than silently
removing those Items. Product version/release identity is coordinated at eventual
integration; no user database or running installation has been changed here.

## Local product behavior

All three details display only their own durable Items, natural stored group
headings, card-specific add/empty/editor copy, and exact counts on the four-card
home. Manual basis stays optional in the existing overflow action. Enter inserts
a newline; Control/Command+Enter requests save; composition defers commit.
Failed/conflicting drafts remain in place, and keep-as-new retains the same card.
A failed destination read replaces only the already-approved outgoing page with
a truthful retry state; a failed in-place refresh retains its exact dirty editor.

Global/Card preferences preserve all lower choices. They grant no currently
usable connection: connections remain zero and external/automatic capabilities
remain false. The Connections page truthfully shows unavailable/empty content,
with normal Back, reload and Settings-return behavior. Inputs remains unavailable
pending its own Topic slice.
