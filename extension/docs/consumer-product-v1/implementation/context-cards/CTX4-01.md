## Minimum persistence decision (architecture schema questions)

1. Product need: approved manually editable Info/Rules/Now Items cannot be represented by the former Memory selection/projection or an existing Source/Input/Thought without violating independent ownership. This stage admits manual Info only.
2. Existing storage suffices: one versioned bounded `context-cards:v1` row in existing IndexedDB `meta`; existing `operationReceipts` contains body-free commit acknowledgements. No object store, DB version, schemaVersion, full-corpus copy or archive migration is added.
3. Owner/invariants: stable UUID per Item; body, section, revision, human protection, removal state and delete token atomically commit with receipt. Expected revision prevents stale edits and deletion resurrection. Restore is explicit and token/revision checked. Access keys have independent revisions, all default off.
4. Compatibility: missing row reads as an empty/default-off projection without writing historical data. Existing Memory/Profile/grant rows are neither imported nor unioned. Invalid/unknown Context row fails closed and is not replaced.
5. Upgrade/rollback: current DB remains version 5; introduction is additive and idempotent. Older runtime ignores the namespaced row; ordinary rollback leaves it intact for reopening with this runtime. No downgrade or destructive migration is performed. Existing-file Archive restore retains the independent row (it is outside the legacy Backup allowlist), invalidates old write/draft sessions through the existing restore epoch, and never imports external access. Old backups do not include these new local Items; no backup/export generation is reopened.
6. Bounds: 512 total active/removed Items, 8,192 UTF-16 code units per body, 1 MiB total serialized row. Reaching limits refuses the transaction and retains the editor draft. Removed Items retain their manual body for local explicit Undo; they are not externally readable or silently purged. Permanent-delete semantics are not expanded.

Source/Working Input/Thought bodies, IDs, timestamps, revisions, provenance and tombstones have no mutation path from this owner. No Topic body/interface is needed for this stage; Topic selection remains unavailable. Recovery uses the existing bounded local recovery store, explicit `context_item` admission and epoch/owner checks; it does not claim unlimited crash recovery.
