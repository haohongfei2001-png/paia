## Implemented bounded scope

Ordinary existing automatic Context Items whose complete old evidence is inside
the exact selected child scope now receive metadata-first independent field
authorization, original bounded lineage qualification and a sent-state baseline.
The formal source response adapter maps UPDATE, REMOVE_CANDIDATE and checked
NO_CHANGE back only to this private baseline. Model output cannot create grants,
epochs, source identities or arbitrary old Item references. Original protected,
manual, removed, stale and invalidated-state rules remain effective.

The original Topic and Context writers retain exact before/expected-after
publication capabilities from their original write intents. Only their actual
joined transaction and successful ACK can advance the sent root/graph baseline.
The Context owner freezes the expected target before the first put and retains
the Input/Source fence through receipt, ACK and counters. All already-granted
child Inputs are fenced when a legal new whole-Input mirror can join an old
Topic; this does not expand the Item's checked provenance or NO_CHANGE coverage.

ADD / UPDATE / REMOVE_CANDIDATE / NO_CHANGE require exact original successful
dispositions. Protected/removed/duplicate responses do not pretend to complete
ordinary writes. The original explicit human-correction protected no-change
exception is preserved. Per-child completed/deferred/error material is released,
while genuine storage rollback retains the verified original command for a
same-response local retry without another provider dispatch.

The reader uses the original shared ceilings across phases, including 20 Items,
16 evidence identities, 8 Topics, 128 Sources and the original work/byte limits.
An actual 131,071-read preflight followed by the original lineage read proves
cumulative exhaustion refuses additional body reads; no fresh per-Item budget or
increased ceiling is used.

## Explicit remaining boundaries

1. Cross-source old-Item semantic retrieval is not implemented by this same-scope
   slice. New independent Inputs correcting another source's old fact need a
   bounded independently granted old-state retrieval path.
2. A new partial-excerpt Entry without its own Entry field authority is refused
   before an original Context owner could read its body. The joined Topic write
   rolls back with zero current-child ACK. It is neither a completed Topic nor a
   submitted explicit Context DEFER. Supporting separate facet progress is
   continuing implementation, not a reason to weaken the boundary.
3. Known STORAGE_FAILED/STORAGE_FULL intentionally retains local retry material.
   Currentness/expiry is checked on subsequent access and host revocation. An
   idle expired grant without another run or host abort has not been proved to
   reclaim that retained material automatically. No automatic idle-expiry or
   JavaScript heap-erasure guarantee is claimed. A bounded lifecycle follow-up
   will test the actual contract before adding background machinery.
4. Default-null production configuration remains. Real identity, processing and
   signed entitlement, model-specific tokenizer/profile, endpoint/region,
   resources, allowance and CTX4-06 real client/transport are not active.
5. Current R3/YEAR-HARMONY source is preserved. Full visual, interaction,
   performance, source-release, supported-source, real quality/billing and final
   user acceptance remain open. No new Sync features or historical mobile scope.
