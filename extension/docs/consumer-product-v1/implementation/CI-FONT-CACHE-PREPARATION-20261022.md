## Exact scope and mechanics

Only three implementation files: `.github/workflows/paia-certification.yml` current_browser font block; dedicated `extension/scripts/prepare-browser-fonts.py`; existing `extension/tests/cpv1-02-hosted-browser-setup.test.mjs`. All workflow bytes outside that block compare identical to the base, including the18-minute job budget, ten shards, every test, Chrome selection/smoke, other jobs, original source rewrite and permissions. Original fc-list/fc-match commands are verbatim. Two optional cache transport steps alone allow failure, each timeout1 minute; restore segment timeout1 minute. Original strict non-cache failure assertions remain scoped to all other steps.

1. Create a **fresh** private lists/archives state; an existing state is rejected. Native `apt-get update` uses the same configured sources/keys and `APT::Update::Error-Mode=any`, disallows unauthenticated/insecure/downgraded repositories and uses no old package cache files. A signature/index failure is terminal. No cache is consulted before that succeeds.
2. Native `apt-get --print-uris --download-only --no-install-recommends install` resolves the two original requested fonts and actual download dependency closure. Match each returned URI/filename/size against current `apt-cache dumpavail` metadata, requiring unique package/version/architecture/SHA256. The printed MD5 is **not** the integrity authority. A missing or ambiguous current record fails closed. No dependency solver is reimplemented; preinstalled packages do not bypass the final APT install or font checks.
3. Exact cache key covers policy, original requests, ImageOS/ImageVersion, OS identity, native architecture and the entire resolved archive metadata/URLs. Restore has no restore-keys. A returned partial/mismatched key is a miss even if bytes are present. Cache contains only deb bytes, no trusted manifest/lists/expanded fonts. Restore is into a separate user temporary directory, never sudo into a system path.
4. Before APT receives a hit, require the exact file set, safe flat filenames, regular nonlinked files, size/SHA256 and dpkg-deb package/version/architecture (including `all`). Validate copied private staging again. Corrupt/missing/extra/linked/mismatched/timeout restores go through **one** original native download-only acquisition, with no script retry loop. It must verify against the same fresh plan. A changed prepared host/policy fails.
5. Native `apt-get --no-download --no-install-recommends install` performs actual dependency/authentication/configuration handling from staging. Install/configuration failure is fatal, never converted to a cache miss; original font commands follow unchanged. No dpkg install bypass or alternate mirror.
6. Restore/save are separate first-party actions. Save is limited to existing push-main events, verified acquired bytes and successful font step; PR only restores. Both use the same cache path so the cache version can match. Bad local restored bytes are moved to private rejected-cache evidence; no remote cache is deleted/overwritten, no credentials/permissions/prewarming or third-party generic APT cache action added. Save preparation/transport failures do not mask the original APT/font result. An unsafe cache parent is not written; native acquisition still runs and save stays disabled.

Native semantics consulted: [APT get manual](https://manpages.debian.org/trixie/apt/apt-get.8.en.html), [APT cache metadata manual](https://manpages.debian.org/trixie/apt/apt-cache.8.en.html), [first-party cache documentation](https://github.com/actions/cache). These inform preparation, not evidence that the Ubuntu hosted combination has executed.
