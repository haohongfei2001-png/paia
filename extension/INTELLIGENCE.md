# Intelligence v0.11.0 — pre-registered evaluation

Baseline: immutable 3a58fcd1 / v0.10.1 enhanced lexical. No runtime ranking changes before dataset freeze and baseline execution.

Synthetic only. At least 100 Topics, 3200 Entries, 800 queries; A exact, B overlap/short, C Chinese paraphrase, D no-overlap/cross-language synonym, E long, F ambiguous, G temporal, H conflict. Explicit relevant ID sets, type and currentness labels. Report hit@1/3/5, precision@3/5, recall@10, MRR, per taxonomy and development/held-out domain split. Repeated templates are disclosed; this is not blind human evaluation. Also run v0.10.1 fixed 240 queries unchanged.

Pre-registered production gates: exact Top-1 must not decrease; C+D recall@10 increase >= 5 percentage points to adopt a semantic model; overall MRR no more than 1 point loss; no authorization, budget or provenance violations. Generic deterministic quality changes require >= 2 point Top-3 or MRR gain without exact regression. Independent performance-only changes require identical rankings and >= 20% median improvement. No more than 12 generic acronym/synonym groups, 150 new runtime retrieval lines, no domain-specific dictionaries, no query-specific rules. At most 3 candidate tuning rounds, then freeze.

Model gates: <= 32 MiB packaged model assets, <= 200 MiB additional peak working memory, CPU/WASM without WebGPU, first use <= 5 s, query p95 <= 500 ms at 10k, 50k bounded index build <= 120 s, <= 50 ms UI task slices, zero production network. Model loading must be lazy; failures retain exact lexical path. If a candidate cannot meet entry gates, record not measured / rejected rather than invent scores. Never download hundred-MB models just to finish a benchmark. Prototype dependencies/models remain outside release.

Confidence is an ordinal lexical-coverage diagnostic, not calibrated factual probability. High does not certify completeness/currentness. Low warns in Preview; no user-facing float, no automatic Provider fallback. No-result is valid. Existing authorization-first, deny-wins, stale fences, source deletion, hard budgets and provenance remain mandatory.

Research: small model only feasibility; LLM fallback only future explicit one-request design. Production choice is exactly one path. Vector lifecycle requirements apply if adopted; otherwise no vector store/migration/rebuild controls in runtime.


## Final production architecture

Choice A: lexical-only optimized. Authorization and source deletion fences run first in MemoryService; a single invocation-local prepared query is reused across the already permitted Entry candidates. Scoring, exact path, stable ordering, currentness, provenance and budget selection are identical to v0.10.1. No persistent text cache, IDF table, model, vector store, new permission, WebGPU dependency or automatic Organizer work. Global Search is unchanged.

Confidence: high/medium/low is lexical coverage of the leading candidate, downgraded when near-equal candidates belong to different Topics. It is not a correctness probability. Low shows “可能没有找到完整相关内容” in Preview; zero result stays empty. A partial 20k scan always reports low, including a distinct scope-limit explanation when empty. Medium keeps existing budget-bounded candidate breadth. No confidence state invokes a Provider. Removing items cannot add new content. Explicit current wording only wins equally relevant historical text; questions/possibility remain uncertain even with a new timestamp. G's current-first is 95%, because a source explicitly saying “可能” correctly stays uncertain. H's conservative multi-expression warning is 100%; neither claims automated contradiction understanding.

Prepared query state exists only during the synchronous call. Nothing new needs index rebuild, corruption recovery, incremental embeddings, backup exclusion or migration. Existing IDB indexes/lifecycle remain. v0.11 backup headers are accepted additively; old formats remain supported. The 20k placement cap is retained: at 50k, entries outside the scanned range may not be found. User can narrow permitted Topics. This is recorded as a limitation, not a 50k complete retrieval claim.

## Benchmark interpretation and reproducibility

Dataset is authored synthetic, 20 scenarios × 5 neighbouring Topics × 32 Entries = 3200, with 800 A–H queries + 20 negatives + 4 mixed/acronym/punctuation/typo probes. Types include fact, preference, decision, judgment, question and plan. Each Topic includes history, explicit current wording, uncertainty and excluded replicas. Broad repeated relevant statements appear in other Topics, so ground truth includes ALL eligible matching statements, not merely the intended Topic. A/B/C/D often have >10 valid records; standard Recall@10 therefore cannot approach 100%. Hit@10 is reported separately. F has many valid answers. Entries are repetitive/templated and judgments self-authored; withheld domains are not independent blind validation. No claim of real-user semantic generalization. P has only four probes, not robust typo evaluation.

Fixture digest and baseline were committed before candidates (4639e43). No dataset/label tuning after freeze. Two generic R&D variants were tried: IDF+hierarchy coverage and six standard acronym/punctuation replacements; neither passed the quality/latency gate. No domain dictionary, query-specific case or endless tuning. All 824 full ordered item objects/scores were then compared against frozen v0.10.1: exact equality. Alternating same-process timing confirmed >20% improvement for query preparation reuse. Original v0.10.1 240-query benchmark is rerun unchanged as a separate continuity check. New scores are not directly comparable to its easier single-target 97.9% Recall@10.

Run from this worktree with Node: `node experiments/intelligence-v0110/run.mjs`. Set PAIA_RETRIEVAL_MODULE to a frozen baseline checkout's core/memory/retrieval.js; PAIA_BENCHMARK_OUTPUT chooses receipt. Candidate modules are in experiments, outside all package allowlists. `parity.mjs` compares full ranks with the sibling frozen checkout. `export-lexical.mjs` writes synthetic top-100 lists for R&D fusion. File receipts contain no real user text. Final tables are in outputs/v0110-acceptance/decision.json and benchmark reports include every query's ground truth ID result, exact metric definitions in run.mjs.

## Local model research and rejected prototype

Public model download was an explicit development step, pinned to minishlab/potion-base-2M revision 389b9f64be5aa4ae7a6bc6fe95ef20ce485ae5da, 7,559,256-byte weights + tokenizer/config (~7.9 MiB together), SHA256 in model-assets.json. The English static embedding model was run on CPU locally with model2vec 0.7.0, network sockets blocked after preparation, no user data and no Provider. No hundreds-MB model was downloaded. Lexical, vector-only (diagnostic ablation), and exact-preserving lexical+vector RRF-60 were measured on the same queries and allowed pool. Vector/hybrid failed quality clearly; model load, 1k/10k/50k build/update/query/RSS are measured in vector-prototype.json. These are Python measurements, NOT browser/WASM/Intel results. Rejected before browser integration, so Chrome model cold-load/startup/WebGPU fallback metrics are N/A. No claim that all browser embeddings are unsuitable; only these evaluated options failed this gate.

The R&D index holds id→vector only, wipes obsolete arrays on remove/update/purge/clear, rejects nonfinite/wrong-shape vectors and excludes vectors from canonical backup design. It is ephemeral and never wired into PAIA. Prototype candidate pool is prefiltered synthetic eligibility, not independent proof of authorization: production authorization/shared-entry/never/source-purge invariants are verified separately in service/Chrome regression. No R&D vector state survives into release, restore or a user's extension. Since the model is rejected, no lifecycle UI or alternate production path is shipped.

Official sources consulted 2026-09-09:

- https://huggingface.co/Xenova/paraphrase-multilingual-MiniLM-L12-v2/tree/main/onnx — multilingual int8/quantized 118 MB, exceeds 32 MiB asset gate; not downloaded or benchmarked.
- https://huggingface.co/minishlab/potion-multilingual-128M/tree/main — 512,361,560-byte F32 weights plus tokenizer; exceeds size gate, not downloaded.

- https://huggingface.co/onnx-community/Qwen2.5-0.5B-Instruct/tree/main/onnx — small generative-model feasibility reference, not executed. No measured task justifies adding generation/intent/reranking complexity in this release.

## Future boundary, not a hidden feature

A future user-clicked semantic recovery could make exactly one Provider request after showing authorized selection/estimated cost; external master switch, global never and Entry/Section exclusions checked before projection and again before use. Query/Thought subset would be size capped; no Source body, credential or unrelated Profile data. A generation fence invalidates stale responses. Output could suggest candidate IDs only, validated against that authorized projection; no automatic fact rewrite, Topic merge or promotion of history to current. Timeout/failure ends the attempt, no auto retry. This is a design only: no new endpoint, button, request, cost or silent download in v0.11.0.

Lexical works offline on CPU without WebGPU and is the sole production path on Intel/Apple Silicon/low-memory devices. Tests ran on the current Apple Silicon host; Intel and constrained-memory hardware were considered, not falsely claimed measured. Rejected model fallback does not exist in runtime; future enhancements must retain lexical on load/corruption failure and load lazily after ordinary pages are usable. Topic quality reuse/global semantic Search remain deferred.


## Chinese model cross-check

A later bounded research cross-check found Xenova/bge-small-zh-v1.5 quantized at 24,451,050 bytes including tokenizer/config, within the asset gate. It uses Chinese BGE weights, ONNX Runtime 1.23.2 CPU (one inference thread), CLS pooling and L2 normalization, plus the model author's recommended query instruction. Same frozen corpus, labels and RRF-60; no query-specific tuning. Official sources: https://huggingface.co/Xenova/bge-small-zh-v1.5/tree/main/onnx and https://huggingface.co/BAAI/bge-small-zh-v1.5 . Pinned revision/hashes in bge-assets.json.

This is a materially stronger option than the English static model: hybrid Top-1 86.625%, Top-3 89.625%, MRR 0.8872; C Hit@10 85%, D Hit@10 55%. It DOES improve semantic ranking. It is still not production-ready: 0/20 no-result probes abstain; C+D mean standard Recall@10 improves only 1.93 points (pre-registered requirement 5 points); 50k build took 268.9s against 120s gate. Total Python process peak RSS 403.6 MiB is reported honestly, not compared as if it were additional Chrome model memory. Timings ran alongside headless regression and are host-load-dependent; no isolated-browser timing claim. Failure to abstain is independently sufficient to reject this uncalibrated prototype. No threshold tuning on the test set to force acceptance.

Production choice A stands; semantic capability is promising R&D, not dismissed as universally useless. No BGE asset/runtime/index enters the packages. Browser model loading, WASM, progressive indexing, memory ceiling and hardware lifecycle are NOT validated because adoption gates failed first. Small generative models remain unjustified; they do not repair uncalibrated retrieval automatically.

Prototype lifecycle results concern a separate id→vector helper whose obsolete arrays are zeroed; the benchmark matrix is a static synthetic evaluation buffer, not a Source-service index. These checks are not proof of integrated Source purge/restore or authorization lifecycle. Production has no vector state to invalidate or back up, and actual canonical safety is covered separately by regression.

The hardening regression also exposed a real UI timing issue: passive status refresh could revert the AI-view checkbox while its local preference save was pending. The switch now retains the requested visual state, disables overlapping user clicks while saving, serializes programmatic switches, and restores the old state on failed persistence. A delayed-response/failure test reproduces the old problem and verifies rollback with zero Provider requests. This is a view preference only, not an AI action or retry.
