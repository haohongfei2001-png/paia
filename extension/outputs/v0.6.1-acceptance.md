# v0.6.1 Smart Filter internal — 验收报告

日期：2026-09-07。独立分支 `codex/smart-filter-v061`，基于冻结的 `01a6350`；本次仅交付 internal candidate，未部署到日常 Chrome，未读取或修改真实用户 IndexedDB。未继续 Thought Library Organizer。

## 实现结果

- 默认轻度 / 关闭；仅完整且高度确定的继续、重试类操作输入可以被过滤。附加限制、选择、否定、事实、观点、问题、引用和未知语境保留。“好的 / 可以 / 是的”不靠关键词过滤。
- 阅读默认隐藏有效过滤结果；全文搜索包含被智能过滤但未被用户删除的输入，以低权重“智能过滤内容”标识，并支持临时上下文查看。搜索命中不产生人工保留意图。
- Settings 提供最近过滤内容、搜索、分页及恢复。用户修改正文或备注、恢复、明确保留产生永久保护；输入后立即 Undo、尚未自动保存的情况也受保护。标题修改不会把整个 conversation 全部标成人工编辑。
- 文档使用固定阅读快照与安全应用边界；后台迟到的判定不会让正在阅读的正文消失。文档内无过滤按钮、AI 图标、隐藏计数或占位条。首页数量代表完整收录数量。
- 升级前存在档案时显示一次弱提示；空白新安装不提示。
- provider-agnostic 分类契约和评测基准已具备，runtime provider 注册表为空。未引入语义模型、模型下载、AI Organizer、AI Memory 或新 History Completion provider。

## 对抗评测与适用限制

524 个合成案例，过滤 6、误过滤 **0**；该测试集观察 precision=100%，过滤占比=1.145%。覆盖混合信息、短判断/诗句、选择/限制/否定、引用、Unicode、附件/引用存在性、人工保护和未知历史证据。

只有 6 个正例；这不是独立用户标注总体样本，也不证明生产环境 99.5% precision 或实际档案的过滤覆盖率。初始语法刻意很窄，缺少可信 presence/authorship 的旧档案不会因升级被自动隐藏。没有通过降低门槛换覆盖，也未为模型存在而引入模型。

## 性能

本机 Chrome 合成 IndexedDB 单次观测，不是延迟 SLA。查询为有限页，不是整库搜索耗时。

| 输入规模 | Smart Filter 增量迁移 | 读取 20 条 | 评估 100 条 | 搜索一批最多 200 条 |
|---|---:|---:|---:|---:|
| 1,000 | 171 ms | 4.0 ms | 25.0 ms | 20.9 ms |
| 10,000 | 1,859 ms | 89.8 ms | 27.5 ms | 21.9 ms |
| 100,000 | 22,167 ms | 98.7 ms | 32.2 ms | 27.9 ms |

每次最多评估 100 条；生产每次唤醒最多四批，持久化 pending，后续已接受请求继续。无额外 alarm 权限。过滤失败不会撤销成功捕获；未知或失效判定显示正文。大库首次增量迁移耗时仍需纳入升级体验预期。

## 隐私、权限与依赖

无新增权限、host 范围或外部网络请求；无遥测、云分类、模型下载和 token 费用。最小 presence metadata 仅枚举与可信度，限定已合格用户 turn、最多 256 元素，不读取附件内容、文件名、助手正文或额外 URL。缺少完整可信边界则 unknown。

Source / time / import 原算法保持冻结；canonical adapter 仅增加合格输入后的可选 presence helper 调用。过滤元数据与正文、Revision、用户移除和永久 tombstone 分离。后端仍为唯一持久写入入口，过滤命令拒绝网页/内容脚本伪造。

既有 Thoughts 不因可见性设置而被改写或删除。未来 extraction 默认只接受可见主输入；filtered 仅可作为有可见同文档 anchor、最多两条邻近范围内的 context_only。被用户移除或永久删除的来源不能通过该入口恢复。
