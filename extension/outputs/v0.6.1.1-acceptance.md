# v0.6.1.1 Smart Filter Diagnostics internal — 验收报告

日期：2026-09-07。基于冻结 `f3fa0e7`，独立分支 `codex/smart-filter-diagnostics-v0611`。实现、自动测试和隔离 Chrome 验收完成。未部署日常安装，未访问真实用户数据库。

## 修复结论

确认 v0.6.1 存在历史漏排队 bug：旧 Input 初始化为 pendingKey=1，而后台只读取 pendingKey=0，因此 Light 开启并不代表历史已经评估。本次一并修复每次外部请求四批上限导致的续跑依赖，以及任务收尾时新 capture 到达可能错过唤醒的并发边界。

不能由此推断私人档案实际应过滤多少条。旧证据仍为 unknown 时，实际检查后的判定仍为 uncertain 并保留。未扩大规则、降低阈值、过滤无语境确认词或加入 semantic classifier。

## Settings 交付

Settings → Input Archive → 智能过滤显示全部指定项：Light/Off、Active Input、已检查、待检查、Keep、Filter、Uncertain、User protected、Failed、Filter 比例、filterVersion、policyVersion、classifier/rules version、后台检查时间和 idle/running/paused/failed。

字段值只含数字或固定枚举。后台检查时间采用 Unix ms，0 表示尚无完成的检查时间。诊断接口有明确字段白名单，不返回正文、标题、URL、来源/消息身份、内容 hash 或原始异常。

计数口径：active=checked+pending；checked=keep+filter+uncertain；userProtected 是 keep 子集；failed 是当前失败且仍待处理的子集，不是累计失败次数。移除/分支输入不计 active。Off 下保留有效 Filter 计数，表示再次启用 Light 时可复用的判断，不表示 Off 当前隐藏了这些内容。

统计每次最多读取 100 行，在事务之间让出执行权。并发修改会导致重新取样；三次仍无法取得一致计数时显示“统计暂不可用”，不展示半成品数量。Settings 每两秒尝试刷新，单请求在途；阅读文档不轮询诊断。

低频入口“检查尚未处理的历史输入”可修复缺失、失败或失效工作；正常初始化和续跑无需点击它。有效缓存、用户保留意图、正文及删除语义不受影响。

最近过滤列表现在会跨过没有有效条目的中间页。无过滤结果时显示“目前没有被轻度智能过滤的内容。”，有搜索词但无匹配时另显示搜索空态。

## 迁移和后台

保留物理 IndexedDB v4、原控制 schema6、Smart Filter migrationVersion=1，新增 diagnosticsVersion=1 元数据修正标记。修复过程沿用持久游标和 100 行事务；只写 Smart Filter 元数据，不重建 Source、Input、Revision 或导入状态。

FilterRunner 每批评估 50 条，批次间让出执行权。worker 启动/安装及已接受活动会自动继续；失败保存固定状态和待处理行，显式恢复或下一次 worker 启动可重试。MV3 worker 被终止时执行会暂停，持久队列由下一次启动继续，不依赖用户把恢复按钮当正常流程。没有新增 alarm 或网络权限。
