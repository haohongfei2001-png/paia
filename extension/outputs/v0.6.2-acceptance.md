## 2. Deterministic 改进

filterVersion=1；policyVersion=2；classifier/rules version=`deterministic-light-2`；reasonTaxonomyVersion=2。

历史 attachment/reference 未知不再一律 uncertain。只有完整命中纯控制语法、无人工保护或已知附件引用时，才允许候选通过。未伪造 verified metadata；缺失/损坏的编辑状态、malformed presence 仍保留。已知附件/引用、userEdited、恢复和 keep override 均优先。

语法分为 pure_continue / pure_start / pure_retry / pure_regenerate，支持批准的中文表达、礼貌前缀、有限语气词、标点和简单英文变体。整句必须完整匹配；问题、否定、选择、限制、引用、创作/引号/结构化内容及附加条款不进入过滤。Unicode 同形字不会通过英文大小写折叠混入语法。

## 3. Semantic classifier spike

**不加入 runtime。** 实验使用本机 Apple NaturalLanguage 的 sentence embedding，加上少量合成原型，分类 pure_control / substantive / ambiguous。它不判断重要性、思想价值或记忆价值。API 依据：[Apple NLEmbedding](https://developer.apple.com/documentation/naturallanguage/nlembedding)。这是离线语义原型，不是已经训练、校准和验收的专用分类器。

2,444 个合成样本（原评测集加 12 个另列的控制释义）结果：原始 top-1 标成 pure_control 的 1,039 例中，**873 例其实应保留**。原始模型额外识别了 10 个正例，但这些不构成可接受增益。仅应用已识别的保护词也不足以保证安全，因此模型契约不允许它越过已验证的完整控制边界。

使用 0.995 分数门槛时没有任何样本获准。confidence 是未校准的 cosine-softmax score，不是 precision；零接纳不是“模型达到 100% 精度”。相对 deterministic-only，**可接纳增量收益为 0**。confidence=1 的恶意 provider 也无法覆盖所有合成负例/硬保护条件。

此外，这个原型依赖 macOS 原生 API，不能作为 Chrome JavaScript provider 直接分发。本轮未引入 nativeMessaging、模型下载、云 fallback 或额外权限。结果仅说明这个原型不适合接入，不代表所有未来语义分类方法都不可行。
