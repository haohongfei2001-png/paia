## B. Recommended design

Chosen story: **Our family cookbook / 给家人的食谱**. All people, words, dates and conversations are fictional. A person wants a family gift, decides to preserve their mother's own phrasing, narrows the project to six recipes, and returns weeks later to write the first page. PAIA saves the person's inputs—not generated recipes, assistant replies or an entire chat. The recovered constraint changes what they write next.

Writing/learning/research alternatives were considered: research is credible but specialist; generic writing is broad but lacks a memorable constraint; career decisions introduce unnecessary sensitive-data connotations. The cookbook is a bounded project with ordinary language, repeated decisions and a concrete reason to preserve one's own words. It is one example, not a claim about target-market demand.

Home: direct AI-input proposition and retained three-space product window → an explicit answer to “Why not just chat history?” → an already-open Topic with continuous original expressions → an intentional reuse moment inside a ChatGPT-shaped page → compact privacy/availability and invitation. No new product dashboard, graph, timeline, task packet, approval inbox or AI service is designed.

Demo: complete operations on the same fictional material. Original/working text, Find, Topic Root/Section reader and manual edits remain. The narrow board demonstrates local frequent wording, same-width Archive search, exact-text inspection before using clipped text, user-controlled open/close, safe draft insertion and manual management. Pro is explained as unavailable, never simulated as a live recommender. Context starts globally/cards/topics closed and is an explicitly page-local scope illustration.

Desktop preserves the asymmetric text/product composition and readable paper-like surfaces. Mobile uses horizontal space tabs and readable selected content rather than a scaled desktop screenshot, gives the reuse scene its own compact composition and keeps actions reachable. Motion explains tab/operation changes; there is no autoplay story, forced tour, send action or completion timer.

## C. Validation protocol

Expert first-visit walkthrough, not recruited-user research: check product/category within 5–10 seconds; a concrete difference from history within 30 seconds; visible old-words-to-new-draft payoff; demo/real-product separation; reachable demo and application. No measured comprehension, desire, conversion or retention claim will be made from this exercise.

Engineering gates preserve existing source safety, permission isolation, no-network/no-persistence, forms, all routes and SEO. ## D. Completed implementation and real verification

Final implementation preserves the existing exterior rather than replacing it.
The home and independent Demo now have different jobs, sharing only the fictional
material and the narrow-board component. No extension or product authority file
was changed. Product source/working-body separation, Topic Root/Section reading,
Context4 independence, forms, routes and service boundaries remain intact.

The accepted browser gate ran **6,205 checks, zero failures**, Chromium
**154.0.8037.99**, using actual local HTTP and the generated assets. It covered
all **48 HTML routes × 1440/768/390/320px**, 320px at **200% text**, EN/ZH mobile
and desktop journeys, default/reduced motion, forced colors, keyboard/focus,
no-JS reading, source immutability, current-body search, draft/selection-safe
insertion, default-off/independent permissions, unexpected requests and beta
form validity. The beta form was **not submitted**. Build determinism checks all
50 generated files; JavaScript syntax and whitespace checks also passed.

The added axe-core **4.10.3** audit completed **78 scans**, with **zero identified
violations** after fixes. It includes both languages, 1440/390/320, home/Demo/beta/
status and selected hero, reader, candidate, edit, search, inspection and Topic
permission states. Its **78 incomplete review groups are retained**, mainly
because gradients/translucent layers or overlapping illustration elements prevent
automatic contrast determination. This is not a blanket WCAG or screen-reader
certification. Raw findings and bounded CSS-color calculations are included.
The primary button's lightest blue was darkened: white-text contrast at that stop
improved from **4.013:1 to 4.955:1**. Selected body, metadata and large-title color
pairs were separately calculated; these samples do not certify every rendered
pixel or untested state.

The font-free offline prototypes passed **8 page/viewport smoke scenarios**:
EN/ZH home and Demo at 1440 and 390, opening Topics, taking exact wording through
inspection into the local draft, no horizontal overflow, no JavaScript errors and
no external network requests. The real-site screenshot set uses the repository's
existing fonts; the offline HTML deliberately uses system fallbacks. No font
files or bytes are redistributed. Application/policy links intentionally point
to the existing public website; merely opening the prototype makes no request.

### Iteration evidence, not a first-run-perfect claim

Initial browser runs exposed outdated assumptions in presentation tests: pre-
granted Context, a permanently open prompt palette, and identical home/Demo
content. Those were replaced with the new explicit states while preserving the
source/scope safety assertions. A one-line row's `innerText` normalizes newlines,
so the exact-body assertion now checks `textContent`. The synthetic clipboard
failure stub was corrected to throw on a user copy action, not during evaluation.
A length-limit test is separate from the intentionally unavailable-band fixture.

Actual improvements made during verification include correct heading hierarchy,
non-landmark wrappers for internal illustration sidebars, a synchronous safe-band
measurement on explicit expansion, exclusive NIB composer sizing (the old Demo
textarea handler no longer owns it), and stale-search-result protection. A result
that changes before selection requires fresh inspection; an already inspected
body that changes cannot be silently inserted. Initial and final records are not
represented as the same run.

## C. Final first-visit design review — expert walkthrough only

| Target | Evidence in the candidate | What this establishes / does not establish |
|---|---|---|
| Understand the category in 5–10 seconds | First-screen copy says Chrome extension, your own AI inputs, find/organize/reuse; invitation limits beside the CTA | The necessary information is present without opening a section. No recruited viewer was timed |
| Understand the difference within 30 seconds | Explicit history comparison, source/working distinction and personal Topic example | The distinction is concrete; native chat history is acknowledged as sufficient for occasional lookup |
| Observe a useful outcome | The earlier “keep Mum’s own words” input is inspected and deliberately inserted into the next draft | A real page-local interaction, not an AI-generated success animation or measured productivity gain |
| Recognize demo versus live product | Fictional/no-connection labels; v4 pending label; AI/Pro/cloud unavailable; separate beta route | The page avoids making a prototype look like an installed service |
| Find experience and application | Primary Demo CTA, secondary application, experience-first navigation, closing CTA | Both routes are reachable and their promises match their destinations |

Recommended design is **clearer and more persuasive than the baseline for people
whose work extends across conversations**. Its strongest change is not extra
polish: the visitor can see an earlier personal intention alter a later task.
Thought Library now exposes the continuous words inside a human-owned structure,
not just the names of containers. The cookbook was selected for ordinary-language
specificity, not asserted to be the dominant market use case.

Still unresolved: consumer comprehension and desire have not been tested with
recruited first-time visitors; invitation/install/onboarding and repeated actual
use remain separate product evidence. A website cannot demonstrate mature AI
quality, real external Context, cloud reliability or installed NIB v4 before those
services/runtime paths are ready. No physical iPhone/iPad, OS IME, assistive-device
or screen-reader certification is claimed. For a person who only needs an
occasional history lookup, PAIA may still be unnecessary.
