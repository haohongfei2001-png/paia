# PAIA 官网 V2：最终设计、实施与验收记录

候选归属：PR #240，`feat/website-words-worth-returning-20261010`。本记录不修改产品方案，不授权合并或发布。正式网站仍与此候选分开。

## 一、最终价值主张

**让你已经想清楚的论点、解释和条件，成为下一次任务可以准确使用的材料。**

首屏保留“对 AI 说过的话，下次接着用”，明确软件类型和自己的输入范围；核心演示从人物故事改成直接可操作的工作问题。一个宽泛的文章提纲请求，逐步带回用户此前已经表达的论点，以及“两周个人尝试、不能推成普遍结论”的证据边界。

这不以 ChatGPT 不会搜索、没有项目上下文或不能记忆为前提。原生功能已经足够的人，不需要再安装 PAIA。目标是经常需要核对自己的具体措辞、持续修订和组织观点、保留适用条件的人，而不是全部 AI 用户。

[场景比较与设计取舍](FLAGSHIP_V2_DESIGN_20261010.md) 比较了写作、学习、长期个人决策和协作规则四个方向。选择“把自己的学习观察写成文章”，因为它能同时显现持续思考、原始表达、证据边界和新任务，而不依赖人物关系或抽象产品开发术语。学习疑问和个人计划作为少量其他场景，不另造互不相关的首页故事。

## 二、相对 PR240 V1 的实质改变

过去原话与新请求在桌面同一工作区并置；思想库保留 Topic → Section → Entry，并打开真实结构下的连续阅读，而不是改成卡片流、关系图或新仪表盘。来源按需核对，四条输入完整读到示例末尾。选“复用这句”先检查全文，明确填入后才改变当前草稿。手机端在同一份阅读/草稿之间切换，不复制两份输入状态。

请求下方的两条提示清楚说明：当前草稿是否完整包含两条预设原话。只有精确文字出现才改变提示，删除、截断或自由改写不会被当作语义等价或“成功”。这些是**网站解释层，不是新增产品功能、AI 分析或评分**。它让用户看见论点和限制被带回，不声称模型原本一定不知道，也不声称 AI 一定遵守、生成质量提升或节省特定时间。

首页与完整 Demo 继续分工。Demo 保留来源/工作编辑、会话 Find、主题根页与章节阅读、NIB 频次/手动编辑/排序/固定/搜索/全文与选区复用、独立默认关闭的 Context。主场景数据、预设阅读、提示词、卡片内容、双语、How、数据页、测试和新原型统一更新。

NIB v4 保持 ≤336px、候选单行、搜索/检查/编辑不扩宽、避让完整输入框、用户控制展开、保护已有草稿、不自动发送。免费手动价值不依赖 Pro。v4 仍标注已批准但扩展尚未实施；真实 AI 服务、Pro 推荐、外部 Context 和云同步不伪称已开放。

## 三、全站职责与改动

| 页面 | 本轮处理 |
|---|---|
| 首页 | 改为原话/当前请求并置的价值演示；增加公平原生比较和明确适用边界；保留光学首屏与三空间 |
| 完整 Demo | 同一套新输入贯穿编辑、主题、浮板和权限；预设阅读明确为网站示意，不假装实时生成 |
| How it works | 重写为保存检查 → 原始/工作文字 → 主题组织 → 明确复用 → 范围控制；不再重复首页营销段落 |
| Use cases | 写作的证据界限、学习的未解决问题、长期计划的仍有效条件；明确不是自动生成的新请求 |
| 数据与权限 | 来源/工作修改示例改用当前数据；修复内部容器和标题语义；四类数据决定仍彼此独立 |
| Availability | 去除过时 SHA/PR/阶段术语；保留消费者能理解的本地基础、邀请与未开放服务；工程依据在独立链接 |
| About / Blog / 文章 | 保留有效品牌原点与阅读布局；中文空间名一致；补充原生搜索、项目、记忆已有效的限定 |
| Beta | 完整 form 字节保持不变：收件人、处理地址、字段、同意要求、提交/返回规则均未变 |
| 隐私/条款/返回页 | 法律与数据处理文案不变；隐私说明容器仅修复语义；导航/页脚共用响应式改进 |

未变更 `extension/**`、产品 Canonical、开发计划、`.github/**`、权限、费用、云账号和外部服务。保留旧审计材料供追溯，但当前页面/示例/原型不再使用被否决的案例。

### 性能取舍，不包装成虚假提速

本地24次观察的中位 DOMContentLoaded约37.2ms、load约43.3ms、记录到的LCP中位52ms，仅用于排查本次构建明显退化，绝不宣传为用户实际访问速度。新增价值提示脚本2,860字节，计算gzip1,088字节。英文首页HTML计算gzip由7,375增至8,084字节；新增交互和说明有约709字节代价，不声称全面缩小资源。原光学主样式体积不变；没有新增访客外部框架、追踪或模型请求。具体每个文件原始/计算gzip值见 `performance.json`；CDN是否实际压缩由真实部署决定。

### 本轮实际修复过程

首轮全页无障碍发现了提示说明对比度4.44:1、数据选择章节标题顺序、隐私说明嵌套地标；修复后又发现手机导航遮住“还原请求”。最后将还原动作放到结果提示旁，设置真实锚点避让，再重新执行完整浏览器与156次扫描，得到上述结果。没有删断言、强制点击或跳过失败状态来算通过。初次失败与后续结果属于不同运行，历史不改写。

## 五、设计验证：哪些已可观察，哪些未被证明

5—10秒：首屏已明确是管理本人 AI 输入的 Chrome 扩展；主标题、产品窗口和“演示/申请”入口处于同一视野。没有招募访客计时，不能宣称所有人10秒理解。

30秒：核心问题直接指出宽泛请求缺少已经形成的论点和证据边界；原生 Search/Projects/Memory 正面说明，用户可以判断已有工具是否足够。具体理解率未知。

核心收益：真实页面操作可将准确措辞带回当前请求，删除后提示反转；其可见收益是保留条件、使当前请求明确，不是编造一份更好的 AI 答案。

长期价值：组织和复用的是自己的可维护材料，不把过去所有表达当永久立场。内容增多并不自动更有用；长期安装价值取决于再次找回、修订、复用的实际频率。

转化：交互演示无需邮箱和安装；扩展需获邀，申请不保证资格。不存在假安装/支付/AI连接按钮。实际邀请安装、首次成功、长期回访和留存没有被本轮官网测试替代。

## 六、最终判断与未解决风险

**V2 比 V1 更直接地证明产品用途，而不是要求用户先喜欢一个故事。** 最重要的变化是把原始表达、人的组织、新任务和丢不得的限制条件放进同一可操作场景。保留克制的视觉系统，没有用新增产品功能补网站表现。

它更适合在意措辞/条件、反复写作学习或持续决策的用户，不应宣传为人人必装。“更易理解、更有吸引力”仍是基于实际页面的设计判断，不是测得的安装意愿或留存提升。下一层未解决证据是陌生用户能否不经说明找到操作、是否愿意拿自己的真实工作再次使用，以及真实扩展的安装、NIB、AI和云服务完成情况。

未做真实用户研究、物理设备/OSIME/读屏器认证或表单送达测试；未激活任何真实AI/云服务。离线原型使用系统字体回退，可能与正式网站字体换行略有不同；实际高保真截图使用仓库原字体。交付包不含字体文件。
