# PAIA 官网 V2：让已经形成的判断，继续约束下一次任务

本轮更新 PR #240，不增加竞争性官网 PR。家庭食谱方案已被负责人否决，只保留在历史审计材料中。

## 1. 基线与判断

初查 main：`d414b0baf4c62c0ba8e7c6cb59620b117d2e5a5a`，扩展 0.43.12；PR240 原候选：`e1bdc085dcdf06376e5844947f6f17ea02a96a36`，Draft/未合并。两者之间八个 main 提交只涉及扩展及其 CI/状态，没有官网源码重叠。活跃 PR249 是扩展可靠性工作，不合入官网。STATUS 的“已合入 / 已验证包 / 已安装 / 真实服务激活”仍是不同事实；NIB runtime 未选中，真实模型、会员推荐、Context 外部连接与云传输仍不可宣传为已开放。

保留：蓝白光学材质、非对称首屏、三个产品空间、官网与完整 Demo 分工、NIB 宽度/选区/草稿安全、权限默认关闭、双语路由、表单和回归门槛。

否决后的问题不只是案例主题：V1 的阅读区域和新任务相隔过远，用户先读长篇示例再向下找输入框；复用完成只证明“文字被贴进去了”，没有清楚暴露当前任务缺少什么、旧话补回什么。首页仍要求人先关心一个人物的小项目，而不是先认出自己反复遇到的问题。

## 2. 公平比较原生能力

2026-10-10 核对 OpenAI 官方帮助：

- Search 可搜索聊天标题/消息，以及账户可用的项目、文件等；不要声称只能找标题、不能找旧消息或不能跨聊天搜索。
- Projects 本来就是持续工作的容器：聊天、文件、指令、项目上下文；不要声称 ChatGPT 每次都从零开始。
- Memory 已能使用相关过去内容，并提供查看/纠正等控制；不要把它描述为完全不可见、不可修改。官方同时说明它不保留每条对话的每个细节。
- 普通笔记可以保存原话、链接、修改原则；提示词工具可以复用文本。PAIA 不垄断任何一个结果。

PAIA 的可辩护区别是**对自己表达的输入级管理路径**：已授权输入 → 原始来源与可编辑工作内容分开 → 跨会话的个人主题和连续阅读 → 核对当前完整措辞 → 主动精确复用；将来按独立权限提供合格上下文。不是宣称更聪明的记忆，不是原生功能不存在，也不把尚未提供的跨平台能力拿来竞争。

原生功能已足够满足的人不必另装。优先用户假设：反复围绕相同问题写作、学习或做判断，且在意自己原话的条件、否定、证据界限和修订的人。需要实测该群体的找回成功、纠错成本和复用频率，而不是把所有 ChatGPT 用户算成需求。

## 3. 场景比较（设计判断，不是用户调查分数）

| 方向 | 需求/复用节奏 | 原生替代与 PAIA 增量 | 三空间契合 | 可见前后变化与视觉 | 风险与结论 |
|---|---|---|---|---|---|
| A 长期写作与创作 | 写作是已观察到的重要 ChatGPT 用途；个人观点/文章改写可反复发生，PAIA 留存仍未证实 | Projects/Canvas/笔记已经能支持；增量在保留人的原话、条件和工作修订，而不是保存生成稿 | 原始输入、按论点连续阅读、可选规则/主题开放都自然 | 模糊“写篇文章”变成带具体问题和证据边界的请求，不需要伪造答案 | 可能看起来是写作工具；选择普通理解问题而非文学创作，少量旁证显示普适 |
| B 持续学习与理解 | 持续学习可高频；研究支持实践指导/信息寻求普遍，但不证明人会回看自己的提问 | 原生搜索、学习和项目已强；PAIA 应保留自己已理解到哪一步、什么还没解决，不能把 AI 讲解纳入档案 | 档案/思想库强；Context 可保存当前程度、解释规则 | 旧误解到新解释可清楚，但容易暗示系统会判断掌握程度 | 保留为次级案例；不模拟学习诊断/掌握评分 |
| C 长期个人项目与复杂决策 | 决策重复但不一定每天；某些阶段密集 | Projects 和人工决策日志是直接替代；精确保留预算、否决原因、适用条件有价值 | 三空间自然，复用强 | 新选项须满足已经确认的约束，可直接展示 | 容易退回抽象 PM 术语或低频购物故事；作为次级案例，不引入财务建议 |
| D 自己与 AI 的协作规则 | 短句复用更高频；实际频率需要产品数据 | 自定义指令、Memory、模板工具均可解决大量问题 | Prompt/Context 强，但独立思想库价值偏弱 | 操作明显，长期思想积累不明显 | 作为入口辅助，不把 PAIA 缩成提示词管理器 |

推荐 A 为主、B 提供内容基础、C 为拓展：**把自己的自学观察写成一篇文章**。核心对象不是“一个写作项目”，而是“此前已经形成、此刻不能丢失的论点与边界”。不预设角色、情绪或人物关系；数据全部虚构。

## 4. 核心价值演示：不仅搬运一段文字

当前任务预填：『帮我列一篇自学方法文章的提纲。』

左侧是已经打开的个人主题『学过以后，留下什么』，四条自己的表达、两个人工章节、两个明确标明的虚构来源对话。关键内容包括：

- 真正想讨论的不是读更多书，而是能否用自己的话解释；
- 『看懂』不自动等于『学会』，这是有意保留的区分；
- 只有两周个人尝试，不能说方法对所有人有效；
- 开头提出昨天读懂、今天讲不清的问题，不列工具清单。

右侧就是当前新草稿及同一 NIB；两者在桌面上并置，移动端用同一个阅读/当前输入切换（这是官网演示切换，不是新增产品页签），不复制两套状态。先选论点或边界，在窄浮板核对，明确点“填入”，原草稿保留。第二次选择使用同样路径。演示不自动发送、不编造 ChatGPT 的错误答案或改进答案。

旁边的『这次明确带回了什么』仅按两条预设虚构原话是否完整出现在当前草稿中做文字核对；不会理解、评价或总结用户自由输入。明确标示『本页演示提示，非 AI 分析』。删掉原话会撤销对应提示；自改后不声称仍符合原意。它证明任务信息由宽泛变为具体，不宣称节约多少时间、质量提升比例或 AI 一定遵守。

把“看原话 → 核对 → 新任务中的证据边界”在同一工作场景显现，是相对 V1 的主要变化。首页保留短路径，复杂的编辑/排序/权限都去独立 Demo。主题内容连续读到真实示例末尾，不用内嵌滚动裁掉后半段。

## 5. 页面职责

首页：类别与受众 → 并置原话/当前任务的价值证据 → 三空间工作分工 → 原生功能公平比较 → 真实邀请与边界。
Demo：同一数据的完整来源/工作编辑、主题概览/连续阅读、NIB 搜索/全文/选区/手动管理、独立默认关闭权限。
How：首次启用支持来源、检查一条自己的输入、修改工作版/核对原始来源、组织主题、从新任务复用；精确指出需要真实测试版/还未提供的部分。
Use cases：写作保留观点与证据界限、学习接着未解决的问题、个人计划沿用已经确认的条件。不是不同情绪故事合集。
Beta：现有数据处理、收件人与同意框不变；明确网页演示/测试邀请/后续服务区别。
Availability：不暴露 SHA、阶段编号、内部执行术语；仅三层“无需安装可体验 / 获邀版本的本地基础 / 尚未开放”。工程依据链接保留。
About：品牌原点留在自己的页面，不能抢主叙事。Blog/文章保留有效观点，删除机械产品开发例子，补充原生能力的公平限定。
数据与权限：保存、PAIA 内部 AI 处理、外部 Context 读取、同步分别说明，仍无真实连接。

## 6. 视觉与验收

继续使用当前蓝白、光学边缘、清楚 UI / 阅读字型、细线和有限玻璃。缩减重复大标题和无内容高度；主演示一个连续工作区，而不是一排 SaaS 卡片。产品正文不靠图片呈现，触屏输入至少16px，说明不代替操作反馈。

验收：原有全站回归继续；新增拒绝旧场景词、主/次数据一致、可逆精确措辞提示、保留草稿/来源、不扩大权限、无模型/远程请求、单状态移动切换和 keyboard/reduced-motion。检查320/390/768/1440、200%文字、所有四个核心功能。记录页面/脚本体积、实验性本地加载/布局稳定性；不把本地计时当公网性能分数。

消费者5–10秒/30秒理解属于专家走查目标；没有招募用户、没有计时人类阅读、没有安装转化/留存结论。最终推荐设计是否更好需与工程“通过”分开判断。
