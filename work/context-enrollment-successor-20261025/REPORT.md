## Repairs

1. Captured `Reflect.apply` invokes the captured SDK functions, Promise `then`, original queue entry, and original repository readonly transaction. An own `.call` property cannot replace these invocations. Both SDK method identity and object identity are rechecked around enrollment awaits.
2. An external Resume refuses any pre-existing repository work window before enrollment writes. The original readonly control scope also refuses any active window at entry, including a caller holding the same opaque ticket: equality proves resource identity, not invocation identity. The scope opens its own window inside the original queue callback. Explicit tickets retain original cumulative bytes, references, elapsed deadline and failure state. No second ticket is minted for overflow, queue wait, late SDK return or a failed borrowed ticket.
3. The original local lifecycle row gains optional strict `enrollmentSettlement` metadata bound to lifecycle binding, generation, start revision and a new attempt id. Enrollment writes/readbacks `pending`, reobserves Context using the same finite work ticket, writes/readbacks `confirmed`, then requires another terminal Context observation before setting the in-process settled flag. Previously installed journal identity alone never grants settlement.
4. Cold startup does not automatically re-enroll from an old receipt. A durable **pending** marker becomes UNKNOWN, remains blocked and cannot automatically Resume, publish or restore. A durable **confirmed** marker confirms only the SDK row write; it does not prove the old cross-storage attempt completed. Cold confirmed and legacy rows require an explicit new Resume, with a new attempt id and complete new qualification. A third-observation failure can leave confirmed plus in-memory UNKNOWN; cold restart retains needs-requalification, not durable UNKNOWN. No cross-store atomicity claim, rollback or replay of the old write.
5. The backend's `#allowed` rejects unsettled Context for publication and recovery. `applicationSelectionAvailable` remains the existing prepare-only gate; this work does not claim a new global application-selection authorization.
6. Readonly `stopAvailable` is true only for uncertain pending enrollment on the same current binding/generation, non-suspended owner. Pending UNKNOWN permits explicit Pause/Disconnect using captured SDK dispatch and exact readback; the pending marker and UNKNOWN remain. Other UNKNOWN states do not gain this exception. This is a restrictive backend hint, not enrollment success. Settings UI wiring is root-owned and excluded from this commit.
7. No-Context lifecycle flows retain their original single-write/readback behavior. Existing old-reader checks now explicitly account for the optional marker; malformed binding/generation markers fail startup rather than being adopted.

The cold behavior is a user-visible conservative change: a previously active Context session requires a new explicit Resume after restart. The owning tests now first assert cold refusal/preservation, then exercise the original manual-edit/checkpoint paths after explicit Resume. No fake startup consent, migration, permission grant or automatic retry.
