## Decision

There is useful local implementation beyond another known-subset wrapper: add **original current top-document inventory plus born-closed / retired-closed native admission**, and compose that actual inventory with original per-document holds and final inventory requalification. Existing original origin-scoped tabs and scripting capabilities can supply current top-document identity without adding a host permission. The current manifest contains storage, scripting and only `https://chatgpt.com/*`; optional nativeMessaging is separate. It has no tabs or webNavigation grant. Existing `capture-recovery.js` already queries only this origin and uses original `scripting.executeScript` top-frame results' `documentId`, then pins subsequent injection to it. Thus discovering current permitted top documents is an implementable local problem, not inherently blocked on a new broad permission.

However, current top-document enumeration is not an inventory of every old execution context. Old unsupported constructors, untracked pre-protocol native continuations and hidden/restorable old documents cannot be turned into complete coverage by polling tabs, injecting the latest adapter, or accepting a fresh receiver. The final global consumer must demand the full original lifetime proof; a lower-level current-document inventory alone remains unusable to open ACTIVATE. Do not implement a method that just renames known-subset evidence “complete.”

## Actual present gaps

1. **Demand-driven map rather than document inventory.** `prompt-insertion-receipts.js:69-72` accepts only authenticated active top-frame sender registration and `resolveReceiver` verifies an exact document, but map membership starts from receiver probes. `service-worker.js:128-129` removes entries after queued ready continuations on tab remove/update. These callbacks are not a synchronous inventory fence; map emptiness says nothing about all documents. The new driver freezes this map accurately, but cannot discover an unregistered member.
2. **Native birth gap.** `chatgpt-composer.js:196-209` installs the original shared per-document state/listener when the content lane constructs the adapter. `registered` is demand-driven. `:298-309` still accepts legacy insertion while `protocolActive` is false. A new document that appears after the frozen map can therefore not be considered intrinsically blocked merely because current worker receipt admissions are held. Only a birth-time gate checked by the actual original native entrypoint fixes this, not a separate readiness reporter.
3. **Retirement gap.** `:197` marks `documentRetired` on pagehide and invalidates a selection hold; `selectionIdentity` uses it. Actual `insert` and the final `#once` guard do not currently reject this bit. A suspended/restored original document must remain ineligible to call native until its original owner deliberately requalifies; a pagehide observation is not proof of destruction. Existing Assist/Next pagehide hooks invalidate their lane UI state but do not prove the shared Manual physical boundary cannot resume.
4. **First-constructor provenance.** `:52-55` deliberately reuses the first immutable constructor in an isolated world. Reinjecting a new bundle neither replaces that constructor nor observes its old closures. `capture-recovery` repairs bundles and capture health, not Prompt physical work; it cannot be repurposed to certify missing insertion coverage. No monkey-patching or wrapping the old constructor can recover already accepted old continuations.
5. **Snapshot race.** Tabs queried before/after a document hold can detect observed changes, but a browser event delayed behind an async continuation does not become a cross-process lock. An ordinary synchronous worker-side version must be invalidated at original onCreated/onUpdated/onRemoved/onReplaced callbacks before awaiting ready. Future documents must be unable to enter native while the global holder exists, independently of whether the worker has already received their event. This requires the original birth/admission protocol, not only the version counter.
6. **No active global consumer yet.** `application-transport-coordination.js:14-21` still captures receipt-only hold methods; it does not consume the new known-document driver. `application-selection-commands.js:13,22` keeps canActivate/canContinue/canRestart false and refuses these requests. Integration must replace the mutually exclusive receipt-only member with the actual complete-document consumer; acquiring both receipt holds will simply refuse. Root must also maintain editor, capture, Context, local tool, activity and prepare-cut requalification ordering, rather than treating host work as the last universal check.

## Minimal coherent local implementation (not yet performed)

### A. Modify the original physical adapter, not a new generic issuer

Use the original per-document private state and captured runtime/Promise primitives. Before any first await, native admission is closed until the document has completed the original authenticated receiver enrollment for the exact current owner/domain. During the enrollment wait, no legacy insertion may enter native. The same gate and admission serial must be tested immediately before original `execCommand`, with no await after the final guard. A malformed/copied request, delayed legacy message or separately loaded Manual/Assist/Next bundle cannot bypass it.

Pagehide must retire native admission and invalidate all previously accepted-but-not-native operations. A restored document may not auto-revive the old serial. Define one original explicit requalification path for a clean still-live supported document only after the global hold has been released and the worker's exact original owner is available; never rerun a prior insertion. If current protocol chooses permanent retirement for that document lifetime, report the user-visible reload requirement rather than silently breaking resumed tabs. Existing active native verification is drained honestly; it is not canceled or changed to not-inserted.

This is a compatibility-sensitive change to the old legacy acceptance path. Implement positive current-manual/assist/next behavior and explicit old-protocol refusal together, not by leaving all fresh inserts broken. No body/draft/UI content is needed for enrollment or inventory.

### B. Original inventory held over the real browser-facing owner

Use the captured original `tabs.query({url: ['https://chatgpt.com/*']})`, exact `tabs.get`, and existing `scripting.executeScript` capability from the real worker. The injected probe only reads original isolated adapter protocol metadata / private owner response; it must not read page text, drafts, selections, account identity, titles or arbitrary origins. Its original returned top-frame documentId is then cross-bound to authenticated receiver registration and the actual HOLD message's nonce/domain/epoch. No caller receiver list or arbitrary supplied callback is accepted.

Install original invalidation listeners synchronously at worker birth; capture function and event-source identity. Count/charge the actual receiver/URL/document metadata under the same 4096 / 2 MiB / 30s work. Refuse missing/changed documentId, unsupported constructor, withheld access, incognito, discarded/frozen/ambiguous lifecycle or unexpected result shape. Do not filter such eligible members out and certify the remainder. A zero-member query is only an empty current inventory; it is not lifetime proof.

Acquisition must discover and authenticate every current member while registration is possible, then synchronously close worker admissions and freeze the exact original membership/version. Any discovery/registration race aborts the attempt; no polling or hidden retry. Acquire original document holds, drain original tasks/serial and compare actual ledger/generation/restore/gate. Requery and exact-document probe every member at the final fence, compare both identities and inventory generation, and verify all prior holders. Every late raw HOLD gets only exact precharged cleanup. Newly born supported documents remain closed by A while discovery/global admission is held; therefore they do not gain native authority through an event-delivery race.

The receipt owner's current known-document driver can be reused internally after this inventory has actually enrolled exactly the current set. Its token alone must not be exported as full coverage. The original complete owner must retain that set, original event version and lifetime qualification all the way to the real consumer, not return a boolean detached from them.

### C. Complete lifetime qualification and actual global integration

A complete positive profile needs evidence that **every potentially resumable original PAIA native writer** is either in the held original inventory or permanently barred at its actual final native boundary. A supported fresh constructor that starts closed and retires closed can provide this prospectively. A current supported document with the original uninterrupted private inventory can also prove accepted operation completion without losing that inventory. Existing historical/unsupported contexts cannot acquire that property retroactively.

The minimal first positive integrated profile should be explicitly constrained to an original, continuously owned supported document lifetime universe; unsupported or unexplained old contexts reject. The browser installation/session provenance needed to establish that universe must be concrete, not inferred from a boolean, an empty map, a new worker, storage.session absence, version string or `onInstalled` reason alone. Current source has no such proven initial-universe witness. If real browser lifecycle guarantees are used to establish it, verify those exact guarantees for discarded, prerendered, cached/restored and extension-replaced contexts before enabling the profile. This audit used no network and makes no undocumented browser guarantee.

Once that proof exists, root can consume the original complete host capability together with all existing owner holds; rerun original prepare-cut requalification under those holds, then call the original activation owner with final no-await identity checks and exact late cleanup. No public DTO, global flag deletion, arbitrary completion callback or per-member budget renewal. Without this lifetime qualification, implement A/B and their refusal controls but do not advertise a usable global ACTIVATE consumer.

## Current physical quiet versus historical outcome UNKNOWN

These are different propositions. If the *same original* adapter has held all native admissions and its complete accepted-operation set has actually drained through original native-call return, verification continuation and listener cleanup, it can prove no further PAIA native call remains from those accepted operations. This need not prove whether an already returned native call inserted exactly the intended text. `#once:380-392` already returns an `unknown` outcome on ambiguous readback and always removes its listener / clears busy in finally. Preserve that outcome, its claim, accounting and replay refusal.

Current code deliberately demands the stronger terminal-outcome condition: adapter `selectionTerminal` rejects any legacy attempt or receipt without a non-unknown ACK, and receipt hold rejects every durable pending claim. Do not simply relax either guard. To admit a physical-only terminal UNKNOWN in a future complete profile, add an original private physical-terminal witness recorded for every accepted path, and prove it binds all exact retained pending claims and all original documents, while the unchanged durable UNKNOWN row remains byte-for-byte retained. A settled arbitrary Promise, a public `busy=false`, absence of an ACK, or a fresh document cannot supply that witness. This is concrete local engineering once A/B and lifetime coverage exist, but not part of an inventory shortcut.

`group-checkpoint-scope.js:142-147` validates the local insertion runtime row and retains it in the raw native cut; it does not make it portable success. The global selection owner compares raw source/target rows separately. Any future selection preserving unresolved receipt/accounting evidence must prove those physical rows survive unchanged and that no new owner treats old pending operations as permission to replay. Historical outcomes can remain unknown forever while genuinely complete current physical closure is separately known; there is no need or authority to clear `legacyCoverageUnknown` merely for the latter.
