# Existing-generation reverse inheritance — next local scope

2026-10-25. Read-only review at root `5f0bab08e8812252c5abf0b49d3a7023d6ae0bf5`. No code changes or tests/native/cloud/real-account actions. This is a local engineering recommendation, not activation authorization.

## Decision

A narrow reverse **qualification** can be implemented locally without new content permission, account access, execution quota or a substitute Sync protocol: the same live original forward-selection owner can prove that its exact source and target full raw cuts remain unchanged except for the precise already-completed original selection/control transitions. The private before-cuts still exist in that owner. A cold owner does not have those cuts and must not claim them from the durable graph digest.

This can proceed independently of global activation. It must remain a read-only, opaque original-owner review consumed later by the existing selection owner; `rollback()` must still refuse actual pointer dispatch until the original durable reverse transition and real global hold consumer exist. Avoid adding an exported generic issuer, caller-supplied snapshots or a detached “readiness” DTO. If root requires an immediately usable reverse switch rather than its bounded qualification, that is a larger original-protocol state-machine package, not a one-method rollback fix.

## Exact smallest useful shape

A proposed `prepareReverse`-style method belongs inside **the same `OriginalApplicationGenerationSelection` owner**, not a new caller-authored coordinator. It accepts no database, cut, operation ID or readiness callback. Eligibility is only:

1. The same undiscarded private forward prepared record exists, its forward attempt reached an exact completed `selected` receipt, original source/target/repository/database/factory/core identities remain the captured identities, and the owner is neither closed, busy nor restricted.
2. The default/source marker is that exact selected operation, the target temporary marker and control reservation are absent, registry root is exactly its recorded root, and local control is exactly the derived original after-row, with the original nonce/stamp. Reject prepared/dispatched/finishing/UNKNOWN, another operation, or a registry successor.
3. Compare **all** tables and rows, using existing exact physical-tree equality including keys and values, against privately retained pre-forward source/target cuts transformed only by the original observed transition. Source gains its exact selected marker. Target has the exact original control revision change and exactly the three original selection write finalizations in its active gate; both temporary marker and reservation are gone. These are finite owner-defined replacements with exact counts/values, not a metadata prefix whitelist, minimum gate revision, graph-only comparison or normalization of arbitrary new rows.
4. Use original repository reads/final fences and ordinary bounds; capture/recheck live identities, lifetime, source/target row vectors, registry and current local SDK binding after awaits. Return only an opaque private reverse-review token plus a non-authoritative descriptive state. A later consumption must revalidate this same full cut, not silently refresh it. Any real write or close invalidates it. A fresh reverse review may be explicitly attempted only from an otherwise eligible unchanged original owner.

For this exact no-new-facts shape, complete original forward qualification plus exact full-cut preservation proves the old library contains the selected library's represented facts; no new source relationship or body permission is needed. It also conservatively rejects noncanonical/local metadata drift rather than guessing whether that drift is harmless. Existing scope/reference proofs are retained as provenance; old proof `require` calls cannot simply be treated as current after the legitimate local control transition. The new fixed review must explicitly bind that transition rather than weakening shared inheritance guards.

One subtle integration constraint: the current original review restriction deliberately refuses `p.attempted`, so the forward lifecycle reservation is **not** already a reverse hold. Do not release/relabel it or reuse its before-row as reverse activation permission. The read-only reverse review should not add a permissive hold workaround.

## What is missing for actual reversal

The version-1 selection marker stores graph/canonical digests and control before/after digests, registry/gate and reservation facts, **not durable full raw source/target before-cuts**. It also only has forward source/target roles and prepared/dispatched/selected phases. `openOriginalSelectedExistingApplication` consumes the source selected marker; simply writing local storage back while that marker remains would cause cold startup to select the target again or fail. Deleting the source marker first would reopen the old writer before an uncertain SDK publication. Deleting it after an unacknowledged SDK set would create an unresolved split without the original durable reverse receipt. Neither is safe.

An actual reverse consumer therefore needs an explicit extension of the **original** fixed selection/control protocol: exact held state on both real repositories, one original stamped SDK write, durable unknown/reconciliation semantics, cold selection rules, exact release order and crash handling. It must preserve current restrictive device controls and cannot replay an older consent/configuration. This is implementable local engineering, not a request for new account/body permissions. It requires careful original-owner changes and synthetic failure controls; it is not supplied by a new metadata flag or the qualification token alone.

The application worker also still refuses ACTIVATE/CONTINUE/RESTART because complete editor/host/writer protection is not assembled. Warm subset owners do not cover cold UNKNOWN or every document. Actual reverse dispatch must consume genuine complete holds across the current target and any old live source owner, and maintain their original deadline through last SDK dispatch. This global proof is a real execution dependency, not a reason to stop read-only reverse qualification work.

## Changed target and cold cases

A real legal edit, captured Source, negative fact, Prompt correction, Context update or human structural change after selection invalidates the narrow unchanged-cut review. Safe reversal then means **inherit all new target facts into the prior library first**, not return to its stale contents. Complete history/negative/reference closure and conflict semantics must be reconstructed by original family owners. `canonical-generation-publication.js:150–152` explicitly rejects `sourceBase.root.active !== null`: an active source revision alone does not prove existing canonical/negative inheritance. The existing retained default is not an ordinary empty staged generation, and its selected marker still fences ordinary writes.

Source Working merge/continuation supports finite lawful shapes, but that is not a complete selected-target-to-prior-library inheritance owner. A legal Source-only descendant might later furnish a narrow merge proof; it still needs the original selected-library write/receipt consumer and full non-Source cut preservation. Current second Working continuation evidence is not evidence for Human/Context/negative or arbitrary mixed reverse inheritance. Do not infer these from a matching graph digest or copy raw target rows.

A cold exact reverse may be engineered later using fresh original complete reference qualifications plus durable transition provenance, but the present marker cannot recover a lost private full raw vector. It is not safe to claim “no changes since selection” after reopening from `graphDigest`, `canonicalDigest`, target gate lower bounds or the old seal alone. Do not invent the missing physical snapshot. The minimal first shape should explicitly refuse cold/new-owner review and all changed targets.
