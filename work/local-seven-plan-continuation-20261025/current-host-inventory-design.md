# Current top-document inventory continuation

Read-only design; no runtime change or test execution. Source checkout HEAD: e2536b6795dfffbd9b70b00efaa885577a91f24e. The user-approved receipt-only core and UI resolve the prior new-document legacy admission gap. This does not retroactively retire old constructors, settle historical claims, or establish the complete BFCache/prerender/document lifetime universe.

## Existing owners and actual missing capability

`capture-recovery.js` already captures original `tabs.query/get` and `scripting.executeScript`, queries only `{url:['https://chatgpt.com/*']}`, and obtains the top frame's browser-provided `documentId` before exact-document subsequent injection. Its `repairAll` is not an inventory API: it filters ineligible members out, repairs/injects scripts, waits for startup, and returns no immutable identity set. Calling repairAll cannot prove that all current members were held. Do not modify or call its replacement/injection behavior for this purpose.

`PromptInsertionReceipts` already owns the authenticated receiver map, original protocol/ledger, one-work known-document driver, transport tracking and exact late cleanup. No equivalent complete current-top inventory exists in it. The narrow useful continuation is to extend this original owner with an internally acquired current-top inventory, then reuse its private known acquisition/fence/release machinery. Do not create a detached registry/readiness service, accept caller-provided tabs/receiver arrays, or call the public known-subset method with a fresh allowance.

The existing manifest grants scripting and the ChatGPT origin. Reuse exactly those existing origin-scoped SDK capabilities and original top-document metadata probe shape. No tabs/webNavigation permission addition, broad tab query, DOM/body/draft/title reading, adapter injection, reload or native insertion is needed. Capability absence is a refusal, not a broad-query fallback.

## Required sequence, one original allowance

A. Before the first await, reject concurrent acquisition, capture API/object/method identities, establish one private inventory record and close original receipt insertion admission. Allocate one original 4096-reference / 2 MiB / 30-second work ticket, never a per-tab ticket. Use captured Promise/then/resolve/apply and preserve genuine pending transport tracking. The whole acquisition itself must not enter the task set that it later drains.

B. Query only the original ChatGPT URL filter. Require a nonempty, duplicate-free complete result within the existing 64-receiver bound. Do not silently filter incognito/discarded/frozen/ineligible/missing-identity members: any such returned member refuses this profile. Record only exact tabId/windowId/url and the relevant restricted booleans; charge their actual UTF-8 encoding and references. Do not retain/log titles or unrelated tab fields.

C. For each member, get the original tab, then execute a fixed body-free top-frame metadata probe in the ISOLATED world. Validate exactly one result, frameId 0, nonempty bounded documentId, permitted origin/top-document result, and no per-result error. Pin a second probe to that browser-provided documentId; get the tab again and require the exact identity. Do not treat script execution success as protocol qualification. The probe returns metadata only and does not instantiate or replace the adapter.

D. While insertion admission stays closed, allow only this original private enrollment operation's expected exact tab/window/document sender to answer the original RECEIVER_PROBE registration. The existing wire `recoveryToken` can carry a private random per-enrollment token; no new caller DTO or issuer is required. The token is bound before send to the expected browser-observed document, same owner/domain/deadline/work, and consumed only in that registration stage. The final post-await registration admission must repeat these checks before map mutation. Other new registrations, producer requests, or unrelated continuations refuse and invalidate acquisition. Settling an already accepted original operation continues under the existing settlement rules; it is never canceled or classified from rejection alone.

This is the one necessary internal admission change: calling current public resolveReceiver while held currently fails, and merely skipping #admit would allow unrelated registration. Do not bypass it with direct map assignment. Preserve the real register sender checks and original adapter protocol. Registration/reconciliation and its event work must share this inventory ticket; do not create a new recovery-event #work. If the adapter has genuine retained pending/unknown evidence, the existing hold/ledger qualification still refuses. Genuine reconciliation may settle only its original ACK under the existing protocol; a fresh inventory cannot synthesize it.

E. After exact `receipt-only-v1` top/exact-document probes and original authenticated enrollment, compare the entire private receiver map against the inventory: each receiver and its URL must match exactly, and every existing map member must be accounted for. Reject stale or extra map members; do not delete them to make the comparison pass. Freeze map version and all entries, then reuse the existing private known HOLD -> actual task drain -> ledger/gate/restore/generation snapshot -> FENCE -> snapshot equality, using the same original work/deadline. No public known-subset call/new ticket and no caller callback supplying a proof.

F. Re-enumerate the entire origin-scoped tab set and repeat top-document identity probes. Require exact equality with the original inventory, unchanged private topology-event sequence, unchanged receiver version, all original holds current, and identical original ledger/control snapshot. No retry on a changed member. The returned opaque token certifies only this current-top profile; scope cannot be renamed to complete host or global activation.

G. The original current/fence paths retain the same deadline and same inventory/event identity. Fence re-enumerates and verifies again, rather than trusting a past snapshot. Release/failure delegates to the existing exact attempted-HOLD cleanup, including negative replies and real late settlement. It must not reopen admission after UNKNOWN cleanup or unobservable SDK transport, nor dispatch RELEASE before actual HOLD settlement. Enumeration failure before any HOLD has no document cleanup to invent, but original accepted tasks must remain tracked. No timeout-based cancellation, retry, renewed allowance, or historical flag clearing.

## Synchronous topology invalidation

Register original listeners for onCreated/onRemoved/onReplaced/onUpdated synchronously in this original owner, before any inventory await. Any possibly relevant creation/replacement/removal/navigation/frozen/discarded transition invalidates the private active acquisition immediately; it must not wait for service-worker `ready`. The existing service-worker callbacks are queued behind ready and are insufficient as the synchronous fence. Conservatively invalidating on all topology events is safe without collecting other-origin content. Missing original event capability refuses this inventory profile while leaving ordinary receipt APIs usable. Freeze event API/add/remove identities and remove only this owner's exact listeners on dispose; late events cannot revive a token.

These events plus double enumeration improve current-top consistency, but they are not a browser atomic inventory lock and do not enumerate every restorable old context. A new receipt-only page cannot accept a fresh unsigned native insertion while worker admission is closed, but a pre-protocol/cached old page has no retrospectively installed gate. Preserve that distinction.

## Minimum meaningful synthetic controls

- Real receipt owner + real adapter VM: two initially unregistered supported top documents become authenticated, held and fully enumerated; original release succeeds, ledger UNKNOWN flag unchanged, native calls zero.
- An extra known receiver absent from query refuses; a query member absent from receiver enrollment refuses; duplicate/missing document/frame IDs, empty list, frozen/discarded/incognito/member outside origin, old profile or old Symbol constructor refuse without dropping the member.
- Navigation/new document/same-tab replacement/create/remove while query, registration's final await, HOLD or final enumeration is pending invalidates; current returns false immediately before service-worker ready. Same documentId with changed nonce/URL/window refuses.
- The only held registration exception is the exact original pending enrollment token and original sender. Wrong token/document/window, external resolve, unrelated register and late register after failure cannot mutate the frozen map or issue an action. Genuine original settlement is not converted to cancellation.
- Query, get, scripting and receiver transport operands/results are cumulatively charged, including long UTF-8 URLs. Large/many members reject within the same allowance; no per-member budget reset. Overdeadline real late HOLD gets only original exact cleanup after observable settlement; unobservable original transport stays UNKNOWN/admission closed.
- Existing durable pending claim or adapter UNKNOWN refuses with byte-identical retained evidence and no new SDK/native operation. New token never satisfies production/global selection gate; historical legacyCoverageUnknown remains true.

Use only one meaningful owning synthetic combination after independent source review. No native/browser/CI is authorized by this design. Current paired VM evidence is real code at both endpoints with synthetic SDK/document objects, not real browser acceptance.

## Genuine remaining boundary

The resulting capability closes the missing *current top-member discovery* step and is useful input to a future original host consumer. It cannot alone close old hidden/preprotocol lifetime coverage, Context native-host closure, historical claim outcomes or global cut requalification. Those retain their existing denials. No new external permission is needed for this local slice; no current source proves the entire old lifetime universe. This limitation does not prevent implementing the meaningful inventory stage, but it forbids presenting its token as a complete global selection authority.
