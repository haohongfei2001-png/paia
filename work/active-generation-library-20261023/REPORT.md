# Controlled published-library writes

This local implementation adds an explicit original `CanonicalGenerationPublication.bindOriginalActiveStore(handle, store)` route. It binds only an actual original LibraryDocumentsStore to the same attached repository after the durable registry commit/receipt, exact active gate, original graph qualification and mandatory shadow marker agree. It does not select an application database, modify chrome.local, enable cloud Sync or migrate an older active library. It returns status, never the private per-transaction token.

Every subsequent ordinary original Repository write on that instance rereads the registry using the fixed original readonly method. Pending/not-active/missing receipt rejects before the callback. Target native strict TX admits only the exact preflight gate; the original finalizer increments writeRevision in the same TX. Ordinary callbacks cannot mutate/clear generation system metadata. Every initial generation-prefix key and the exact native range count are fenced at completion, including raw writes bypassing ordinary methods. The original 4096-reference/2MiB/30s transaction limits, semantic/navigation/backup finalizers, rollback and native completion remain in force. Stage/target-ready, unknown/cold unbound repository instances and forged handles stay denied. A cold original store can rebind using actual durable publication and continue its original editing API without resetting consent.

Cross-database precision: a reservation can start after the registry preflight and before the target write. The test uses that actual split: target writeRevision advances, and original publication rejects the stale replacement as reservation-invalidated while retaining the committed source write. This is not a globally atomic registry/target transaction or a guarantee of no write during a raced pending interval.

The active binding is an explicit trusted local application repository capability. Ordinary canonical callbacks retain the existing Repository API; this is not a new arbitrary shadow writer or a replacement for domain/Source/AI permission guards. Default service worker factory, local-control migration, prior-active negative inheritance, complete journal wiring and ordinary full-library backup replacement remain separate implementation work. Every clearing operation remains denied by protected mode; no general clear is enabled to make tests green. No claim of resistance to arbitrary same-origin native IndexedDB code outside original Repository is made.
