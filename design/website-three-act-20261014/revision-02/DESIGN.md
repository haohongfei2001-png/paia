# PAIA：从固定舞台到连续页面 · 修订 02

状态：独立设计候选。没有替换正式官网，没有生产发布授权。本次是根据负责人对 #287 的否定意见重新取舍，不宣称审美目标已经完成。

## 先纠正上一版的问题

上一版把中间内容放进 1200 × 740 的设计画布，随视口统一缩放；各对象在多个定点间移动、缩成小块再归位。每段转场前 27% 的滚动没有推进画面，之后重新进入一次缓动。在滚动帧中同时写入宽、高和 detail，后者继续改变字号、内距与文字换行。

这些结构确实会制造“等一下，再动一下”的节奏，以及多次布局重算的成本。它也把完整的设计等同于“同一组小道具的复杂编排”：观看者一直站在舞台外面，而不是顺着页面进入产品。性能和审美必须分别改，不能只把动画变快。

## 修订方向

仍然保留原首屏、原结尾与最后的产品总览，但不再以“三幕”为理由锁住一个全局演出容器。中段采用页面尺度的连续构图，宽度随真实视口展开，无整体 scale，无固定虚拟画布。标题、阅读内容与产品展示是页面本身的组成部分，不是被放进去的模型。

1. 档案以宽阔的时间与原话排版展开，没有套着完整应用窗口的三张小截图。标题与来源共用稳定的排版基线。
2. 三张主题卡片以可读尺寸进入正常页面流，再进入同一个宽幅阅读面。AI 整理只在这个阅读面的内部更新，外框不换位置，光线掠过后退出。该面板按内容收敛高度，不用巨大空白冒充气场。
3. ChatGPT 场景占据实际阅读空间。球、建议胶囊和窄板仍在同一锚点，文字不跟随控件缩放。胶囊背景使用合成变换；窄板宽度始终是 336 CSS px（窄屏322），没有自动发送或用户输入任务。
4. Context 是安静的四个目录，仅有分类名称及用途说明，没有任何私密正文。它不需要再上演一次大幅变形。
5. 总览以可以直接阅读的产品关系和内容要点收束：档案、思想库、Context 同一横向秩序，提示词在下方接续。它不是四个完整界面的缩略图，也不是虚构的产品工作台。

### 明确放弃的约束

放弃“所有内容必须由同一组 DOM 道具缩小归位”。对象身份一致本身不是设计质量。总览以同一组真实示例和产品类别形成一致性，而不是靠缩小字形或复杂飞行证明它们是同一批 DOM。

这版也不是一段锁屏影片。除两个约 280px / 260px 的局部变化区间外，页面正常上下流动；用户可以快滚、反向回看或停下来读。不要求点选状态，不拦截滚轮，不模拟额外惯性，不设置等待播放时间。

## 性能边界

新的滚动处理只读取 scrollY 并更新 transform/opacity；元素尺寸、字号和内距仅由静态 CSS 决定。几何缓存只在窗口或字体条件变化时刷新，没有滚动帧内的布局读写交错。减少动态、增大文字、窄屏下直接呈现稳定内容。

`verification.json` 保存实际 Chromium 诊断。新旧页面用相同视口、180 个真实 rAF 区间采样，比较 LayoutCount、LayoutDuration 与其他工作量。两版内容路径不同，这只是一项渲染成本诊断，不能当成所有设备的帧率保证，也不能证明已完全复现负责人的主观卡顿。两版采样的 rAF 间隔相近，不据此编造“帧率提升多少”。

相关原则：Google web.dev 的高性能动画指南建议避免逐帧布局/绘制属性，优先 transform 和 opacity，并通过性能工具核查实际发生的工作。
