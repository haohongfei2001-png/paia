# Future implementer: execute the design, not a reinterpretation

本轮只交付设计；不要因为看到这份文档就自动开始实现。

当 owner 明确授权官网实现后：先核验 remote main、当前唯一 website writer、Consumer Product canonical 状态。已有同边界 writer 就接续它。不要同时重建扩展内部 UI。

先打开 `previews/home-en-1440.png`，再看 SVG 和相同文件名的 geometry JSON。设计基线是实际图稿，不是这份文档里的一串风格词。先还原桌面首屏的构图、层级、字型和摄影关系，再逐段推进；不要先铺通用组件库后把画面塞进去。

允许 grid、flex、绝对定位、可复用组件等任何正常实现方式；不允许实现方便成为改掉构图的理由。将 collage 作为独立的局部坐标场景；不要把它拆成一排整齐的卡片。正文保持真实 HTML 和正常文档流，不要用整页图片伪装实现。

实际还原优先级：整体构图 → 主次与空间层次 → 字体和换行 → 元素比例 → 照片与裁切 → 段落节奏 → 连线与微细节。大问题没对齐时，不要用增加动画或阴影掩盖。

完整站点页面、文章、表单、错误状态和中英文均已给出。不要在首页精修后，把二级页重新降级成默认模板。移动端已经有独立画稿，不能以删除照片、连线或来源卡片来凑响应式。

素材采用 manifest 中的固定本地文件。字体按 font-lock 验证，不得默默用系统字体替代。字体二进制不随设计包分发；从对应官方来源取得匹配版本后自行建立 production 字体资产。无法得到匹配版本时，应把换字体作为显式视觉变更重新证明，而不是宣称已经像素还原。

每个主要区域用真实 HTTP 页面截图比对。不允许只做代码 review；不允许把自动测试数量当作视觉证据；不允许用“遵循设计理念”替代原图对齐。最终同时交付功能证据和视觉证据，两者分开。

产品事实冲突时，改文案和来源标签，保留照片、纸面关系和视觉重量。不要复制原始概念图中的虚构证言、不存在的影片、未发布的平台支持或自动人格结论。新增加的手记文章仍须做正常发布审阅，既不需要造假背书，也不需要为了避免写文章而删除整个 Journal。

工程收口之后，报告精确 SHA、实际改动页面、关键截图、残留差异和未验证外部边界。新页面尚未经 owner 视觉审阅这一事实不能被 CI 改成“已批准”。
