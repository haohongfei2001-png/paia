# PAIA website — Context in motion v5

The public website is a next-generation AI input/context product presentation,
not a reading app, lifestyle page or image-only mockup. The owner authorized v5
implementation only if isolated from product development. PR89 owns this website
batch; PR88 retains extension retrieval development. See
[website/README.md](website/README.md) and
[the v5 receipt](website/receipts/WEBSITE_V5.md) for current verification status.

## Design authority

Text-first opening → individual input arrivals → visible relationships → a
layered context object. The next section is a real selection-and-copy workspace.
Motion must explain actual source/context state, not pretend to run AI. Sources
not yet supported remain marked planned. Keep provider marks exact, line art
custom, typography deliberate, spatial depth and normal viewport proportions.

The v4 implementation and rejected90-artboard editorial package are historical,
not reasons to keep decorative photography, small slogans or redundant feature
rows. The current refinement intentionally removes those elements. The three
core icons mean recover, connect and reuse; no generic orbit substituted for a
functional symbol. The dark interactive stage contrasts with the open light
hero without turning the site into a generic neon AI template.

Normal scrolling, static meaningful content, keyboard use, explicit selection,
source integrity, clipboard error handling and reduced motion remain mandatory.
No-JS keeps a concrete read-only context preview. Aesthetic review is independent
of test counts; compare actual browser frames at normal viewport sizes, not only
a compressed whole-page thumbnail.

Product capabilities and privacy/release meaning remain governed by current
canonical extension documentation, never by a concept image or this site.
Nothing in this change authorizes a new AI integration or product release.
